Use `Sentry.captureCheckIn()` for any scheduler when you need to control when check-ins are sent, such as when a job's start and completion happen in separate parts of your application. Requires SDK version `7.51.1` or higher.

Send an `in_progress` check-in at the start and an `ok` or `error` check-in at the end. Sentry can then detect jobs that don't start on time or exceed their configured maximum runtime. Reuse the returned `checkInId` for the same execution, including when job runs overlap.

```javascript
// 🟡 Notify Sentry your job is running:
const checkInId = Sentry.captureCheckIn({
  monitorSlug: "<monitor-slug>",
  status: "in_progress",
});

// Execute your scheduled task here...

// 🟢 Notify Sentry your job has completed successfully:
Sentry.captureCheckIn({
  checkInId,
  monitorSlug: "<monitor-slug>",
  status: "ok",
});
```

If your job execution fails, you can notify Sentry about the failure:

```javascript
// 🔴 Notify Sentry your job has failed:
Sentry.captureCheckIn({
  checkInId,
  monitorSlug: "<monitor-slug>",
  status: "error",
});
```

## Heartbeat

Send a single `ok` or `error` check-in when your job finishes to report its result and detect missed runs. Without an `in_progress` check-in, Sentry can't detect a job exceeding its maximum runtime while it runs. Use paired check-ins above if you need timeout detection.

```javascript
// Execute your scheduled task...

// 🟢 Notify Sentry your job completed successfully:
Sentry.captureCheckIn({
  monitorSlug: "<monitor-slug>",
  status: "ok",
});
```

If your job execution fails, you can:

```javascript
// 🔴 Notify Sentry your job has failed:
Sentry.captureCheckIn({
  monitorSlug: "<monitor-slug>",
  status: "error",
});
```
