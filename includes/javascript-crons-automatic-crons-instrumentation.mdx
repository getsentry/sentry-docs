If you're using the [`cron`](https://www.npmjs.com/package/cron), [`node-cron`](https://www.npmjs.com/package/node-cron) or [`node-schedule`](https://www.npmjs.com/package/node-schedule) libraries to run your periodic tasks, you can use our instrumentation functions in the `Sentry.cron` export to monitor your cron jobs. These functions send the job's schedule with each check-in, so Sentry creates the monitor for you.

### Cron

#### Monitor All Named Jobs

Requires SDK version `11.9.0` or higher and `cron` version `4.3.0` or higher.

We recommend adding `cronJobIntegration`, which monitors every job that has a `name`:

```JavaScript
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    Sentry.cronJobIntegration({
      excludeJobs: ["cleanup-temp-files", /^debug-/], // Optional.
    }),
  ],
});
```

```JavaScript
import { CronJob } from "cron";

CronJob.from({
  name: "daily-report",
  cronTime: "0 30 9 * * 1-5",
  timeZone: "Europe/Vienna",
  onTick: sendReport,
  start: true,
});
```

The monitor slug is the job `name`. Jobs without a `name`, and jobs that run once at a date, aren't monitored. `excludeJobs` skips jobs whose name matches a string exactly or a regular expression.

Each check-in sends the schedule and time zone (your server's time zone if `timeZone` isn't set). Schedules that can't be expressed in the Crons schedule format (for example, a job that runs every 10 seconds), and jobs with a `utcOffset`, check in without a monitor config, so create those monitors in Sentry first.

In NestJS, use the Nest integration's `monitorCronJobs` option instead, because `@nestjs/schedule` runs `@Cron()` methods as named `cron` jobs.

#### Monitor Specific Jobs

Requires SDK version `7.92.0` or higher.

Use `Sentry.cron.instrumentCron` to instrument the `CronJob` constructor or `CronJob.from` method in the [`cron`](https://www.npmjs.com/package/cron) library. Pass the name of the cron monitor as a second argument to the function.

```JavaScript
import { CronJob } from "cron";

const CronJobWithCheckIn = Sentry.cron.instrumentCron(CronJob, "my-cron-job");

// use the constructor
const job = new CronJobWithCheckIn("* * * * *", () => {
  console.log("You will see this message every minute");
});

// or from method
const job = CronJobWithCheckIn.from({
  cronTime: "* * * * *",
  onTick: () => {
    console.log("You will see this message every minute");
  },
});
```

`cronJobIntegration` skips jobs created with `instrumentCron`, so using both doesn't send duplicate check-ins.

### Node Cron

#### Monitor All Named Tasks

Requires SDK version `11.9.0` or higher.

We recommend adding `nodeCronIntegration`, which monitors every task that has a `name`, without changing how you import `node-cron`:

```JavaScript
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    Sentry.nodeCronIntegration({
      excludeJobs: ["cleanup-temp-files", /^debug-/], // Optional.
    }),
  ],
});
```

```JavaScript
import cron from "node-cron";

cron.schedule("0 9 * * 1-5", sendReport, {
  name: "daily-report",
  timezone: "Europe/Vienna",
});
```

The monitor slug is the task's `name`. Tasks without a `name` aren't monitored. `excludeJobs` skips tasks whose name matches a string exactly or a regular expression.

Each check-in sends the task's schedule and time zone (your server's time zone if `timezone` isn't set). Schedules that can't be expressed in the Crons schedule format (for example, a task that runs every 10 seconds) aren't monitored.

#### Monitor Specific Tasks

Requires SDK version `7.92.0` or higher.

Use `Sentry.cron.instrumentNodeCron` to instrument the `cron` export from the [`node-cron`](https://www.npmjs.com/package/node-cron) library. This returns an object with the same API as the original `cron` export, but with the `schedule` method instrumented. You can pass the name of the cron monitor and an optional time zone as part of the third options argument to the function.

```JavaScript
import cron from "node-cron";

const cronWithCheckIn = Sentry.cron.instrumentNodeCron(cron);

cronWithCheckIn.schedule(
  "* * * * *",
  () => {
    console.log("running a task every minute");
  },
  { name: "my-cron-job" }
);
```

`nodeCronIntegration` skips tasks created with `instrumentNodeCron`, so using both doesn't send duplicate check-ins.

### Node Schedule

#### Monitor All Named Jobs

Requires SDK version `11.9.0` or higher.

We recommend adding `nodeScheduleIntegration`, which monitors every job created with `scheduleJob` that has a name:

```JavaScript
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    Sentry.nodeScheduleIntegration({
      excludeJobs: ["cleanup-temp-files", /^debug-/], // Optional.
    }),
  ],
});
```

```JavaScript
import schedule from "node-schedule";

schedule.scheduleJob(
  "daily-report",
  { rule: "30 9 * * 1-5", tz: "Europe/Vienna" },
  sendReport
);
```

The monitor slug is the job name. Jobs without a name, and jobs that run once at a `Date`, aren't monitored. `excludeJobs` skips jobs whose name matches a string exactly or a regular expression.

For cron strings, each check-in sends the schedule and time zone (your server's time zone if `tz` isn't set). Recurrence rules, rules with a `start` or `end`, and schedules that can't be expressed in the Crons schedule format (for example, a job that runs every 10 seconds) aren't monitored.

#### Monitor Specific Jobs

Requires SDK version `7.93.0` or higher.

Use `Sentry.cron.instrumentNodeSchedule` to instrument the `schedule` export from the [`node-schedule`](https://www.npmjs.com/package/node-schedule) library. This returns an object with the same API as the original `schedule` export, but with the `scheduleJob` method instrumented. You can pass the name of the cron job as the first argument to the function. Currently this only supports cronstring as the second argument to `scheduleJob`.

```JavaScript
import * as schedule from "node-schedule";

const scheduleWithCheckIn = Sentry.cron.instrumentNodeSchedule(schedule);

scheduleWithCheckIn.scheduleJob(
  "my-cron-job",
  "* * * * *",
  () => {
    console.log("running a task every minute");
  }
);
```

`nodeScheduleIntegration` skips jobs created with `instrumentNodeSchedule`, so using both doesn't send duplicate check-ins.
