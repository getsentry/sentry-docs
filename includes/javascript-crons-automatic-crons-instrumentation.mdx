If you're using the [`cron`](https://www.npmjs.com/package/cron), [`node-cron`](https://www.npmjs.com/package/node-cron) or [`node-schedule`](https://www.npmjs.com/package/node-schedule) libraries to run your periodic tasks, you can use our instrumentation functions in the `Sentry.cron` export to monitor your cron jobs. These functions send the job's schedule with each check-in, so Sentry creates the monitor for you.

<PlatformSection notSupported={["javascript.bun"]}>

If you run jobs from [BullMQ](https://docs.bullmq.io) job schedulers, add `bullmqJobSchedulerIntegration` to monitor them, as described in [BullMQ](#bullmq) below.

</PlatformSection>

### Cron

Requires SDK version `7.92.0` or higher.

Use `Sentry.cron.instrumentCron` to instrument the `CronJob` constructor or `CronJob.from` method in the [`cron`](https://www.npmjs.com/package/cron) library. Pass the name of the cron monitor as a second argument to the function.

```JavaScript
import { CronJob } from "cron";

const CronJobWithCheckIn = Sentry.cron.instrumentCron(CronJob, "my-cron-job");

// use the constructor
const job = new CronJobWithCheckIn("* * * * *", () => {
  console.log("You will see this message every minute");
});

// or from method
const job = CronJobWithCheckIn.from({
  cronTime: "* * * * *",
  onTick: () => {
    console.log("You will see this message every minute");
  },
});
```

### Node Cron

Requires SDK version `7.92.0` or higher.

Use `Sentry.cron.instrumentNodeCron` to instrument the `cron` export from the [`node-cron`](https://www.npmjs.com/package/node-cron) library. This returns an object with the same API as the original `cron` export, but with the `schedule` method instrumented. You can pass the name of the cron monitor and an optional time zone as part of the third options argument to the function.

```JavaScript
import cron from "node-cron";

const cronWithCheckIn = Sentry.cron.instrumentNodeCron(cron);

cronWithCheckIn.schedule(
  "* * * * *",
  () => {
    console.log("running a task every minute");
  },
  { name: "my-cron-job" }
);
```

### Node Schedule

Requires SDK version `7.93.0` or higher.

Use `Sentry.cron.instrumentNodeSchedule` to instrument the `schedule` export from the [`node-schedule`](https://www.npmjs.com/package/node-schedule) library. This returns an object with the same API as the original `schedule` export, but with the `scheduleJob` method instrumented. You can pass the name of the cron job as the first argument to the function. Currently this only supports cronstring as the second argument to `scheduleJob`.

```JavaScript
import * as schedule from "node-schedule";

const scheduleWithCheckIn = Sentry.cron.instrumentNodeSchedule(schedule);

scheduleWithCheckIn.scheduleJob(
  "my-cron-job",
  "* * * * *",
  () => {
    console.log("running a task every minute");
  }
);
```

### BullMQ

Requires the next SDK release after `11.12.0`, and `bullmq` version `5.16.0` to `6.x`.

Add `bullmqJobSchedulerIntegration` to send check-ins for every job a BullMQ `Worker` runs from a [job scheduler](https://docs.bullmq.io/guide/job-schedulers). Every worker in your app is monitored, without changes to your worker code:

```JavaScript
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    Sentry.bullmqJobSchedulerIntegration({
      excludeJobSchedulers: ["cache-warmup", /^tmp-/], // Optional.
    }),
  ],
});
```

```JavaScript
import { Queue, Worker } from "bullmq";

const queue = new Queue("reports", { connection });
await queue.upsertJobScheduler(
  "daily-report",
  { pattern: "0 9 * * 1-5", tz: "Europe/Vienna" },
  { name: "report" }
);

const worker = new Worker("reports", processor, { connection });
```

<PlatformSection notSupported={["javascript.nextjs"]}>

Like the SDK's other auto-instrumentation, this only works if `Sentry.init()` runs before your app imports `bullmq`, so load your instrument file with `--import`. If `bullmq` is imported first, no check-ins are sent.

</PlatformSection>

<PlatformSection supported={["javascript.nextjs"]}>

Next.js bundles `bullmq` into your server build by default, which stops this integration from working. Add it to `serverExternalPackages` in your `next.config.js` (`experimental.serverComponentsExternalPackages` on Next.js 14):

```JavaScript {filename:next.config.js}
const nextConfig = {
  serverExternalPackages: ["bullmq"],
};
```

</PlatformSection>

The monitor slug is the queue name and the job scheduler ID joined by `-`, like `reports-daily-report` in this example, and the scheduler's `pattern` or `every` is sent as the monitor schedule. Each monitored job scheduler creates its own monitor, and each monitor is billed. Jobs that weren't created by a job scheduler aren't monitored. `excludeJobSchedulers` skips job schedulers whose ID matches a string exactly or a regular expression.

Patterns use the scheduler's `tz` time zone, or the server's time zone without one. A job that BullMQ retries shows as one check-in, which fails only if the last attempt fails.

These aren't monitored:

- Schedules Sentry can't express, like an `every` interval that isn't a whole number of minutes or a pattern that runs every few seconds
- Time zones given as an offset like `UTC+5` rather than an IANA name like `Europe/Vienna`
- Schedulers with a `limit` or `endDate`
- On BullMQ 5, patterns with an `nthDayOfWeek` and anything but a single day of the week
- Patterns on a worker with a custom `repeatStrategy`
- Repeatable jobs added with `queue.add` and the `repeat` option
- Workers in a server build that bundles BullMQ instead of loading it from `node_modules`

</PlatformSection>
