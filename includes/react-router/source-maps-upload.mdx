Next, call `sentryOnBuildEnd` in the `buildEnd` hook of your `react-router.config.ts`. It adds debug IDs to your build output and uploads the source maps:

```typescript {filename: react-router.config.ts} {diff}
import type { Config } from "@react-router/dev/config";
+import { sentryOnBuildEnd } from "@sentry/react-router/vite";

export default {
  ssr: true,
+ buildEnd: async ({ viteConfig, reactRouterConfig, buildManifest }) => {
+   // ...
+   // Call this at the end of the hook
+   await sentryOnBuildEnd({ viteConfig, reactRouterConfig, buildManifest });
+ },
} satisfies Config;
```

When you don't set `build.sourcemap` in your Vite config, the SDK turns on hidden source maps for the client and server builds. After the upload, `sentryOnBuildEnd` removes the `.map` files from your build directory. When you turn on source maps yourself, the SDK uploads them and they stay.

To change this, set the [`sourcemaps.upload`](/platforms/javascript/sourcemaps/uploading/bundler-plugin-options/#sourcemaps.upload), [`sourcemaps.injectDebugIds`](/platforms/javascript/sourcemaps/uploading/bundler-plugin-options/#sourcemaps.injectDebugIds), and [`sourcemaps.delete`](/platforms/javascript/sourcemaps/uploading/bundler-plugin-options/#sourcemaps.delete) options in your Sentry config. For example, to keep the source maps for a manual upload later:

```typescript {filename: vite.config.ts}
const sentryConfig: SentryReactRouterBuildOptions = {
  // ...
  sourcemaps: {
    upload: false,
    delete: false,
  },
};
```
