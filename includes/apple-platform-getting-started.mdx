## Install

Sentry captures data by using an SDK within your application's runtime. We recommend installing the SDK with Swift Package Manager (SPM).

<PlatformSection supported={["apple.ios"]}>

### Automatic Install

The [Sentry Wizard](https://github.com/getsentry/sentry-wizard) installs the SDK and adds an initial configuration. Run this command from your project directory:

```bash
brew install getsentry/tools/sentry-wizard && sentry-wizard -i ios
```

Review and commit the files the wizard modifies.

<Expandable title="The following tasks will be performed by the Sentry Wizard">

- Install the Sentry SDK with Swift Package Manager
- Update your `AppDelegate` or SwiftUI app initializer with the initial Sentry configuration and an example message
- Add an `Upload Debug Symbols` build phase to your Xcode target
- Create `.sentryclirc` with an auth token for uploading debug symbols (the file is added to `.gitignore`)
- Add a Fastlane lane for uploading debug symbols if you're using Fastlane

</Expandable>

**Return to this guide after running the wizard to complete setup.** The wizard doesn't configure Session Replay, instrument your SwiftUI views, or add application-specific logs and metrics.

Continue with [Configure](#configure), merge the settings into the existing `SentrySDK.start` call, and follow the remaining steps to send and verify your data.

Wizard 9.0.0 also needs these corrections when used with the SDK versions in this guide:

- Remove `options.experimental.enableLogs` if the wizard adds it. SDK 9.27.0+ sends logs through `SentrySDK.logger` without an enable flag.
- In Objective-C, replace `SentryProfilingLifecycleTrace` with `SentryProfileLifecycleTrace`.

### Manual Install

To install without the wizard, follow the SPM instructions below. If you used the wizard, skip to [Configure](#configure). For more detail, see <PlatformLink to="/manual-setup/">Manual Setup</PlatformLink>.

</PlatformSection>

In Xcode, open **File > Add Package Dependencies**, then enter this repository URL:

```
https://github.com/getsentry/sentry-cocoa.git
```

Select a compatible SDK version and add **one** SDK product to your application target:

- **SentrySPM** builds the SDK from source and is the recommended choice.
- **Sentry** uses the prebuilt static framework.

Both products use `import Sentry`. See <PlatformLink to="/install/swift-package-manager/">Swift Package Manager</PlatformLink> for other products, or <PlatformLink to="/install/">the installation options</PlatformLink> for other installation methods.

### Initialize the SDK

Initialize the SDK in your app delegate's `application(_:didFinishLaunchingWithOptions:)` method or your SwiftUI `App` initializer. Session Replay requires Sentry Cocoa SDK 8.31.1+ and supports the iOS versions supported by that SDK; it doesn't require iOS 16. UI Profiling requires SDK 8.49.0+.

```swift {tabTitle:Swift} {mdExpandTabs}
import Sentry
import UIKit

func application(_ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
    SentrySDK.start { options in
        options.dsn = "___PUBLIC_DSN___"
        options.debug = true
        options.sendDefaultPii = true

        // Enable Tracing. Reduce this value in production.
        options.tracesSampleRate = 1.0

        // Enable Profiling.
        options.configureProfiling = {
            $0.lifecycle = .trace
            $0.sessionSampleRate = 1.0
        }

        // Enable Session Replay.
        options.sessionReplay.onErrorSampleRate = 1.0
        options.sessionReplay.sessionSampleRate = 0.1
    }
    return true
}
```

```objc {tabTitle:Objective-C}
@import Sentry;

- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
    [SentrySDK startWithConfigureOptions:^(SentryOptions *options) {
        options.dsn = @"___PUBLIC_DSN___";
        options.debug = YES;
        options.sendDefaultPii = YES;

        // Enable Tracing. Reduce this value in production.
        options.tracesSampleRate = @1.0;

        // Enable Profiling.
        options.configureProfiling = ^(SentryProfileOptions *profiling) {
            profiling.lifecycle = SentryProfileLifecycleTrace;
            profiling.sessionSampleRate = 1.0;
        };

        // Enable Session Replay.
        options.sessionReplay.onErrorSampleRate = 1.0;
        options.sessionReplay.sessionSampleRate = 0.1;
    }];
    return YES;
}
```

```swift {tabTitle:SwiftUI with App conformer}
import Sentry
import SwiftUI

@main
struct ExampleApp: App {
    init() {
        SentrySDK.start { options in
            options.dsn = "___PUBLIC_DSN___"
            options.debug = true
            options.sendDefaultPii = true
            options.tracesSampleRate = 1.0
            options.configureProfiling = {
                $0.lifecycle = .trace
                $0.sessionSampleRate = 1.0
            }
            options.sessionReplay.onErrorSampleRate = 1.0
            options.sessionReplay.sessionSampleRate = 0.1
        }
    }

    var body: some Scene {
        WindowGroup {
            SentryTracedView("Home") {
                Text("Hello, world!")
            }
        }
    }
}
```

For SwiftUI, keep your existing app content inside `WindowGroup` and wrap the views you want to measure with `SentryTracedView`, as shown above. See <PlatformLink to="/tracing/instrumentation/swiftui-instrumentation/">SwiftUI Instrumentation</PlatformLink> for more options.

</PlatformSection>

### Initialize the SDK

Initialize the SDK in your app delegate's `applicationDidFinishLaunching(_:)` method or your SwiftUI `App` initializer. The snippet configures Tracing and Profiling. UI Profiling requires Sentry Cocoa SDK 8.49.0+. macOS doesn't support Session Replay.

```swift {tabTitle:Swift}
import Sentry

SentrySDK.start { options in
    options.dsn = "___PUBLIC_DSN___"
    options.debug = true
    options.sendDefaultPii = true
    options.enableUncaughtNSExceptionReporting = true

    // Enable Tracing. Reduce this value in production.
    options.tracesSampleRate = 1.0

    // Enable Profiling.
    options.configureProfiling = {
        $0.lifecycle = .trace
        $0.sessionSampleRate = 1.0
    }
}
```

```objc {tabTitle:Objective-C}
@import Sentry;

[SentrySDK startWithConfigureOptions:^(SentryOptions *options) {
    options.dsn = @"___PUBLIC_DSN___";
    options.debug = YES;
    options.sendDefaultPii = YES;
    options.enableUncaughtNSExceptionReporting = YES;
    options.tracesSampleRate = @1.0;
    options.configureProfiling = ^(SentryProfileOptions *profiling) {
        profiling.lifecycle = SentryProfileLifecycleTrace;
        profiling.sessionSampleRate = 1.0;
    };
}];
```

On macOS, the SDK can't capture uncaught exceptions without additional configuration. The snippets enable `enableUncaughtNSExceptionReporting`, which also sets `NSApplicationCrashOnExceptions` so the app crashes on an uncaught exception.

Don't combine this option with `SentryCrashExceptionApplication`, which can cause duplicate reports. See <PlatformLink to="/usage/#capturing-uncaught-exceptions">capturing uncaught exceptions</PlatformLink> for details.

</PlatformSection>

### Send a Test Trace

Sampling settings determine which transactions to send; they don't create transactions. Start a transaction around an operation in your app and finish it when the operation completes:

```swift {tabTitle:Swift} {mdExpandTabs}
let transaction = SentrySDK.startTransaction(
    name: "Example Operation",
    operation: "task",
    bindToScope: true
)

// Perform the operation you want to measure.

transaction.finish()
```

```objc {tabTitle:Objective-C}
id<SentrySpan> transaction = [SentrySDK startTransactionWithName:@"Example Operation"
                                                    operation:@"task"
                                                  bindToScope:YES];

// Perform the operation you want to measure.

[transaction finish];
```

For asynchronous work, finish the transaction in the completion handler. Binding a transaction to the scope lets automatic instrumentation, such as HTTP tracing, attach child spans to it.

<PlatformSection supported={["apple.macos", "apple.watchos"]}>

macOS and watchOS don't automatically create UIKit screen-load or app-start transactions. Add transactions around operations you want to measure, as shown above, or instrument your views with <PlatformLink to="/tracing/instrumentation/swiftui-instrumentation/">SwiftUI Instrumentation</PlatformLink>.

</PlatformSection>

<PlatformSection supported={["apple.ios", "apple.macos"]}>

With the `.trace` profiling lifecycle used above, profiling runs while sampled root spans are active. Configure and start a transaction to collect profiles; setting a profile sample rate alone doesn't start the profiler. See <PlatformLink to="/profiling/">Set Up Apple Profiling</PlatformLink> for other lifecycles.

</PlatformSection>

## Send Logs

Use `SentrySDK.logger` after initializing the SDK to send logs on all supported Apple platforms, including watchOS. In SDK 9.27.0+, these calls don't require an enable flag.

For SDK 9.0.0–9.26.x, set `options.enableLogs = true` during initialization. For SDK 8.55.0–8.x, use `options.experimental.enableLogs = true`. See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for logging methods and options.

```swift {tabTitle:Swift} {mdExpandTabs}
SentrySDK.logger.info("User example action completed")

SentrySDK.logger.warn("Slow operation detected", attributes: [
    "operation": "data_fetch",
    "duration": 3500
])
```

```objc {tabTitle:Objective-C}
SentryLogger *logger = SentrySDK.logger;
[logger info:@"User example action completed"];
[logger warn:@"Slow operation detected" attributes:@{
    @"operation": @"data_fetch",
    @"duration": @3500
}];
```

To stop sending logs, remove the logging calls or filter them with <PlatformLink to="/logs/#beforesendlog">`beforeSendLog`</PlatformLink>. In SDK 9.27.0+, setting `enableLogs` to `false` doesn't drop logs sent through this API.

## Send Application Metrics <FeatureBadge type="new" />

Application Metrics are enabled by default, but you must record them explicitly. In Sentry Cocoa SDK 9.12.0 and later, use `SentrySDK.metrics` to send counters, gauges, and distributions. Metrics were experimental in versions 9.2.0–9.11.x.

`SentrySDK.metrics` is a Swift API. Objective-C projects can use `SentryObjCSDK.metrics` through the separate `SentryObjC` integration, available since SDK 9.16.0. See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for usage and filtering options.

```swift {tabTitle:Swift}
SentrySDK.metrics.count(key: "checkout.failed", value: 1)

SentrySDK.metrics.gauge(key: "time_since_refresh", value: 4, unit: .hour)

SentrySDK.metrics.distribution(
    key: "api_latency",
    value: 187,
    unit: .millisecond,
    attributes: ["endpoint": "/api/orders"]
)
```

## Verify Your Setup

Capture a handled test error after initializing the SDK. You should see it in your Sentry project's Issues page within a few minutes.

```swift {tabTitle:Swift} {mdExpandTabs}
import Foundation
import Sentry

SentrySDK.capture(error: NSError(domain: "SentryTest", code: 1))
```

```objc {tabTitle:Objective-C}
[SentrySDK captureError:[NSError errorWithDomain:@"SentryTest" code:1 userInfo:nil]];
```

<PlatformSection notSupported={["apple.watchos"]}>

This verifies handled-error delivery. To test crash reporting, run your app **without a debugger attached**, trigger a test crash, then relaunch the app so the SDK can send the report. See <PlatformLink to="/usage/">Capturing Errors</PlatformLink> for more ways to capture events.

</PlatformSection>
