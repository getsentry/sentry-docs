Most server SDKs no longer register an OpenTelemetry tracer provider. They produce native Sentry spans and ignore spans created through `@opentelemetry/api`. Only `@sentry/nextjs` and `@sentry/sveltekit` register a lightweight OpenTelemetry-compatible provider by default to capture framework spans.

If you only use the Sentry SDK, tracing works as before. If your code or a library creates spans through `@opentelemetry/api`, set [`enableOpenTelemetrySetup: true`](#enable-opentelemetry-setup) to send those spans to Sentry.

If you run your own OpenTelemetry pipeline, follow [Custom OpenTelemetry setups](#custom-otel-setup) and use [`openTelemetryIntegration()`](#otlp-integration-changes) to connect Sentry events to it.
