String and regular-expression matching for `tracePropagationTargets` is now case-insensitive. In browsers, a target written with the same casing as the request, such as `'myApi.com'`, could never match before, because `new URL()` lower-cases the origin before matching. The `g` and `y` flags are ignored on regular expressions now, since they made matching stateful via `lastIndex`.

If you relied on case-sensitive matching to distinguish targets, narrow the target with a more specific path.
