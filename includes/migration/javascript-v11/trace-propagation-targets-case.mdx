String and regular-expression matching for `tracePropagationTargets` is now case-insensitive. In browsers, a target written with the same casing as the request, such as `'myApi.com'`, could never match before, because the URL is lower-cased with `new URL()` first. The `g` and `y` flags are ignored on regular expressions now, since they made matching stateful via `lastIndex`.

Nothing to do, unless you relied on case sensitivity to exclude a target. It will now match and receive trace headers.
