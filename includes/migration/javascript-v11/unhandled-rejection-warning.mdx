In `strict` mode, the warning `This error originated either by throwing inside of an async function without a catch block, or by rejecting a promise which was not handled with .catch(). The promise rejected with the reason:` is now printed only when the rejection reason has no stack trace, matching Node.js. A rejection with an `Error` reason prints the error alone.

Nothing to do, unless you match on that warning text in log processing or tests. The process still exits with code `1` and the reason is still written to `stderr`.
