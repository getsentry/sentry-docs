In `strict` mode, `onUnhandledRejectionIntegration` printed a warning in front of every unhandled rejection. It's now printed only when the rejection reason has no stack trace, which matches Node.js. Update log processing or tests that match on that text. The process still exits with code `1`, and the reason is still written to `stderr`.
