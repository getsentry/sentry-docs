Version 7 removes `SentryOptions.EnableLogs`, so setting it in `SentrySdk.Init` fails to compile with error CS1061. Remove the line. Logs sent with `SentrySdk.Logger` or through the logging integrations don't need it.

In 6.x, `SentrySdk.Init` turned logs on:

```csharp {filename:Program.cs}
SentrySdk.Init(options =>
{
    options.Dsn = "___PUBLIC_DSN___";
    options.EnableLogs = true;
});
```

In 7.x, logs need no option:

```csharp {filename:Program.cs}
SentrySdk.Init(options =>
{
    options.Dsn = "___PUBLIC_DSN___";
});
```

`EnableLogs` stays on the options of `UseSentry` in ASP.NET Core, MAUI, Blazor WebAssembly and generic host apps. There it still defaults to `false`, and it only controls whether the `ILogger` integration that `UseSentry` adds sends log entries as logs:

```csharp {filename:Program.cs}
var builder = WebApplication.CreateBuilder(args);
builder.UseSentry(options =>
{
    options.Dsn = "___PUBLIC_DSN___";
    options.EnableLogs = true;
});
```

You can also set `EnableLogs` in the `Sentry` section of `appsettings.json` in these apps. A generic host app that set `EnableLogs` on `Logging.AddSentry` in 6.x sets it on `UseSentry` now.

The Serilog sink no longer takes an `enableLogs` argument, and NLog's `enableLogs` setting has no effect. The Serilog sink, the NLog target and the log4net appender send logs whether `EnableLogs` is on or off. See [Logging Integrations Send Logs](#logging-integrations-send-logs).
