In an app that calls `UseSentry`, `Logging.AddSentry()` now does nothing, and options passed to it in code no longer apply. Move those options to `UseSentry` and remove the call.

The exception is an app that calls `ClearProviders()` after `UseSentry`, which also removes Sentry's logger providers. Keep `Logging.AddSentry()` there to add them back. It uses the options of `UseSentry`, not the ones passed to it. Leave it out if Serilog, NLog or log4net already sends the app's `ILogger` entries to Sentry, because each entry would then arrive twice.

In 6.x, an app with both calls captured each error, breadcrumb and log twice. In 7.x, the `ILogger` integration that `UseSentry` adds captures them once, with the options of `UseSentry`. With `Debug` on, the SDK logs a warning about the redundant call.

In 6.x, the app passed the logging options to `Logging.AddSentry`:

```csharp {filename:Program.cs}
var builder = WebApplication.CreateBuilder(args);
builder.WebHost.UseSentry(options => options.Dsn = "___PUBLIC_DSN___");
builder.Logging.AddSentry(options => options.MinimumBreadcrumbLevel = LogLevel.Debug);
```

In 7.x, set them on the options of `UseSentry`:

```csharp {filename:Program.cs}
var builder = WebApplication.CreateBuilder(args);
builder.UseSentry(options =>
{
    options.Dsn = "___PUBLIC_DSN___";
    options.MinimumBreadcrumbLevel = LogLevel.Debug;
});
```

Blazor WebAssembly apps often called `Logging.AddSentry` with `InitializeSdk = false`. That line now fails to compile with error CS0619. In 6.x, the setup looked like this:

```csharp {filename:Program.cs}
using Microsoft.AspNetCore.Components.WebAssembly.Hosting;

var builder = WebAssemblyHostBuilder.CreateDefault(args);
builder.UseSentry(options => options.Dsn = "___PUBLIC_DSN___");
builder.Logging.AddSentry(options => options.InitializeSdk = false);
```

In 7.x, remove the `Logging.AddSentry` line:

```csharp {filename:Program.cs}
using Microsoft.AspNetCore.Components.WebAssembly.Hosting;

var builder = WebAssemblyHostBuilder.CreateDefault(args);
builder.UseSentry(options => options.Dsn = "___PUBLIC_DSN___");
```

The log levels under `Logging:Sentry` keep working, because `UseSentry` reads that section too.
