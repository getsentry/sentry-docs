Your job sends check-ins to Sentry, and Sentry compares them with the monitor's schedule.

## Check-Ins

Send an `in_progress` check-in when the job starts and an `ok` or `error` check-in when it finishes. Use the same `check_in_id` for both, so Sentry matches them to the right run. SDK monitor helpers and `sentry-cli monitors run` do this for you.

Sentry marks a run as:

- **Missed** if no check-in arrives within the check-in margin of the expected time.
- **Timed out** if it started but didn't finish within the max runtime.

If you only send a check-in when the job finishes, Sentry can't detect runs that hang.

## Schedules

A crontab schedule expects a check-in each time the expression matches, in the monitor's timezone. An interval schedule expects one an interval after the last check-in. If your job starts at fixed times, use a crontab schedule.

## Issues

Sentry opens an issue after the number of failures in a row (missed, failed, or timed out) set by the monitor's failure tolerance, and resolves it after the number of successes in a row set by its recovery tolerance. Connect an [Alert](/product/monitors-and-alerts/alerts/) to get notified.

Each environment has its own check-ins and issues. If a job stops running in an environment, delete that environment from the monitor, or Sentry will keep marking it as missed.

## Limits and Defaults

| Setting                        | Default    | Limit                                                 |
| ------------------------------ | ---------- | ----------------------------------------------------- |
| Schedule                       | —          | Five-field crontab or interval, at most once a minute |
| Check-in margin                | 1 minute   | 28 days                                               |
| Max runtime                    | 30 minutes | 7 days                                                |
| Failure and recovery tolerance | 1          | 720                                                   |
| Timezone                       | UTC        | —                                                     |
| Monitor slug                   | —          | 50 characters                                         |
| Check-ins                      | —          | 6 per minute per environment                          |
| Retention                      | —          | 90 days                                               |
