The Supabase for Seer integration gives [Seer Agent](/product/ai-in-sentry/seer/#seer-agent) read-only access to project logs and security and performance advisors in your Supabase organization. Seer can then use Supabase data to enhance or supplement Sentry telemetry in issue analysis or investigations.

The connection is shared across your Sentry organization. You can connect one Supabase organization per Sentry organization. Individual Sentry users don't need to connect their own Supabase accounts.

Seer connects through [Supabase's MCP server](https://supabase.com/docs/guides/ai-tools/mcp) in read-only mode, with only the account and debugging tool groups enabled. These tools let Seer discover projects and read their logs and advisor findings. SQL queries, database table browsing, and tools that change Supabase resources are not enabled.

This integration is separate from [Supabase Log Drains](/product/drains/supabase/), which forward Supabase logs to Sentry.

## Install the Supabase for Seer Integration

<Alert>

Sentry Owner, Manager, or Admin permissions are required to install this integration.

You also need to be a Supabase organization owner to authorize access across the organization's projects. A Supabase organization owner can complete these steps for you.

</Alert>

1. Navigate to [Seer Connector Settings](https://sentry.io/orgredirect/organizations/:orgslug/settings/seer/connectors/).
2. Select the Supabase for Seer integration and click **Add Organization**.
3. Click **Authorize Supabase**. A Supabase authorization window opens. If it doesn't, allow popups from Sentry in your browser and click **Authorize Supabase** again.
4. In the Supabase window, select the organization you want to connect, review the requested access, and approve it.

   Sentry's app requests read-only access to **Analytics**, **Database**, **Organizations**, and **Projects**. Analytics access lets Seer read logs, and Database access lets it read security and performance advisors. The connection covers the organization's current and future projects; you don't select individual projects during setup.

5. After you approve, Sentry checks that it can identify the authorized organization before completing installation. The new connection appears as **Supabase (_Organization Name_)**.

   This check does not test logs or advisors for every project. If setup fails, the error appears in the setup modal. Correct the problem and click **Authorize Supabase** again. You can retry in the same setup modal.

## Configure

The integration has no settings to edit. Sentry refreshes the Supabase access token automatically, so you don't need to create or rotate API keys or personal access tokens.

To reauthorize the organization, open the [Supabase for Seer settings page](https://sentry.io/orgredirect/organizations/:orgslug/settings/integrations/supabase/), click **Add Organization** (or **Reinstall** if the connection is disabled), then click **Authorize Supabase** and approve access in Supabase again. Choose the same organization you connected originally. To connect a different organization, uninstall the current connection first, then install the integration again.

When you uninstall the integration, Sentry attempts to revoke its access in Supabase. If another Sentry organization is connected to the same Supabase organization, Sentry keeps the grant so that organization's connection keeps working.

## Troubleshooting

If the connection needs attention:

- **Supabase authorization was canceled:** You closed or declined the Supabase authorization window. Click **Authorize Supabase** to try again.
- **The authorization popup was blocked:** Allow popups from Sentry in your browser, then click **Authorize Supabase** again.
- **Could not reach Supabase:** Supabase could not be reached during setup. Wait a moment, then try again.
- **Supabase authorization failed:** Confirm that you're a Supabase organization owner and approved the requested access, then authorize the organization again. For an existing connection, access may have been revoked in Supabase. Reauthorize it from the integration settings.
- **Could not verify the connection to Supabase:** Retry authorization and select one Supabase organization. If the error persists, contact Sentry support with the error shown.
- **An error asks you to change OAuth app permissions:** The OAuth app is managed by Sentry. Contact Sentry support rather than creating your own app or providing a personal access token.
- **Remove the current Supabase connection before connecting a different organization:** Your Sentry organization is already connected to a different Supabase organization. Uninstall that connection, or select the original organization when you reauthorize.
- **The integration was disabled:** Sentry disables the connection if Supabase rejects its refresh token, for example after access is revoked. Click **Reinstall** on the integration settings page and authorize the organization again.
- **Setup succeeds, but Seer cannot read logs or advisors:** Setup verifies the organization, not every project's logs and advisors. Confirm that the project belongs to the connected Supabase organization and that the requested data is available in Supabase.

After correcting the setup, retry **Authorize Supabase** during installation or reauthorize the connection from the integration settings.
