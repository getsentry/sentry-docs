The <PlatformLink to="/metric-kit/">MetricKit</PlatformLink> integration sends the metric payloads of [MetricKit](https://developer.apple.com/documentation/metrickit), such as CPU time, network transfer, memory, launch times and app exit counts, as <PlatformLink to="/metrics/">Application Metrics</PlatformLink>. Metric reports are independent of <PlatformLink to="/metric-kit/diagnostic-reports/">diagnostic reports</PlatformLink>, and you can enable either without the other.

<Alert level="warning" title="Experimental">

This option is experimental and may change in future releases. It's available from Swift on Cocoa 9.32.0 and up, and through the <PlatformLink to="/install/swift-package-manager/#sentryobjc-objective-c">SentryObjC</PlatformLink> SDK on Cocoa 9.33.0 and up.

</Alert>

## Enable Metric Reports

Use `options.experimental.metrickit.enabledMetricReports` to choose the [metric reports](#available-reports) the SDK sends. A non-empty set enables the integration, even when no diagnostic reports are enabled. Use `.all` (`SentryObjCMetricKitMetricReportAll` in Objective-C) to send every metric report. The option defaults to an empty set.

```swift {tabTitle:Swift}
import Sentry

SentrySDK.start { options in
    options.dsn = "___PUBLIC_DSN___"
    options.experimental.metrickit.enabledMetricReports = [
        .cpuCumulativeTime,
        .memoryPeakUsage,
        .exitForegroundWatchdog,
        .exitForegroundMemoryResourceLimit,
    ]
}
```

```objc {tabTitle:Objective-C (SentryObjC)}
#import <SentryObjC/SentryObjC.h>

[SentryObjCSDK startWithConfigureOptions:^(SentryObjCOptions *options) {
    options.dsn = @"___PUBLIC_DSN___";
    options.experimental.metrickit.enabledMetricReports =
        SentryObjCMetricKitMetricReportCPUCumulativeTime
        | SentryObjCMetricKitMetricReportMemoryPeakUsage
        | SentryObjCMetricKitMetricReportExitForegroundWatchdog
        | SentryObjCMetricKitMetricReportExitForegroundMemoryResourceLimit;
}];
```

## Volume and Attributes

MetricKit delivers metric payloads [at most once a day](https://developer.apple.com/documentation/metrickit/monitoring-app-performance-with-metrickit#Understand-the-reporting-model), each covering the previous 24 hours, so metrics can arrive up to a day after the values were recorded. Each enabled report adds up to one metric per payload, except for [histogram reports](#histogram-reports), which add up to about 100. Metrics count towards your metrics quota. Counts of zero aren't sent. Every metric is placed in the middle of the payload's reporting interval and carries these attributes:

- `app.version` and `app.build`: the app version the values were recorded with. They're left out when the payload spans an app update.
- `sentry.release`: the release of that app version, when it differs from the running release.
- `os.version`: the OS version the values were recorded on.
- `metal.layer_name`: the name of the Metal layer, only on the `metrickit.metal.*` metrics.

On macOS, MetricKit delivers metric payloads from macOS 26, and only to apps built with Xcode 26 or later.

Only `MetricManager` provides the reports listed as available on iOS and macOS 27 and later, and it doesn't report `.animationScrollHitchTimeRatio`, because it only reports the hitch time of all animations. ## Histogram Reports

MetricKit reports launch times, hang times and the cellular condition as histograms, which only count samples per range of values. Starting with SDK version 9.35.0, the SDK sends each sample as one distribution value at the middle of its range, spread evenly across the reporting interval. A histogram with more than 100 samples is scaled down to about 100 values and keeps its shape.
