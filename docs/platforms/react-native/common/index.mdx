## Install

Sentry captures data by using an SDK within your application's runtime. These platform-specific SDKs give Sentry a deeper understanding of how your application works.

Run `@sentry/wizard` to install and configure the SDK:

```bash {tabTitle:npm}
npx @sentry/wizard@latest -i reactNative
```

[Sentry Wizard](https://github.com/getsentry/sentry-wizard) patches your project. You only need to do this once; then add the patched files to version control. If you prefer, follow the [manual setup guide](/platforms/react-native/manual-setup/manual-setup/).

<Expandable title="The following tasks will be performed by the Sentry Wizard">

- Install the `@sentry/react-native` package.
- Add `@sentry/react-native/metro` to the _*metro.config.js*_ Metro configuration.
- Add `@sentry/react-native/expo` to the _*app.json*_ Expo configuration.
- Enable the Sentry React Native Gradle build step for Android to auto-upload generated source maps and debug symbols.
- Wrap the _Bundle React Native code and images_ Xcode project build phase script to upload generated source maps and collect bundled node modules.
- Add the _Upload Debug Symbols to Sentry_ Xcode project build phase.
- Run `pod install`.
- Store build credentials in _*ios/sentry.properties*_, _*android/sentry.properties*_, and _*.env.local*_.
- Configure Sentry with the supplied DSN in your _*layout.tsx*_ or _*App.tsx*_ file.

</Expandable>

If you're using Expo, follow the [Expo guide](/platforms/react-native/guides/expo/) for Expo-specific setup. The SDK works with both managed and bare projects.

## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** need `enableLogs: true` in the initialization snippet below, and you'll learn how to send them in [Send Logs](#send-logs). **Application Metrics** need no extra configuration, and you'll learn how to send them in [Send Application Metrics](#send-application-metrics-).

This guide also enables **Tracing**, **Profiling**, **Session Replay**, and **User Feedback**. **Size Analysis** uses a separate build-time setup; see <PlatformLink to="/size-analysis/">Size Analysis</PlatformLink>.

<Include name="quick-start-features-expandable" />

To capture errors, initialize the Sentry React Native SDK as early as possible in your application's lifecycle.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>
- Profiling: via `profilesSampleRate` (see <PlatformLink to="/profiling/">Profiling</PlatformLink>)
- Session Replay: via `mobileReplayIntegration()` and the replay sample rates (see <PlatformLink to="/session-replay/">Session Replay</PlatformLink>)
- User Feedback: via `feedbackIntegration()` (see <PlatformLink to="/user-feedback/">User Feedback</PlatformLink>)
- Logs: via <PlatformLink to="/configuration/options/#enableLogs">`enableLogs`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

```javascript {filename:App.js}
import * as Sentry from "@sentry/react-native";

Sentry.init({
  dsn: "___PUBLIC_DSN___",
  // Adds context data to events, such as IP address, cookies, and user.
  sendDefaultPii: true,

  integrations: [
    // Enables Session Replay
    Sentry.mobileReplayIntegration(),
    // Enables User Feedback. Open the form with Sentry.showFeedbackWidget().
    Sentry.feedbackIntegration(),
  ],

  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,

  // Enables Profiling for 100% of sampled transactions.
  profilesSampleRate: 1.0,

  // Enables Logs to be sent to Sentry.
  enableLogs: true,

  // Capture replays for 10% of sessions and 100% of sessions with an error.
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,
});
```

### Wrap Your App

To automatically instrument your app with [touch event tracking](/platforms/react-native/configuration/touchevents/) and [automatic tracing](/platforms/react-native/tracing/instrumentation/automatic-instrumentation/), wrap its root component with `Sentry.wrap`:

```javascript {filename:App.js}
export default Sentry.wrap(App);
```

You don't need this if your app doesn't have a single parent `App` component.

## Send Logs

Use `Sentry.logger` to send logs at different levels. You can include attributes to search or filter by later.

The SDK can capture `console.*` calls when Logs are enabled. See the [Console logging integration](/platforms/react-native/integrations/console-logging/) for details.

```javascript
Sentry.logger.info("Order processed", { order_id: "order-123" });
Sentry.logger.warn("Slow operation detected", {
  operation: "data_fetch",
  duration_ms: 3500,
});
```

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and message formatting options.

## Send Application Metrics <FeatureBadge type="new" />

Application Metrics are supported in React Native SDK 7.8.0 and newer. No extra option is needed after SDK initialization. Use `Sentry.metrics` to send counters, gauges, and distributions:

```javascript
Sentry.metrics.count("checkout.failed", 1);
Sentry.metrics.gauge("active_connections", 42);
Sentry.metrics.distribution("api_latency", 187, { unit: "millisecond" });
```

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

## Verify Your Setup

Trigger a test error to confirm that Sentry is receiving events. You should see the error in Sentry within a few minutes.

```javascript {tabTitle:Throw Error} {mdExpandTabs}
throw new Error("My first Sentry error!");
```

```javascript {tabTitle:Native Crash}
Sentry.nativeCrash();
```

Alternatively, use the <PlatformLink to="/manual-setup/playground/">Sentry Playground</PlatformLink> to test your setup interactively with multiple error scenarios.
