## Configure

**Error Monitoring** starts when the Spring integration initializes. This guide configures **Tracing** and **Profiling**. **Logs** require an explicit enable option, which the setup below includes. **Application Metrics** need no extra configuration; send them in [step 4](#send-application-metrics-).

Don't need a feature? Remove its configuration. Remove the `sentry-async-profiler` dependency to disable Profiling.

The default setup uses the Sentry OpenTelemetry agent. See the [agent setup guide](/platforms/java/opentelemetry/setup/agent/) or [agentless setup guide](/platforms/java/opentelemetry/setup/agentless/) for details.

## Send Logs

Logs must be enabled in your configuration; the snippets in Configure already do this. Use `Sentry.logger()` to send logs at different levels:

```java
import io.sentry.Sentry;

Sentry.logger().info("User example action completed");
Sentry.logger().warn("Slow operation detected");
Sentry.logger().error("Validation failed");
```

If you already log with JUL, Log4j2, or Logback, see the [JUL](/platforms/java/guides/jul/), [Log4j2](/platforms/java/guides/log4j2/), and [Logback](/platforms/java/guides/logback/) guides to send those logs to Sentry. Spring Boot users can also use the [logging framework integrations](/platforms/java/guides/spring-boot/logging-frameworks/).

See [Set Up Logs](/platforms/java/logs/) for all logging methods and configuration options.

## Send Application Metrics <FeatureBadge type="new" />

Metrics are available after SDK initialization; no additional option is required. Use `Sentry.metrics()` to send counters, gauges, and distributions. Add attributes to filter and group metrics.

See [Set Up Metrics](/platforms/java/metrics/) for all metric types and configuration options.

```java
import io.sentry.Sentry;

Sentry.metrics().count("checkout.failed", 1.0);
Sentry.metrics().gauge("queue_depth", 42.0);
Sentry.metrics().distribution("response_time", 187.5);
```
