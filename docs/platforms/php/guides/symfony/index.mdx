## Prerequisites

You need:

- a [Sentry account](https://sentry.io/signup/) and project
- a Symfony app running on PHP `7.2` or later
- [Composer](https://getcomposer.org/)

<StepConnector selector="h2" showNumbers={true}>

## Install

Install the latest `sentry/sentry-symfony` bundle:

```bash
composer require sentry/sentry-symfony
```

### Install Monolog for Logs

The logging configuration below also requires MonologBundle. If it isn't already installed, add it:

```bash
composer require symfony/monolog-bundle
```

## Configure

**Error Monitoring** starts working as soon as the bundle is enabled and your DSN is set. **Application Metrics** need no extra configuration and you'll learn how to send them in step [#4](#send-application-metrics-).
This guide also enables **Tracing**, **Profiling**, and **Logs**.

<Include name="quick-start-features-expandable" />

### Initialize the Sentry SDK

Add your Sentry DSN to your `.env` file:

```plain {filename:.env}
###> sentry/sentry-symfony ###
SENTRY_DSN="___PUBLIC_DSN___"
###< sentry/sentry-symfony ###
```

Then configure the bundle in `config/packages/sentry.yaml` as shown in the snippet below.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#traces_sample_rate">`traces_sample_rate`</PlatformLink>
- Profiling: via <PlatformLink to="/configuration/options/#profiles_sample_rate">`profiles_sample_rate`</PlatformLink>
- Logs: via the <PlatformLink to="/logs/">`sentry_logs` Monolog handler</PlatformLink>

Don't need a feature? Remove its options from the snippet.

{/* prettier-ignore */}
```yaml {filename:config/packages/sentry.yaml}
when@prod:
    sentry:
        dsn: '%env(SENTRY_DSN)%'
        options:
            # Enables Tracing.
            # Set to 1.0 to capture 100% of spans for tracing.
            # We recommend reducing this value in production.
            traces_sample_rate: 1.0

            # Enables Profiling.
            # Profiles are sampled relative to traces_sample_rate.
            profiles_sample_rate: 1.0

    # Sends Monolog records to Sentry as Logs.
    monolog:
        handlers:
            sentry_logs:
                type: service
                id: Sentry\SentryBundle\Monolog\LogsHandler

    services:
        Sentry\SentryBundle\Monolog\LogsHandler:
            arguments:
                # The minimum level of logs to send to Sentry.
                - !php/const Monolog\Logger::INFO
```

<Alert level="warning" title="Capture stack trace arguments">
  To receive stack trace arguments in your errors, set `zend.exception_ignore_args = Off` in your `php.ini`.
</Alert>

### Control the Data You Send to Sentry

By default, the SDK sends user identity data (IP address, ID, and similar) and other data (HTTP bodies, URL query parameters, etc.), with sensitive values scrubbed.

To opt out of individual categories use the `data_collection` option. For the full list of categories and their defaults, <PlatformLink to="/configuration/options/#data_collection">see the `data_collection` options</PlatformLink>.

```yaml {filename:config/packages/sentry.yaml}
when@prod:
    sentry:
        options:
            data_collection:
                # opt out of collecting user info
                user_info: false
                # opt out of collecting cookies
                cookies:
                    mode: "off"
                # other categories
            # your other Sentry options
],
```

### Enable Sentry in Other Environments

When using Symfony Flex, the Sentry bundle is enabled in the `prod` environment only by default, which is why the snippet uses `when@prod`. To use Sentry in other environments, update `config/packages/sentry.yaml` and the Sentry bundle entry in `config/bundles.php`.

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

Create the following controller, then visit `/_sentry-test` in an environment where Sentry is enabled:

```php
<?php

namespace App\Controller;

use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\Routing\Attribute\Route;

class SentryTestController extends AbstractController
{
    #[Route('/_sentry-test', name: 'sentry_test')]
    public function testException()
    {
        throw new \RuntimeException('Example exception.');
    }
}
```
