Sentry takes data privacy very seriously and has default settings in place that prioritize data safety, especially when it comes to personally identifiable information (PII) data. When you add the Sentry SDK to your application, you allow it to collect data and send it to Sentry during the runtime of your application.

The data the Sentry Unity SDK collects depends on the options and integrations you enable. Here's a list of data categories it collects:

## HTTP Requests and Database Queries

The Unity SDK doesn't instrument HTTP requests or databases, so it doesn't send request URLs, headers, cookies, or SQL queries.

## Information About the User

The SDK always sends an anonymous installation ID as `user.id`. On iOS, Android, and Nintendo Switch, it's the native SDK's installation ID, so C# events and native crashes share the same user.

If `SendDefaultPii` is set to `true`, the SDK also sends:

- The user's IP address. See [Users' IP Address](#users-ip-address).
- The device unique identifier. See [Device Unique Identifier](#device-unique-identifier).
- The device name. See [Device Name](#device-name).
- The operating system's user name as `user.username`, if **Auto Set UserName** (`IsEnvironmentUser`) is also enabled. Learn more in [Options](/platforms/unity/configuration/options/#IsEnvironmentUser).

To send your own user information, [identify the user](../../enriching-events/identify-user/).

## Users' IP Address

By default, the Sentry SDK doesn't send the user's IP address.

If `SendDefaultPii` is set to `true`, the SDK sets the user's IP address to `{{auto}}`, and Sentry fills in the IP address the event came from.

You can [prevent Sentry from storing IP Addresses](../../enriching-events/identify-user/#ip_address) either by configuring this in the ["Security & Privacy"](https://sentry.io/orgredirect/organizations/:orgslug/settings/projects/:projectId/security-and-privacy/) settings of your Sentry project or using [server-side data scrubbing](/security-legal-pii/scrubbing/server-side-scrubbing/).

## Device Unique Identifier

The Sentry SDK does not set the `Device Unique Identifier` by default.

If `SendDefaultPii` is set to `true` then the SDK will capture `SystemInfo.deviceUniqueIdentifier` automatically and send this with any event.

## Device Name

By default, the Sentry SDK doesn't send the device name.

If `SendDefaultPii` is set to `true`, the SDK sends the device's name as `device.name`. On desktop, this is the computer name.

The SDK never sends `ServerName`.

## General Device Information

The SDK collects information about the app, the operating system, the device, the GPU, and Unity, and sends it with every event. It sets these contexts when the SDK starts:

- `app`: the product name, the start time, and whether it's a debug or release build.
- `os`: the operating system description. On Xbox and PlayStation, it's the name of the console.
- `device`: the processor count, CPU, time zone, vibration support, device type, model, and system memory. In the Unity Editor, the device is marked as a simulator.
- `gpu`: the GPU's ID, name, vendor name and ID, memory, graphics API and version, maximum texture size, shader level, multithreaded rendering, and support for non-power-of-two textures, instancing, ray tracing, and compute and geometry shaders.
- `unity`: the Editor version, install mode, target frame rate, copy texture support, and rendering threading mode.

For events captured on the main thread, the SDK also adds:

- The app's allocated memory (`app.memory`).
- The battery status and level, and the device orientation.
- The connection type, on iOS and Android.
- The name of the active scene, in the Unity Editor and in IL2CPP builds.

Every event also records whether it was captured on the main thread (`unity.is_main_thread`).

## Breadcrumbs

The SDK records Unity log messages, scene changes, and app lifecycle events as breadcrumbs, and sends them with events. Log messages can contain PII, depending on what your game logs. Learn more in [Breadcrumbs](../../enriching-events/breadcrumbs/).

## Screenshots and View Hierarchy

Screenshots and the view hierarchy are opt-in. Both can contain PII, such as names shown on screen or in the names of GameObjects. Learn more in [Screenshots](../../enriching-events/screenshots/) and [View Hierarchy](../../enriching-events/view-hierarchy/).

## Data captured by Mobile SDKs

On mobile platforms, the Sentry SDK for Unity can also capture data through the Android and iOS SDKs. Refer to the documentation for those SDKs for more information on what data they capture.

- [Android](/platforms/android/data-management/data-collected/)
- [iOS](/platforms/apple/data-management/data-collected/)

## Data captured by the Native SDK

When compiling for Windows, Linux or other platforms that use Sentry Native, refer to [data captured by the Native SDK](/platforms/native/data-management/data-collected/) to understand what data is sent with those events.
