The Zerolog integration sends error events and optional breadcrumbs to Sentry. For structured logs, use `sentry.NewLogger` or a supported structured logging integration.

## Install

```bash
go get github.com/getsentry/sentry-go
go get github.com/getsentry/sentry-go/zerolog
```

## Configure

Initialize the Sentry client separately, then pass a context and `sentryzerolog.Options` to `New`. The writer uses that context for all its events and breadcrumbs.

```go
package main

import (
	"context"
	"log"
	"os"
	"time"

	"github.com/getsentry/sentry-go"
	sentryzerolog "github.com/getsentry/sentry-go/zerolog"
	"github.com/rs/zerolog"
)

func main() {
	if err := sentry.Init(sentry.ClientOptions{Dsn: "___PUBLIC_DSN___"}); err != nil {
		log.Fatal(err)
	}
	defer sentry.Flush(2 * time.Second)

	ctx, scope := sentry.WithScope(context.Background())
	scope.SetTag("job", "checkout")
	writer, err := sentryzerolog.New(ctx, sentryzerolog.Options{
		Levels:          []zerolog.Level{zerolog.ErrorLevel, zerolog.FatalLevel, zerolog.PanicLevel},
		WithBreadcrumbs: true,
		FlushTimeout:    3 * time.Second,
	})
	if err != nil {
		log.Fatal(err)
	}
	defer writer.Close()

	logger := zerolog.New(zerolog.MultiLevelWriter(os.Stderr, writer))
	logger.Error().Msg("Checkout failed")
}
```

`Levels` defaults to error, fatal, and panic. `WithBreadcrumbs` defaults to false. `FlushTimeout` defaults to three seconds and bounds flushing on fatal events and `writer.Close()`.

To use a custom client, create it with `sentry.NewClient` and pass `sentry.ContextWithClient(ctx, client)` to the writer.

## Per-Request Writers

Create a writer using each request's Go context to associate its errors and breadcrumbs with the correct scope and trace:

```go
writer, err := sentryzerolog.New(ctx, sentryzerolog.Options{WithBreadcrumbs: true})
if err != nil {
	return err
}
logger := zerolog.New(writer)
logger.Error().Msg("Request failed")
```

A shared `io.Writer` cannot receive a different context on each `Write` call. Avoid sharing a writer bound to one request with another request. Obtain the context from your Sentry middleware and flush the selected client before process shutdown.
