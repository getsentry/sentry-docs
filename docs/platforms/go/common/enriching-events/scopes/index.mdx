A scope holds tags, user data, breadcrumbs, and other metadata for an operation. Captures use the scope and client carried by the `context.Context` you pass to the SDK. HTTP and gRPC server integrations create request scopes automatically.

Replacing hubs from 0.x? See <PlatformLink to="/migration/v0-to-v1/#isolating-scope-data">the scope migration steps</PlatformLink>.

## Isolating an Operation

Use `WithScope` to keep one request or job's metadata separate from other work. It clones the scope on the parent context, or starts an empty scope when the parent has none.

```go
ctx, scope := sentry.WithScope(ctx)
scope.SetTag("job", "checkout")
scope.SetUser(sentry.User{ID: "user-123"})
sentry.CaptureException(ctx, err)
```

Keep using the returned context for this operation. There is no scope stack to push or pop. For goroutines, see <PlatformLink to="/usage/concurrency/">Concurrency</PlatformLink>.

## Enriching a Request

Inside Sentry middleware, get the existing scope from the request context. `ScopeFromContext` returns nil if no scope is attached.

```go
ctx := r.Context()
if scope := sentry.ScopeFromContext(ctx); scope != nil {
	scope.SetTag("page", "checkout")
}
sentry.CaptureException(ctx, err)
```

For Gin, Echo, Fiber, FastHTTP, and Iris, use the integration's `GetContext` helper to obtain the Go context. Set request-specific user data on this scope and clear it with `scope.SetUser(sentry.User{})` when needed.

## Application-Wide Metadata

Set shared metadata on `GlobalScope()`:

```go
sentry.GlobalScope().SetTag("region", "eu-central")
```

The global scope is merged into every event, log, and metric when it is captured, so changes made after a scope was created still apply. Keep request-specific data off the global scope to avoid mixing users or operations.

A context without an attached scope has nowhere to keep state: events captured with it receive the global scope's data, but `AddBreadcrumb` drops the breadcrumb, `LastEventID` returns an empty ID, and `ScopeFromContext` returns `nil`. Create a scope with `WithScope` first.

`NewScope()` creates an empty scope, and `ContextWithScope(ctx, scope)` attaches it. Do not attach a clone of the global scope, because its breadcrumbs and event processors would be applied twice. Use `ContextWithClient(ctx, client)` to select a client without changing the scope.

## Setting Attributes

Scope attributes enrich logs and metrics. Use tags or contexts for error-event metadata.

```go
import "github.com/getsentry/sentry-go/attribute"

ctx, scope := sentry.WithScope(ctx)
scope.SetAttributes(
	attribute.String("user.role", "admin"),
	attribute.Int("retry.count", 3),
)
sentry.NewLogger(ctx).Info().Emit("Retrying checkout")
scope.RemoveAttribute("user.role")
```

A transaction is set on its scope, so captures, logs, and metrics sent with that scope are linked to it. To associate them with a child span, pass `span.Context()` instead.
