Fork a scope for each goroutine that adds operation-specific metadata. This prevents one goroutine's tags, users, or breadcrumbs from appearing on another goroutine's events.

```go
var wg sync.WaitGroup
for _, job := range jobs {
	jobCtx, scope := sentry.WithScope(ctx)
	scope.SetTag("job", job.ID)
	wg.Add(1)
	go func() {
		defer wg.Done()
		defer sentry.Recover(jobCtx, nil)
		if err := process(jobCtx, job); err != nil {
			sentry.CaptureException(jobCtx, err)
		}
	}()
}
wg.Wait()
sentry.ClientFromContext(ctx).Flush(2 * time.Second)
```

`WithScope` clones the parent's scope, or starts an empty scope when the parent has none. The global scope is merged in when telemetry is captured. The returned context retains the parent's client and active span.

Scopes are safe for concurrent access, but sharing a scope also shares its metadata. Use separate scopes for unrelated operations and keep request-specific data off `GlobalScope()`.

Pass `span.Context()` to work associated with that span. For background work launched from Fiber or FastHTTP, obtain the Go context with the integration's `GetContext` during the request; do not retain the reused framework context. Use `context.WithoutCancel` only if the work should outlive request cancellation, and give that work its own timeout.

For scope inheritance and client selection, see <PlatformLink to="/enriching-events/scopes/">Scopes and Contexts</PlatformLink>.
