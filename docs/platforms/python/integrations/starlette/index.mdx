## Prerequisites

You need:

- A Sentry [account](https://sentry.io/signup/) and [project](/product/projects/)
- Your application up and running
- Starlette:
  - `0.16+` (SDK &lt;3.0)
  - `0.20+` (SDK 3.0+)
- Python: `3.7+`

This guide requires `sentry-sdk` version 2.70.0 or later. If you already have the SDK installed, upgrade it with `pip install --upgrade sentry-sdk`.

## Configure

**Error Monitoring** starts working as soon as you call `sentry_sdk.init()`. **Logs** and **Application Metrics** need no extra configuration when using `sentry_sdk.logger` and `sentry_sdk.metrics`, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing** and **Profiling**.

### Initialize the Sentry SDK

Configuration should happen as **early as possible** in your application's lifecycle.

<Alert>

If you have the `starlette` package in your dependencies, the Sentry Starlette integration will be enabled automatically when you initialize the Sentry SDK.

</Alert>

Import and initialize the SDK in your app's entry point:

The snippet also turns on:

- Collection of user data, such as the user's IP address: via <PlatformLink to="/configuration/options/#data_collection">`data_collection`</PlatformLink>
- Tracing: via <PlatformLink to="/configuration/options/#traces_sample_rate">`traces_sample_rate`</PlatformLink>
- Profiling: via <PlatformLink to="/configuration/options/#profile_session_sample_rate">`profile_session_sample_rate`</PlatformLink> and <PlatformLink to="/configuration/options/#profile_lifecycle">`profile_lifecycle`</PlatformLink>

Don't need a feature? Remove its options from the snippet.

```python
import sentry_sdk

sentry_sdk.init(
    dsn="___PUBLIC_DSN___",

    # Check https://docs.sentry.io/platforms/python/data-management/data-collected/ to configure what data is collected
    data_collection={
        "user_info": True,
    },

    # Enables Tracing.
    # Set to 1.0 to capture 100% of spans for tracing.
    # We recommend reducing this value in production.
    traces_sample_rate=1.0,

    # Enables Profiling.
    # Set to 1.0 to profile 100% of sessions.
    profile_session_sample_rate=1.0,
    # Profiles are collected while a transaction is active.
    profile_lifecycle="trace",
)
```

To further customize your setup, review the [Options section](#options) below.

### Capturing Errors

Sentry automatically captures errors and reports issues for you.
You can also expect the following for your Starlette project:

- By default, all exceptions leading to an Internal Server Error are reported. The HTTP status codes to report on are configurable via the `failed_request_status_codes` [option](#options).
- Request data will be attached to all events: HTTP method, URL, headers, form data, JSON payloads. Sentry excludes raw bodies and multipart file uploads.
- Sentry also excludes personally identifiable information (such as user ids, usernames, cookies, authorization headers, IP addresses) unless you configure which categories to collect with the <PlatformLink to="/configuration/options/#data_collection">`data_collection` option</PlatformLink> or set `send_default_pii` to `True`. `send_default_pii` will be removed in version 3.0 of the SDK.

To learn how to manually report issues, see <PlatformLink to="/usage/">Capturing Errors</PlatformLink>.

## Send Logs

Use `sentry_sdk.logger` to send structured logs at different levels. You can include searchable attributes with each message.

To capture records from Python's standard-library `logging` module or Loguru, configure `capture_sentry_logs=True` on the corresponding integration. See the <PlatformLink to="/integrations/logging/">standard logging</PlatformLink> and <PlatformLink to="/integrations/loguru/">Loguru</PlatformLink> integration guides.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and formatting options.

```python
import sentry_sdk

sentry_sdk.logger.info("Order processed {order_id}", order_id="order-123")
sentry_sdk.logger.warning("Rate limit reached", attributes={"endpoint": "/api/orders"})
```

## Send Application Metrics <FeatureBadge type="new" />

Use `sentry_sdk.metrics` to send counters, gauges, and distributions from your app. Metrics are enabled by default after you initialize the SDK.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

```python
import sentry_sdk

sentry_sdk.metrics.count("checkout.failed", 1)
sentry_sdk.metrics.gauge("active_connections", 42)
sentry_sdk.metrics.distribution("api_latency", 187, unit="millisecond")
```

## Verify Your Setup

Let's test your setup and confirm that data reaches your Sentry project.

Add this route to your Starlette app, then request `/sentry-debug`:

```python
from starlette.applications import Starlette
from starlette.routing import Route

async def trigger_error(request):
    1 / 0

app = Starlette(routes=[Route("/sentry-debug", trigger_error)])
```

## Options

<Include name="python-stream-mode-integration-option-callout.mdx" />

Add `StarletteIntegration` to your `sentry_sdk.init()` call to set options for `StarletteIntegration` to change its behavior.

```python
from sentry_sdk.integrations.starlette import StarletteIntegration

sentry_sdk.init(
    # ...
    integrations=[
        StarletteIntegration(
            transaction_style="endpoint",
            failed_request_status_codes={403, *range(500, 599)},
            middleware_spans=False,
            http_methods_to_capture=("GET",),
        )
    ],
)
```

You can pass the following keyword arguments to `StarletteIntegration()`:

<SdkOption name='transaction_style' type='string' defaultValue='"url"'>

How to name transactions that show up in Sentry tracing.
The default is `"url"`.

In the code example, the transaction name will be:

- `"/catalog/product/{product_id}"` if you set `transaction_style="url"`.
- `"product_detail"` if you set `transaction_style="endpoint"`

```python
  async def product_detail(request):
      return JSONResponse({...})

  app = Starlette(routes=[
      Route('/catalog/product/{product_id}', product_detail),
  ])
```

</SdkOption>

<SdkOption name='failed_request_status_codes' type='set[int]' defaultValue='{*range(500, 600)}'>

A `set` of integers that will determine which status codes should be reported to Sentry.

The `failed_request_status_codes` option determines whether [`HTTPException`](https://starlette.dev/exceptions/#httpexception) exceptions should be
reported to Sentry. Unhandled exceptions that don't have a `status_code` attribute will always be reported to Sentry.

Examples of valid `failed_request_status_codes`:

- `{500}` will only send events on HTTP 500.
- `{400, *range(500, 600)}` will send events on HTTP 400 as well as the 5xx range.
- `{500, 503}` will send events on HTTP 500 and 503.
- `set()` (the empty set) will not send events for any HTTP status code.

The default is `{*range(500, 600)}`, meaning that all 5xx status codes are reported to Sentry.

</SdkOption>

<SdkOption name='middleware_spans' type='bool' defaultValue='False'>

Create spans and track performance of all middleware layers in your project. Set to `True` to enable.
The default is `False`.

</SdkOption>

<SdkOption name='http_methods_to_capture' type='Tuple[str, ...]' defaultValue='("CONNECT", "DELETE", "GET", "PATCH", "POST", "PUT", "TRACE",)' availableSince='2.15.0'>

A tuple containing all the HTTP methods (as uppercase strings) that should create a transaction in Sentry.
The default is `("CONNECT", "DELETE", "GET", "PATCH", "POST", "PUT", "TRACE",)`.

Note that `OPTIONS` and `HEAD` are excluded by default.

</SdkOption>
