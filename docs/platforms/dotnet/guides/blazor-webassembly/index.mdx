Sentry provides an integration with Blazor WebAssembly through the [Sentry.AspNetCore.Blazor.WebAssembly NuGet package](https://www.nuget.org/packages/Sentry.AspNetCore.Blazor.WebAssembly).

## Install
Add the Sentry dependency to your Blazor WebAssembly application:

```shell {tabTitle:.NET Core CLI}
dotnet add package Sentry.AspNetCore.Blazor.WebAssembly -v {{@inject packages.version('sentry.dotnet.aspnetcore.blazor.webassembly') }}
```

```powershell {tabTitle:Package Manager}
Install-Package Sentry.AspNetCore.Blazor.WebAssembly -Version {{@inject packages.version('sentry.dotnet.aspnetcore.blazor.webassembly') }}
```

This package extends [Sentry.Extensions.Logging](/platforms/dotnet/guides/extensions-logging/). This means that in addition to the related Blazor WebAssembly features, you'll also get access to the `ILogger<T>` integration and other features available in the main [Sentry](/platforms/dotnet/) SDK through this package.

## Configure

**Error Monitoring** starts working as soon as you initialize the SDK. **Logs** sent through `Microsoft.Extensions.Logging` need `EnableLogs = true`, and **Application Metrics** need no extra configuration. You'll learn how to send them in [Send Logs](#send-logs) and [Send Application Metrics](#send-application-metrics-).

This guide also enables **Tracing**.


Sentry integration with Blazor WebAssembly is done by calling `.UseSentry()` and specifying the options, for example:



The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#TracesSampleRate">`TracesSampleRate`</PlatformLink>
- Logs: via <PlatformLink to="/logs/#enablelogs">`EnableLogs`</PlatformLink>

Don't need a feature? Remove its options from the snippet.

```csharp
using Microsoft.AspNetCore.Components.WebAssembly.Hosting;
using Microsoft.Extensions.Logging;

var builder = WebAssemblyHostBuilder.CreateDefault(args);
builder.UseSentry(options =>
{
    options.Dsn = "___PUBLIC_DSN___";
    options.EnableLogs = true;
    // When configuring for the first time, to see what the SDK is doing:
    options.Debug = true;
    // Adds request URL and headers, IP and name for users, etc.
    options.SendDefaultPii = true;
    // Enables Tracing.
    // Set to 1.0 to capture 100% of spans for tracing.
    // We recommend reducing this value in production.
    options.TracesSampleRate = 0.1;
});

await builder.Build().RunAsync();
```

`UseSentry` also registers the logging integration. Don't call `builder.Logging.AddSentry` separately.

## Send Logs

Use `Microsoft.Extensions.Logging` to send structured logs from your application. Set `EnableLogs = true` in your Sentry initialization.

See [Microsoft.Extensions.Logging](/platforms/dotnet/guides/extensions-logging/) for setup details.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and formatting options.

```csharp
using Microsoft.Extensions.Logging;

public sealed class OrderService
{
    private readonly ILogger<OrderService> _logger;

    public OrderService(ILogger<OrderService> logger) => _logger = logger;

    public void Process()
    {
        _logger.LogInformation("Order processed {OrderId}", "order-123");
        _logger.LogWarning("Rate limit reached for {Endpoint}", "/api/orders");
    }
}
```

## Send Application Metrics <FeatureBadge type="new" />

Metrics are enabled by default in Sentry .NET SDK 6.1.0 and later. Use `SentrySdk.Metrics` to send counters, gauges, and distributions from your app.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

```csharp
SentrySdk.Metrics.EmitCounter("button_click", 5,
    new Dictionary<string, object> { ["browser"] = "Firefox" });
SentrySdk.Metrics.EmitGauge("page_load", 15.0, MeasurementUnit.Duration.Millisecond,
    new Dictionary<string, object> { ["page"] = "/home" });
SentrySdk.Metrics.EmitDistribution("api_latency", 187, MeasurementUnit.Duration.Millisecond,
    new Dictionary<string, object> { ["endpoint"] = "/api/orders" });
```
