Version 9 removes the deprecated Hub compatibility APIs, the global Logs and Metrics enable options, and the `enablePerformanceV2` option. Migrate remaining Hub references to Scopes, then update your telemetry configuration.

## Removed Hub APIs

Version 8 deprecated Hub and introduced Scopes. Version 9 removes the Hub compatibility layer:

- `IHub` has been removed. Use `IScopes` instead.
- `HubAdapter.getInstance()` has been removed. Use `ScopesAdapter.getInstance()` instead.
- `HubScopesWrapper` has been removed. Use the wrapped `IScopes` instance directly.
- `NoOpHub.getInstance()` has been removed. Use `NoOpScopes.getInstance()` instead.
- `Sentry.getCurrentHub()` and `Sentry.setCurrentHub(...)` have been removed. Use `Sentry.getCurrentScopes()` and `Sentry.setCurrentScopes(...)` instead.
- `IHub.clone()` and `IScopes.clone()` have been removed. Use `forkedScopes(...)` or `forkedCurrentScope(...)` when you need an independent Scopes instance. For temporary scope changes, use `withScope()` or `withIsolationScope()`.

### Remove `popScope()` Calls

`Sentry.popScope()` and `IScopes.popScope()` have been removed. Use `Sentry.withScope()` or `Sentry.withIsolationScope()` for temporary scope changes instead. Both methods restore the previous scopes after the callback finishes.

### Scopes Model

The Scopes model introduced in version 8 is the supported context model in version 9:

- The global scope is attached to all events created by the SDK. To modify it before `SentryAndroid.init()`, call methods directly on `Sentry.getGlobalScope()`, such as `Sentry.getGlobalScope().setTag(...)`.
- The isolation scope attaches data to events within an isolated lifecycle.
- The current scope contains data for the active operation. Child scopes inherit its data, but parent scopes don't receive changes made in a child scope.

On Android, APIs such as `Sentry.configureScope()` and `Sentry.setTag()` use the current scope by default.

## Removed `traceSampling` Option

Version 9 removes `SentryOptions.setTraceSampling(...)`, `SentryOptions.isTraceSampling()`, and the `io.sentry.traces.trace-sampling` manifest option. This option was a global switch for trace propagation, not a transaction sampling setting.

To stop attaching `sentry-trace` and `baggage` headers to outgoing HTTP requests, set `tracePropagationTargets` to an empty list. If your app uses manifest-only auto-initialization, replace the removed manifest option with an empty propagation target value:

```xml {filename:AndroidManifest.xml}
<meta-data
    android:name="io.sentry.traces.trace-propagation-targets"
    android:value="" />
```

For Apollo v2, set `attachTracingHeaders` to `false` on `SentryApolloInterceptor` because the interceptor doesn't have a request URL to match against propagation targets.

There is no replacement for suppressing the trace context in Sentry envelopes. Transactions with baggage now always include that context.

## Manual Logs and Metrics

Calls to `Sentry.logger()` and `Sentry.metrics()` no longer require a global enable option. Remove calls to:

- `options.getLogs().setEnabled(...)`
- `options.getMetrics().setEnabled(...)`

The `beforeSendLog` and `beforeSendMetric` callbacks remain available for filtering or modifying telemetry.

## Android Manifest Options

Remove these manifest entries:

```xml {filename:AndroidManifest.xml}
<meta-data android:name="io.sentry.logs.enabled" android:value="true" />
<meta-data android:name="io.sentry.metrics.enabled" android:value="false" />
```

To capture logs from an automatic Android integration, use its integration-specific option instead:

```xml {filename:AndroidManifest.xml}
<meta-data android:name="io.sentry.timber.log-capture.enabled" android:value="true" />
<meta-data android:name="io.sentry.logcat.log-capture.enabled" android:value="true" />
```

The equivalent `SentryAndroidOptions` properties are `timberLogCaptureEnabled` and `logcatLogCaptureEnabled`. Both default to `false`.

## Timber Constructor Changes

Manual `SentryTimberIntegration` and `SentryTimberTree` construction now requires a `logsEnabled` argument. Pass `false` to keep automatic Sentry Logs capture disabled:

```kotlin {tabTitle:Kotlin}
SentryTimberIntegration(logsEnabled = false)
```

```java {tabTitle:Java}
new SentryTimberIntegration(false);
```

Pass `true` only when Timber records should also be sent as Sentry Logs.

## Removed Performance V2 Option

Version 8 enabled Performance V2 by default. Version 9 always enables it and removes the option to turn it off:

- `SentryAndroidOptions.setEnablePerformanceV2(...)` and `SentryAndroidOptions.isEnablePerformanceV2()` have been removed. Delete these calls.
- The `io.sentry.performance-v2.enable` manifest entry has been removed. Delete it from your manifest:

```xml {filename:AndroidManifest.xml}
<meta-data android:name="io.sentry.performance-v2.enable" android:value="false" />
```

If you previously turned Performance V2 off, the SDK now:

- Measures app starts from process start on Android 7.0 (API 24) and later. Below API 24, it falls back to the SDK initialization time.
- Measures slow and frozen frames for each span instead of only for Activity transactions.

### Removed `ActivityFramesTracker`

`ActivityFramesTracker` has been removed, and the `ActivityLifecycleIntegration` constructor no longer takes it. If you create `ActivityLifecycleIntegration` manually, pass only the `Application` and `BuildInfoProvider` arguments.

## Removed Android `LoadClass` Shim

Version 9 removes the deprecated `io.sentry.android.core.LoadClass` class. Replace imports of this class with `io.sentry.util.LoadClass`. The replacement provides the same constructor and methods.

## Removed `IEnvelopeCache.store()` Methods

Version 9 removes the deprecated `IEnvelopeCache.store(...)` overloads. If you provide a custom envelope cache:

- Rename `store(SentryEnvelope, Hint)` to `storeEnvelope(SentryEnvelope, Hint)`.
- Return `true` only when the envelope was stored, and `false` when it wasn't.
- Replace calls to `store(envelope)` with `storeEnvelope(envelope, new Hint())`.
