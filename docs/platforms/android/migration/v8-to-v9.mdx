Version 9 removes the deprecated Hub compatibility APIs and the global Logs and Metrics enable options. Migrate remaining Hub references to Scopes, then update your telemetry configuration.

## Removed Hub APIs

The Hub compatibility layer was deprecated in version 8 and is removed in version 9. Replace any remaining Hub references before upgrading:

| Removed API                                  | Replacement                                                                   |
| -------------------------------------------- | ----------------------------------------------------------------------------- |
| `IHub`                                       | `IScopes`                                                                     |
| `HubAdapter.getInstance()`                   | `ScopesAdapter.getInstance()`                                                 |
| `HubScopesWrapper`                           | Use the wrapped `IScopes` instance directly                                   |
| `NoOpHub.getInstance()`                      | `NoOpScopes.getInstance()`                                                    |
| `Sentry.getCurrentHub()`                     | `Sentry.getCurrentScopes()`                                                   |
| `Sentry.setCurrentHub(...)`                  | `Sentry.setCurrentScopes(...)`                                                |
| `IHub.clone()` and `IScopes.clone()`         | `forkedScopes(...)` or `forkedCurrentScope(...)`                              |
| `Sentry.popScope()` and `IScopes.popScope()` | Close the lifecycle token returned by `pushScope()` or `pushIsolationScope()` |

Use try-with-resources or a `finally` block to close lifecycle tokens. This restores the previous scopes without relying on a separate `popScope()` call.

## Manual Logs and Metrics

Calls to `Sentry.logger()` and `Sentry.metrics()` no longer require a global enable option. Remove calls to:

- `options.getLogs().setEnabled(...)`
- `options.getMetrics().setEnabled(...)`

The `beforeSendLog` and `beforeSendMetric` callbacks remain available for filtering or modifying telemetry.

## Android Manifest Options

Remove these manifest entries:

```xml {filename:AndroidManifest.xml}
<meta-data android:name="io.sentry.logs.enabled" android:value="true" />
<meta-data android:name="io.sentry.metrics.enabled" android:value="false" />
```

To capture logs from an automatic Android integration, use its integration-specific option instead:

```xml {filename:AndroidManifest.xml}
<meta-data android:name="io.sentry.timber.log-capture.enabled" android:value="true" />
<meta-data android:name="io.sentry.logcat.log-capture.enabled" android:value="true" />
```

The equivalent `SentryAndroidOptions` properties are `timberLogCaptureEnabled` and `logcatLogCaptureEnabled`. Both default to `false`.

## Timber Constructor Changes

Manual `SentryTimberIntegration` and `SentryTimberTree` construction now requires a `logsEnabled` argument. Pass `false` to keep automatic Sentry Logs capture disabled:

```kotlin {tabTitle:Kotlin}
SentryTimberIntegration(logsEnabled = false)
```

```java {tabTitle:Java}
new SentryTimberIntegration(false);
```

Pass `true` only when Timber records should also be sent as Sentry Logs.
