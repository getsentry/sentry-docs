## Prerequisites

You need:

- A Sentry [account](https://sentry.io/signup/) and [project](/product/projects/)
- Your application up and running
- Android 5.0 (API level 21) or higher
  - Session Replay requires at least Android 8.0 (API level 26)

## Install

We recommend installing the SDK through our [Sentry Wizard](https://github.com/getsentry/sentry-wizard) by running one of the following commands inside your project directory:

<PlatformContent includePath="getting-started-install" />

This will patch your project and configure the SDK. You only need to patch the project once, then you can add the patched files to your version control system.

Prefer to set things up yourself? Check out the <PlatformLink to="/manual-setup/">Manual Setup guide</PlatformLink>.

<Expandable title="The following tasks will be performed by the Sentry Wizard">

The wizard will prompt you to log in to Sentry. It'll then automatically do the following steps for you:

- Update your app's `build.gradle` file with the Sentry Gradle plugin and configure it
- Update your `AndroidManifest.xml` with your DSN, tracing, user-interaction tracing, screenshots, view hierarchies, and default PII collection
- Ask whether to enable automatic Logs collection
- Create `sentry.properties` with an auth token to upload proguard mappings (this file is automatically added to `.gitignore`)
- Add an example error to your app's Main Activity to verify your Sentry setup

</Expandable>

The wizard does not enable Profiling or Session Replay. Follow [Additional Configuration](#additional-configuration) to add them and adjust the generated configuration, including <PlatformLink to="/data-management/data-collected/">data collection</PlatformLink>.

## Additional Configuration

**Error Monitoring** starts working as soon as you initialize the SDK. You can also send **Logs** and **Application Metrics** after initialization, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-). The configuration below also enables **Tracing**, **Profiling**, and **Session Replay**.

<Include name="quick-start-features-expandable" />

<Alert>
Use SDK version **8.58.0 or later** for the full configuration below.
</Alert>

The SDK initializes automatically using your application's `AndroidManifest.xml`. If you ran the wizard, update the existing Sentry entries and add the missing options from the snippet below. Keep a single `io.sentry.dsn` entry.

The snippet also turns on:

- Data Collection: via <PlatformLink to="/configuration/options/#dataCollection">`data-collection`</PlatformLink>
- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>
- Profiling: via <PlatformLink to="/configuration/options/#profileSessionSampleRate">`profileSessionSampleRate`</PlatformLink> and <PlatformLink to="/configuration/options/#profileLifecycle">`profileLifecycle`</PlatformLink>
- Session Replay: via `sessionSampleRate` and `onErrorSampleRate` in the <PlatformLink to="/session-replay/configuration/#general-configuration">Session Replay configuration</PlatformLink>
- Logs: via <PlatformLink to="/logs/">`logs.enabled`</PlatformLink>

Don't need a feature? Remove its options from your app's manifest. The `trace` profiling lifecycle requires tracing: if you disable tracing, also remove the profiling options or <PlatformLink to="/profiling/#enabling-manual-lifecycle-ui-profiling">configure manual profiling</PlatformLink>.

```xml {filename:AndroidManifest.xml}
<application>
  <!-- Required: set your sentry.io project identifier (DSN) -->
  <meta-data android:name="io.sentry.dsn" android:value="___PUBLIC_DSN___" />
  <!-- Use Data Collection defaults but don't collect automatic user information. -->
  <meta-data android:name="io.sentry.data-collection.user-info" android:value="false" />

  <!-- Enables Tracing. -->
  <!-- Set to 1.0 to capture 100% of transactions. -->
  <!-- We recommend reducing this value in production. -->
  <meta-data android:name="io.sentry.traces.sample-rate" android:value="1.0" />

  <!-- Enables Profiling while sampled traces are active. -->
  <!-- Sampling is evaluated once per session. Reduce this value in production. -->
  <meta-data android:name="io.sentry.traces.profiling.session-sample-rate" android:value="1.0" />
  <meta-data android:name="io.sentry.traces.profiling.lifecycle" android:value="trace" />

  <!-- Captures replays for 10% of sessions and 100% of sessions with errors. -->
  <meta-data android:name="io.sentry.session-replay.on-error-sample-rate" android:value="1.0" />
  <meta-data android:name="io.sentry.session-replay.session-sample-rate" android:value="0.1" />

  <!-- Enables automatic Logs collection through integrations. -->
  <meta-data android:name="io.sentry.logs.enabled" android:value="true" />
</application>
```


<Alert level="info" title="A note on Profiling">

Starting with SDK version 8.51.0, profiling on Android 15 (API level 35) and higher uses the Android <Link to="https://developer.android.com/reference/android/os/ProfilingManager">ProfilingManager</Link> to capture <Link to="https://perfetto.dev/">Perfetto</Link> traces. On older devices, the SDK automatically falls back to the <PlatformLink to="/profiling/legacy/">legacy profiler</PlatformLink>.

</Alert>

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

Trigger and capture a test error in your application:

```java {tabTitle: Java}
import io.sentry.Sentry;

Sentry.captureException(new Exception("This is a test."));
```

```kotlin {tabTitle: Kotlin}
import io.sentry.Sentry

Sentry.captureException(Exception("This is a test."))
```
