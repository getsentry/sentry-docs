On this page, we get you up and running with Sentry's PowerShell SDK. The PowerShell Sentry SDK is tested to work with:

- PowerShell 7.4+ on Windows, macOS, and Linux
- Windows PowerShell 5.1

The PowerShell SDK is based on the Sentry .NET SDK. You can refer to the [.NET SDK docs](/platforms/dotnet/configuration/) for the documentation of advanced features you don't find here.

## Install

Install the PowerShell SDK from the PowerShell Gallery using [PowerShellGet](https://learn.microsoft.com/en-us/powershell/gallery/powershellget/install-powershellget):

```powershell
Install-Module -Name Sentry -Scope CurrentUser -Repository PSGallery -Force
```

## Configure

**Error Monitoring** starts working as soon as you call `Start-Sentry`. **Logs** are available in PowerShell SDK 0.5.0 and later and need no extra configuration; you'll learn how to send them in [Send Logs](#send-logs).
This guide also enables **Tracing** and **Release Health**.

Call `Start-Sentry` as early as possible in your script, before the code you want to monitor runs.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#TracesSampleRate">`TracesSampleRate`</PlatformLink>. The PowerShell SDK doesn't create transactions automatically, so start them with `Start-SentryTransaction`, as shown in <PlatformLink to="/tracing/instrumentation/custom-instrumentation/">Custom Instrumentation</PlatformLink>.
- Release Health: via <PlatformLink to="/configuration/releases/#sessions">`AutoSessionTracking`</PlatformLink>, which starts a session when your script starts and ends it when your script exits.
- Collection of potentially personally identifiable information (PII), such as the machine name: via <PlatformLink to="/configuration/options/#SendDefaultPii">`SendDefaultPii`</PlatformLink>. Review the data your script sends before enabling this in production.

Don't need a feature? Remove its options from the snippet.

```powershell
# You may need to import the module if you've just installed it.
Import-Module Sentry

Start-Sentry {
    # You can set it in the SENTRY_DSN environment variable, or you can set it in code here.
    $_.Dsn = '___PUBLIC_DSN___'

    # Enables Tracing.
    # Set to 1.0 to capture 100% of transactions for tracing.
    # We recommend reducing this value in production.
    $_.TracesSampleRate = 1.0

    # Enables Release Health by sending session data.
    $_.AutoSessionTracking = $true

    # If you'd like to include data that potentially includes PII, such as Machine Name
    $_.SendDefaultPii = $true
}
```

## Send Logs

Use the `Write-SentryLog` cmdlet to send logs at different levels, such as `Info`, `Warning`, or `Error`. Logs require PowerShell SDK 0.5.0 or later. If you don't pass `-Level`, the log is sent at the `Info` level.

Use placeholders like `{0}` with `-Parameters` to send templated messages, and `-Attributes` to attach any key-value pairs you want to search or filter by later.

`Write-SentryLog` is built on the .NET SDK's logs API. See the [.NET Logs documentation](/platforms/dotnet/logs/) for more configuration options.

```powershell
Write-SentryLog 'User example action completed'

Write-SentryLog -Level Warning `
    -Message 'Slow operation detected: {0} took {1} ms' `
    -Parameters 'data_fetch', 3500

Write-SentryLog -Level Error `
    -Message 'Validation failed' `
    -Attributes @{ form_field = 'email'; reason = 'Invalid email' }
```

## Verify Your Setup

This snippet includes an intentional error, so you can test that everything is working as soon as you set it up:

```powershell
try
{
    throw 'Test error'
}
catch
{
    $_ | Out-Sentry
}
```

Learn more about manually capturing an error or message in our <PlatformLink to="/usage/">Usage documentation</PlatformLink>.

### View Captured Data in Sentry

To view and resolve the recorded error, log into [sentry.io](https://sentry.io) and select your project. Select **Issues** in the sidebar to find the new issue.
