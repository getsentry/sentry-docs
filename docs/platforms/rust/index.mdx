## Install

To add Sentry to your Rust project, add a new dependency to your `Cargo.toml`:

```toml {filename:Cargo.toml}
[dependencies]
sentry = "{{@inject packages.version('sentry.rust') }}"
```

## Configure

Call `sentry::init()` as early as possible in your `main` function. It starts a Sentry client with a default set of integrations, such as panic reporting, and binds it to the current Hub.

`sentry::init()` returns a guard that flushes events that haven't been sent yet when it's dropped. The flush has a two-second deadline, so application shutdown may be slightly delayed. Keep the guard alive for as long as your app runs, or the SDK won't be able to send events.

```rust {filename:main.rs}
fn main() {
    let _guard = sentry::init(
        sentry::ClientOptions::new()
            .dsn("___PUBLIC_DSN___")
            .maybe_release(sentry::release_name!())
            // Enable tracing and capture all traces and spans.
            // Reduce this sample rate in production, or remove it to disable tracing.
            .traces_sample_rate(1.0)
            // Capture user IPs and potentially sensitive headers when using HTTP server integrations.
            // Review the data your app sends before enabling this option in production.
            .send_default_pii(true),
    );

    // implementation of main
}
```

**Important:** Remember your DSN. The DSN (Data Source Name) tells the SDK where to send events. If you forget it, you can find it by going to: Settings -> Projects -> [Client Keys (DSN)](https://sentry.io/orgredirect/organizations/:orgslug/settings/projects/:projectId/keys/) in sentry.io.

### Async Main Function

In a multithreaded application, spawned threads should inherit the Hub from the main thread. For that to happen, initialize the Sentry client before starting an async runtime or spawning threads. This means you'll have to avoid macros such as `#[tokio::main]` or `#[actix_web::main]`, because they start the runtime first. So rather than doing this:

```rust {filename:main.rs}
// WRONG
#[tokio::main]
async fn main() {
    let _guard = sentry::init(
        sentry::ClientOptions::new()
            .dsn("___PUBLIC_DSN___")
            .maybe_release(sentry::release_name!()),
    );

    // implementation of main
}
```

Do this instead:

```rust {filename:main.rs}
// RIGHT
fn main() {
    let _guard = sentry::init(
        sentry::ClientOptions::new()
            .dsn("___PUBLIC_DSN___")
            .maybe_release(sentry::release_name!()),
    );

    tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()
        .unwrap()
        .block_on(async {
            // implementation of main
        });
}
```

### Integrations

_Integrations_ extend the functionality of the SDK for some common frameworks and libraries. A list of integrations and their feature flags can be found [in the integration API docs](https://docs.rs/sentry/0/sentry/integrations/index.html).

<Alert>

If you keep debug information files in the produced binary, rather than strip them down or split them,
do not add the `debug_images` integration and the corresponding `debug-images` feature flag,
as it will collide with the built-in debug file processing.

Conflicts could lead to UI warning messages in Sentry, as it can be interpreted as a problem with debug files and processing your error. See this [comment](https://github.com/getsentry/sentry-rust/issues/574#issuecomment-1534316787) and connected issue for more information.

</Alert>

## Verify Your Setup

The quickest way to verify Sentry in your Rust application is to cause a panic after initializing the SDK:

```rust {filename:main.rs}
// Sentry will capture this
panic!("Everything is on fire!");
```

To view and resolve the recorded panic, log into [sentry.io](https://sentry.io) and select your project. Select **Issues** in the sidebar to find the new issue.
