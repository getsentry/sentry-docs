The Sentry SDK offers an integration for tokio's [tracing](https://github.com/tokio-rs/tracing) ecosystem that supports:

- Reporting `tracing` events to Sentry as events, breadcrumbs, or logs.
- Reporting `tracing` spans to Sentry.
- Reporting errors and panics with the correct trace correlation.

## Install

Add Sentry and the `tracing` dependencies to your `Cargo.toml`. The `tracing` feature enables the Sentry tracing integration.

```toml {filename:Cargo.toml}
[dependencies]
tracing = "0.1.41"
tracing-subscriber = "0.3.19"
sentry = { version = "{{@inject packages.version('sentry.rust') }}", features = ["tracing"] }
tokio = { version = "1.45.0", features = ["full"] }
```

## Configure

**Error Monitoring** starts working as soon as you call `sentry::init()`. **Logs** are supported in Rust SDK 0.42.0 and later and enabled by default. **Application Metrics** are available in Rust SDK 0.48.0 and later; both are covered in [Send Logs](#send-logs) and [Send Application Metrics](#send-application-metrics-).
This guide also enables **Tracing**.

Initialize Sentry before starting the async runtime, then register the Sentry tracing layer with `tracing_subscriber`.

<Alert level="warning">

Macros like `#[tokio::main]` and `#[actix_web::main]` are not supported. Initialize the Sentry client before starting the async runtime, as shown below.

</Alert>

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#traces_sample_rate">`traces_sample_rate`</PlatformLink>.

Don't need a feature? Remove its options from the snippet.

```rust {filename:main.rs}
use tracing_subscriber::prelude::*;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let _guard = sentry::init(
        sentry::ClientOptions::new()
            .dsn("___PUBLIC_DSN___")
            .maybe_release(sentry::release_name!())
            // Enables Tracing.
            // Set to 1.0 to capture 100% of spans for tracing.
            // We recommend reducing this value in production.
            .traces_sample_rate(1.0),
    );

    tracing_subscriber::registry()
        .with(tracing_subscriber::fmt::layer())
        .with(sentry::integrations::tracing::layer())
        .init();

    tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()?
        .block_on(async {
            // Bind async work to the current Sentry Hub.
            fail().bind_hub(sentry::Hub::current()).await;
        });

    Ok(())
}

#[tracing::instrument]
async fn fail() {
    tracing::debug!("Doing work");
    let _span = tracing::info_span!("Child span").entered();
    tracing::error!("Everything is on fire!");
}
```

By default, error-level events from `tracing` are captured as Sentry events, and events at or above info level are added to the current scope as breadcrumbs. Events at or above info level are also captured as Sentry logs unless logs are disabled when initializing the SDK.

### Customize Tracing Event Capture

You can customize how `tracing` events are sent by setting an `event_filter` on the Sentry layer. This example shows the default filter used with the `tracing` feature:

```rust
use sentry::integrations::tracing::EventFilter;

let sentry_layer =
    sentry::integrations::tracing::layer().event_filter(|metadata| match *metadata.level() {
        // Capture error and warn events as both logs and events.
        tracing::Level::ERROR => EventFilter::Event | EventFilter::Log,
        // Ignore trace events because they're too verbose.
        tracing::Level::TRACE => EventFilter::Ignore,
        // Capture other events as both breadcrumbs and logs.
        _ => EventFilter::Breadcrumb | EventFilter::Log,
    });
```

## Send Logs

The Sentry tracing layer sends `tracing` events at info level and above as logs by default. Use the <PlatformLink to="/logs/#tracing-integration">`tracing` integration</PlatformLink> to add log fields as searchable attributes. The Rust SDK also supports the <PlatformLink to="/logs/#log-integration">`log` integration</PlatformLink> with the `log` feature enabled on `sentry`.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and configuration options.

```rust
tracing::info!(order_id = "order-123", "Order processed");
tracing::error!(reason = "invalid email", "Validation failed");
```

## Send Application Metrics <FeatureBadge type="new" />

Use `sentry::metrics` to send counters, gauges, and distributions. Metrics require Rust SDK 0.48.0 or later and are enabled by default in the `sentry` crate.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

```rust
use sentry::metrics;

metrics::counter("checkout.failed", 1).capture();
metrics::gauge("active_connections", 42).capture();
metrics::distribution("api_latency", 187.0).capture();
```

## Verify Your Setup

Send an error-level event to confirm that Sentry captures an event:

```rust
tracing::error!("Sentry test event");
```

### View Captured Data in Sentry

To view the recorded event, log into [sentry.io](https://sentry.io) and select your project. Select **Issues** in the sidebar to find it. You can view traces in **Explore** > **Traces**, and captured logs in **Explore** > **Logs**.
