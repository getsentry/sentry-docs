The Sentry SDK offers middleware for the [Actix Web](https://actix.rs/) framework that supports:

- Capturing server errors returned by Actix Web services.
- Starting a [transaction](/concepts/key-terms/tracing/) for each request-response cycle.

## Install

Add Sentry with the `actix` integration to your `Cargo.toml`:

```toml {filename:Cargo.toml}
[dependencies]
actix-web = "4.11.0"
sentry = { version = "{{@inject packages.version('sentry.rust') }}", features = ["actix"] }
```

## Configure

**Error Monitoring** starts working as soon as you call `sentry::init()`. **Logs** are supported in Rust SDK 0.42.0 and later and enabled by default. **Application Metrics** are available in Rust SDK 0.48.0 and later; both are covered in [Send Logs](#send-logs) and [Send Application Metrics](#send-application-metrics-).
This guide also enables **Tracing**.

Initialize Sentry before starting the async runtime, then add the Sentry middleware to your Actix Web app. The example route returns an error so you can verify the setup in the next step.

<Alert level="warning">

Macros like `#[tokio::main]` and `#[actix_web::main]` are not supported. Initialize the Sentry client before starting the async runtime, as shown below.

</Alert>

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#traces_sample_rate">`traces_sample_rate`</PlatformLink> and the middleware's `start_transaction(true)`.
- User IP and HTTP header collection: via <PlatformLink to="/configuration/options/#send_default_pii">`send_default_pii`</PlatformLink>. Review the data your app sends before enabling this in production.
- HTTP request body collection: via <PlatformLink to="/configuration/options/#max_request_body_size">`max_request_body_size`</PlatformLink>.

Don't need a feature? Remove its options from the snippet.

```rust {filename:main.rs}
use std::io;

use actix_web::{get, App, Error, HttpRequest, HttpServer};

#[get("/")]
async fn failing(_req: HttpRequest) -> Result<String, Error> {
    Err(io::Error::new(io::ErrorKind::Other, "An error happens here").into())
}

fn main() -> io::Result<()> {
    let _guard = sentry::init(
        sentry::ClientOptions::new()
            .dsn("___PUBLIC_DSN___")
            .maybe_release(sentry::release_name!())
            // Enables Tracing.
            // Set to 1.0 to capture 100% of spans for tracing.
            // We recommend reducing this value in production.
            .traces_sample_rate(1.0)
            // Capture user IPs and potentially sensitive headers when using HTTP server integrations.
            // See https://docs.sentry.io/platforms/rust/data-management/data-collected/ for more info.
            .send_default_pii(true)
            // Capture all HTTP request bodies, regardless of size.
            .max_request_body_size(sentry::MaxRequestBodySize::Always),
    );

    actix_web::rt::System::new().block_on(async {
        HttpServer::new(|| {
            App::new()
                .wrap(
                    sentry::integrations::actix::Sentry::builder()
                        .capture_server_errors(true) // Capture server errors
                        .start_transaction(true) // Start a transaction (Sentry root span) for each request
                        .finish(),
                )
                .service(failing)
        })
        .bind("127.0.0.1:3001")?
        .run()
        .await
    })?;

    Ok(())
}
```

### Instrument Actix Web

The Sentry middleware provides correct request and trace association for any captured errors or panics, so it should be the first to process the request. That means it should be the last in your chain of `wrap` calls.

`capture_server_errors(true)` reports server errors returned by your services to Sentry, and `start_transaction(true)` starts a transaction for each request.

## Send Logs

Use Sentry's `logger_*` macros to send logs at different levels. Logs are supported in Rust SDK 0.42.0 and later and enabled by default unless you compile the SDK without default features. In that case, enable the `logs` feature on `sentry`. For logging through the `tracing` or `log` crates, see the <PlatformLink to="/logs/#tracing-integration">`tracing` integration</PlatformLink> and <PlatformLink to="/logs/#log-integration">`log` integration</PlatformLink> guides.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and configuration options.

```rust
use sentry::logger_info;

logger_info!("Order processed");
```

## Send Application Metrics <FeatureBadge type="new" />

Use `sentry::metrics` to send counters, gauges, and distributions. Metrics require Rust SDK 0.48.0 or later and are enabled by default in the `sentry` crate.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

```rust
use sentry::metrics;

metrics::counter("checkout.failed", 1).capture();
metrics::gauge("active_connections", 42).capture();
```

## Verify Your Setup

Send a request to the application. The route returns an error, and Sentry captures it.

```bash
curl http://localhost:3001/
```

### View Captured Data in Sentry

To view and resolve the recorded error, log into [sentry.io](https://sentry.io) and select your project. Select **Issues** in the sidebar to find the new issue.
