The Sentry SDK offers middleware for the [axum](https://github.com/tokio-rs/axum) framework that supports:

- Reporting errors and panics with the correct request correlation.
- Starting a [transaction](/concepts/key-terms/tracing/) for each request-response cycle.

The integration also supports any crate based on [tower](https://github.com/tower-rs/tower), not just `axum`.

## Install

Add Sentry with the `axum` integration to your `Cargo.toml`:

```toml {filename:Cargo.toml}
[dependencies]
axum = "0.8.4"
tower = "0.5.2"
tokio = { version = "1.45.0", features = ["full"] }
sentry = { version = "{{@inject packages.version('sentry.rust') }}", features = ["tower-axum-matched-path"] }
```

## Configure

**Error Monitoring** starts working as soon as you call `sentry::init()`. **Logs** are supported in Rust SDK 0.42.0 and later and enabled by default. **Application Metrics** are available in Rust SDK 0.48.0 and later; both are covered in [Send Logs](#send-logs) and [Send Application Metrics](#send-application-metrics-).
This guide also enables **Tracing**.

Initialize Sentry before starting the async runtime, then add the Sentry middleware to your Axum app. The example route panics so you can verify the setup in the next step.

<Alert level="warning">

Macros like `#[tokio::main]` are not supported. Initialize the Sentry client before starting the async runtime, as shown below.

</Alert>

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#traces_sample_rate">`traces_sample_rate`</PlatformLink> and `SentryHttpLayer::enable_transaction()`.
- User IP and HTTP header collection: via <PlatformLink to="/configuration/options/#send_default_pii">`send_default_pii`</PlatformLink>. Review the data your app sends before enabling this in production.

Don't need a feature? Remove its options from the snippet.

```rust {filename:main.rs}
use axum::{body::Body, http::Request, routing::get, Router};
use sentry::integrations::tower::{NewSentryLayer, SentryHttpLayer};
use std::io;
use tower::ServiceBuilder;

async fn failing() {
    panic!("Everything is on fire!");
}

fn main() -> io::Result<()> {
    let _guard = sentry::init(
        sentry::ClientOptions::new()
            .dsn("___PUBLIC_DSN___")
            .maybe_release(sentry::release_name!())
            // Enables Tracing.
            // Set to 1.0 to capture 100% of spans for tracing.
            // We recommend reducing this value in production.
            .traces_sample_rate(1.0)
            // Capture user IPs and potentially sensitive headers for HTTP server integrations.
            .send_default_pii(true),
    );

    let app = Router::new().route("/", get(failing)).layer(
        ServiceBuilder::new()
            .layer(NewSentryLayer::<Request<Body>>::new_from_top())
            .layer(SentryHttpLayer::new().enable_transaction()),
    );

    tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()?
        .block_on(async {
            let listener = tokio::net::TcpListener::bind("127.0.0.1:3001")
                .await
                .unwrap();
            axum::serve(listener, app.into_make_service())
                .await
                .unwrap();
        });

    Ok(())
}
```

### Instrument Axum

`NewSentryLayer` binds a Hub to each request so Sentry can associate errors with the correct request. `SentryHttpLayer::enable_transaction()` starts a transaction for each request.

If you bind the layers directly to the `Router`, apply them in the opposite order to avoid a memory leak.

## Send Logs

Use Sentry's `logger_*` macros to send logs at different levels. Logs are supported in Rust SDK 0.42.0 and later and enabled by default unless you compile the SDK without default features. For logging through the `tracing` or `log` crates, see the <PlatformLink to="/logs/#tracing-integration">`tracing` integration</PlatformLink> and <PlatformLink to="/logs/#log-integration">`log` integration</PlatformLink> guides.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and configuration options.

```rust
use sentry::logger_info;

logger_info!("Order processed");
```

## Send Application Metrics <FeatureBadge type="new" />

Use `sentry::metrics` to send counters, gauges, and distributions. Metrics require Rust SDK 0.48.0 or later and are enabled by default in the `sentry` crate.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

```rust
use sentry::metrics;

metrics::counter("checkout.failed", 1).capture();
metrics::gauge("active_connections", 42).capture();
```

## Verify Your Setup

Send a request to the application. The route panics, and Sentry captures the error.

```bash
curl http://localhost:3001/
```

### View Captured Data in Sentry

To view and resolve the recorded panic, log into [sentry.io](https://sentry.io) and select your project. Select **Issues** in the sidebar to find the new issue.
