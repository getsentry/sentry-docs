The Sentry SDK offers middleware for the [axum](https://github.com/tokio-rs/axum) framework that supports:

- Reporting errors and panics with the correct request correlation.
- Starting a [transaction](/concepts/key-terms/tracing/) for each request-response cycle.

The integration also supports any crate based on [tower](https://github.com/tower-rs/tower), not just `axum`.

## Install

Add Sentry with the `axum` integration to your `Cargo.toml`:

```toml {filename:Cargo.toml}
[dependencies]
axum = "0.8.4"
tower = "0.5.2"
tokio = { version = "1.45.0", features = ["full"] }
sentry = { version = "{{@inject packages.version('sentry.rust') }}", features = ["tower-axum-matched-path"] }
```

## Configure

Initialize the Sentry client, then add the Sentry middleware to your axum app. The example route panics so you can verify the setup in the next step.

<Alert level="warning">

Macros like `#[tokio::main]` are not supported. Initialize the Sentry client before starting the async runtime, as shown below.

</Alert>

```rust {filename:main.rs}
use axum::{body::Body, http::Request, routing::get, Router};
use sentry::integrations::tower::{NewSentryLayer, SentryHttpLayer};
use std::io;
use tower::ServiceBuilder;

async fn failing() {
    panic!("Everything is on fire!");
}

fn main() -> io::Result<()> {
    let _guard = sentry::init(
        sentry::ClientOptions::new()
            .dsn("___PUBLIC_DSN___")
            .maybe_release(sentry::release_name!())
            // Enable tracing and capture all traces and spans.
            // Reduce this sample rate in production, or remove it to disable tracing.
            .traces_sample_rate(1.0)
            // Capture user IPs and potentially sensitive headers when using HTTP server integrations.
            // Review the data your app sends before enabling this option in production.
            .send_default_pii(true),
    );

    let app = Router::new().route("/", get(failing)).layer(
        ServiceBuilder::new()
            // Bind a new Hub per request to associate errors with the correct request.
            .layer(NewSentryLayer::<Request<Body>>::new_from_top())
            // Start a transaction (Sentry root span) for each request.
            // If binding layers directly to the Router, reverse their order to avoid a memory leak.
            .layer(SentryHttpLayer::new().enable_transaction()),
    );

    tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()?
        .block_on(async {
            let listener = tokio::net::TcpListener::bind("127.0.0.1:3001")
                .await
                .unwrap();
            axum::serve(listener, app.into_make_service())
                .await
                .unwrap();
        });

    Ok(())
}
```

## Verify Your Setup

Run the example above, then send a request to its failing route. The route panics, and Sentry captures the error.

```bash
curl http://localhost:3001/
```

To view and resolve the recorded panic, log into [sentry.io](https://sentry.io) and select your project. Select **Issues** in the sidebar to find the new issue.
