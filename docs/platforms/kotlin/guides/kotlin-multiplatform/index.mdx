## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`, including native crash reporting. **ANR detection** (Android), **App Hang detection** (iOS, macOS, and tvOS), and **Release Health** (Android and Apple) are on by default. **Logs** are supported in Kotlin Multiplatform SDK `0.24.0` and later, and you'll learn how to send them in step [#3](#send-logs).
This guide also enables **Session Replay**, which is available on Android and iOS only.

You can also collect **User Feedback** from your own UI with the `Sentry.captureUserFeedback()` API. Learn more in <PlatformLink to="/user-feedback/">Set Up User Feedback</PlatformLink>.

### Initialize the SDK

Create a shared initializer in your `commonMain` source set. Configuration should happen as early as possible in your application's lifecycle.

The snippet also turns on:

- User IP and HTTP header collection: via <PlatformLink to="/configuration/options/#sendDefaultPii">`sendDefaultPii`</PlatformLink>. Review the data your app sends before enabling this in production.
- Logs: via <PlatformLink to="/logs/">`logs.enabled`</PlatformLink>
- Session Replay: via <PlatformLink to="/session-replay/#sampling">`sessionReplay.sessionSampleRate` and `sessionReplay.onErrorSampleRate`</PlatformLink>. Session Replay requires Kotlin Multiplatform SDK `0.12.0` or later and Android 8 (API level 26) or newer, and isn't supported for Compose Multiplatform UI.

Don't need a feature? Remove its options from the snippet.

```kotlin {filename:commonMain/SentrySetup.kt}
import io.sentry.kotlin.multiplatform.Sentry

fun initializeSentry() {
  Sentry.init { options ->
    options.dsn = "___PUBLIC_DSN___"
    // Adds request headers and IP for users, for more info visit:
    // https://docs.sentry.io/platforms/kotlin/guides/kotlin-multiplatform/data-management/data-collected/
    options.sendDefaultPii = true

    // Enables Logs
    options.logs.enabled = true

    // Enables Session Replay on Android and iOS.
    // Capture replays for 10% of all sessions,
    // plus for 100% of sessions with an error.
    options.sessionReplay.sessionSampleRate = 0.1
    options.sessionReplay.onErrorSampleRate = 1.0
  }
}
```

### Call the Initializer on Each Platform

Call `initializeSentry()` at an early lifecycle stage of each app, so the SDK is set up before your code uses it. To initialize with native SDK options instead, see <PlatformLink to="/initialization-strategies/">Initialization Options</PlatformLink>.

```kotlin {filename:MainActivity.kt}{tabTitle: androidApp} {mdExpandTabs}
import your.kmp.app.initializeSentry

class YourApplication : Application() {
  override fun onCreate() {
    super.onCreate()
      initializeSentry()
   }
}
```

```swift {tabTitle: iosApp}
import shared

func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey : Any]? = nil
) -> Bool {
    SentrySetupKt.initializeSentry()
    return true
}

// OR if you're using SwiftUI:

@main
struct SwiftUIApp: App {
    init() {
        SentrySetupKt.initializeSentry()
    }
}
```

## Send Logs

Use `Sentry.logger` to send logs at different levels, such as `info`, `warn`, or `error`. You can pass any attributes you want and search or filter by them later. Logs require Kotlin Multiplatform SDK `0.24.0` or later and the `logs.enabled` option from the snippet above.

If you initialize the SDK with native platform options, enable logs through the native SDK's configuration instead. Learn more in <PlatformLink to="/logs/#using-native-platform-options">Using Native Platform Options</PlatformLink>.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and the syntax for formatting messages.

```kotlin
import io.sentry.kotlin.multiplatform.Sentry

Sentry.logger.info("Order created") { this["orderId"] = "order_456" }
Sentry.logger.warn("Rate limit approaching") { this["current"] = 95; this["max"] = 100 }
Sentry.logger.error("Payment failed") { this["reason"] = "card_declined" }
```

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

Add the following function to your shared code and call it from your app. It captures an intentional error:

```kotlin
import io.sentry.kotlin.multiplatform.Sentry

fun captureError() {
  try {
    throw Exception("This is a test.")
  } catch (e: Exception) {
    Sentry.captureException(e)
  }
}
```

### View Captured Data in Sentry

To view and resolve the recorded error, log into [sentry.io](https://sentry.io) and select your project. Clicking on the error's title will open a page where you can see detailed information and mark it as resolved.
