## Install

### Install the SDK

Use the Bun package manager to add the Sentry SDK to your application:

```bash {tabTitle:Bun}
bun add @sentry/bun
```

## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**.

<Include name="quick-start-features-expandable" />

### Initialize the Sentry SDK

Sentry should be initialized as early in your app as possible.
Create a file named `instrument.js` in the root directory of your project and add the code snippet shown below.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

```javascript {filename: instrument.js}
import * as Sentry from "@sentry/bun";

// Ensure to call this before importing any other modules!
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,
});
```

### Apply Instrumentation to Your App

Preload your instrumentation file with the [`--preload`](https://bun.com/docs/runtime#param-preload) flag. This is what guarantees that `Sentry.init()` runs before any other module is loaded.

```bash {tabTitle:From source}
bun --preload ./instrument.js app.js
```

```bash {tabTitle:Built output}
bun --preload ./instrument.js dist/app.js
```

On Bun `1.4.6` or later, with SDK version `11.15.0` or later, `Sentry.init()` also instruments your dependencies as they load, so `bun run` records spans from database drivers, AI SDKs, and web frameworks like Express, Koa and Hapi without a build step. Packages that load before `Sentry.init()` runs aren't instrumented, which is another reason to preload the file.

If you call `Sentry.init()` inside your app instead of preloading it, preload `@sentry/bun/import` so the static imports of your entry file are instrumented too:

```bash
bun --preload @sentry/bun/import app.js
```

### Build With the Sentry Plugin (Optional)

Build with the Sentry plugin if you bundle your app with `Bun.build()`, or if you run a Bun version earlier than `1.4.6`, where Sentry can't instrument packages at runtime. The plugin rewrites your dependencies as `Bun.build()` bundles them, so they also record spans.

Add `sentryBunPlugin` from `@sentry/bun/plugin` to your `Bun.build()` call, then run the output with `--preload` as shown above. Errors, the spans you create yourself, and `Bun.serve`, `node:http` and `fetch` spans work either way.

```typescript {filename:build.ts}
import { sentryBunPlugin } from "@sentry/bun/plugin";

await Bun.build({
  entrypoints: ["./app.ts"],
  outdir: "./dist",
  target: "bun",
  plugins: [sentryBunPlugin()],
});
```
