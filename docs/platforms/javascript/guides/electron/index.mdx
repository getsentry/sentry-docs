## Install

### Install the Sentry SDK

<SplitLayout>
<SplitSection>
<SplitSectionText>

Run the command for your preferred package manager to add the Sentry SDK to your application:

</SplitSectionText>
<SplitSectionCode>

```bash {tabTitle:npm}
npm install @sentry/electron --save
```

```bash {tabTitle:yarn}
yarn add @sentry/electron
```

```bash {tabTitle:pnpm}
pnpm add @sentry/electron
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**, **Session Replay**, and **User Feedback**.

<Include name="quick-start-features-expandable" />

You should initialize the SDK in both the `main` process and every `renderer` process you spawn.

### Configure the Main Process

<SplitLayout>
<SplitSection>
<SplitSectionText>

Initialize the SDK in your Electron `main` process as early as possible.

The main and renderer snippets also turn on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>
- Session Replay: via `replayIntegration()`, sampled with <PlatformLink to="/configuration/options/#replaysSessionSampleRate">`replaysSessionSampleRate`</PlatformLink> and <PlatformLink to="/configuration/options/#replaysOnErrorSampleRate">`replaysOnErrorSampleRate`</PlatformLink>
- User Feedback: via <PlatformLink to="/user-feedback/configuration/">`feedbackIntegration()`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

</SplitSectionText>
<SplitSectionCode>

```javascript
import * as Sentry from "@sentry/electron/main";

Sentry.init({
  dsn: "___PUBLIC_DSN___",

  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,
  integrations: [
    // Enables startup tracing in the main process
    Sentry.startupTracingIntegration(),
  ],
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

### Configure the Renderer Process

<SplitLayout>
<SplitSection>
<SplitSectionText>

Initialize the SDK in your Electron renderer processes as early as possible. All renderer events are sent through the main process so passing `dsn`, `release` or `environment` to renderer `init` will have no effect.

</SplitSectionText>
<SplitSectionCode>

```javascript
import * as Sentry from "@sentry/electron/renderer";

Sentry.init({
  integrations: [
    Sentry.browserTracingIntegration(),
    Sentry.replayIntegration(),
    Sentry.feedbackIntegration({
      // Additional integration configuration goes in here
      colorScheme: "system",
    }),
  ],

  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,

  // Capture replays for 10% of all sessions,
  // plus for 100% of sessions with an error
  // Requires Sentry.replayIntegration()
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

### Configure Any Utility Processes

<SplitLayout>
<SplitSection>
<SplitSectionText>

If your app uses utility processes, initialize Sentry in each one.

</SplitSectionText>
<SplitSectionCode>

```javascript
import * as Sentry from "@sentry/electron/utility";

Sentry.init();
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

<Alert title="Capturing errors in the preload context">
<SplitLayout>
<SplitSection>
<SplitSectionText>

If your app uses a preload script and `contextIsolation: true`, Sentry can't automatically capture errors that occur in the preload context. To include those, initialize Sentry in your preload script as well:

</SplitSectionText>
<SplitSectionCode>

```javascript
import * as Sentry from "@sentry/electron/renderer";

Sentry.init(); // don't forget to add your configuration options
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

</Alert>

<Expandable title="Did you change the userData directory?" level="warning">

<SplitLayout>
<SplitSection>
<SplitSectionText>

If you change the `userData` directory used by your app, ensure this change is made before you configure the SDK as this path is used to cache scope and events between application restarts.

</SplitSectionText>
<SplitSectionCode>

```javascript
import { app } from "electron";
import * as Sentry from "@sentry/electron/main";

app.setPath("userData", "~/.config/my-app");
Sentry.init({ dsn: "___PUBLIC_DSN___" });
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

</Expandable>

### Using Framework-Specific SDKs

<SplitLayout>
<SplitSection>
<SplitSectionText>

If you're using a framework in your renderers, you can combine the Electron SDK with the framework SDK:

</SplitSectionText>
<SplitSectionCode>

```javascript
import { init } from "@sentry/electron/renderer";
import { init as reactInit } from "@sentry/react";

init(
  {
    dsn: "___PUBLIC_DSN___",
    integrations: [
      /* integrations */
    ],
    /* Other Electron and React SDK config */
  },
  reactInit
);
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

## Send Logs

<SplitLayout>
<SplitSection>
<SplitSectionText>

Use `Sentry.logger` to send logs at different levels, such as `info`, `warn`, or `error`. You can add searchable attributes to each log.

If you already use `console`, capture those calls as Sentry Logs with <PlatformLink to="/logs/#console-integration">`consoleLoggingIntegration`</PlatformLink>.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and message formatting options.

</SplitSectionText>
<SplitSectionCode>

```javascript
Sentry.logger.info("User example action completed");

Sentry.logger.warn("Slow operation detected", {
  operation: "data_fetch",
  duration: 3500,
});

Sentry.logger.error("Validation failed", {
  form_field: "email",
  reason: "Invalid email",
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>
## Send Application Metrics <FeatureBadge type="new" />

<SplitLayout>
<SplitSection>
<SplitSectionText>

Use `Sentry.metrics` to send counters, gauges, and distributions from your app to Sentry. You can add searchable attributes to each metric.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

</SplitSectionText>
<SplitSectionCode>

```javascript
Sentry.metrics.count("checkout.failed", 1);

Sentry.metrics.gauge("time_since_refresh", 4, { unit: "hour" });

Sentry.metrics.distribution("api_latency", 187, {
  unit: "millisecond",
  attributes: { endpoint: "/api/orders" },
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

</SplitSectionText>
<SplitSectionCode>

```javascript

  throw new Error("Sentry Test Error");
});
```

</SplitSection>
