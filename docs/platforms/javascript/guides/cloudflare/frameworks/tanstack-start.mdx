## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-). This guide also enables **Tracing**, **Session Replay**, and **User Feedback**.

When deploying TanStack Start to Cloudflare Workers, you need to wrap the server entry point with `Sentry.withSentry` from `@sentry/cloudflare`. TanStack Start allows you to create a custom server entry file for this purpose.

### Create a Custom Server Entry

Create a `src/server.ts` file that wraps the TanStack Start handler with Sentry.

Use `wrapFetchWithSentry` from `@sentry/tanstackstart-react` to instrument TanStack Start server functions with tracing.

<Alert level="info">

Due to type differences between TanStack Start and Cloudflare Workers, you'll need to add a `// @ts-expect-error` comment as shown in the example. This is expected and doesn't affect functionality.

</Alert>

The snippet also turns on:
- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>

```typescript {filename:src/server.ts}
import * as Sentry from "@sentry/cloudflare";
import { wrapFetchWithSentry } from "@sentry/tanstackstart-react";
import handler from "@tanstack/react-start/server-entry";

export default Sentry.withSentry(
  () => ({
    dsn: "___PUBLIC_DSN___",
      // Enables Tracing.
    // Set to 1.0 to capture 100% of spans for tracing.
    // We recommend reducing this value in production.
    tracesSampleRate: 1.0,
  }),
  // @ts-expect-error - handler is not typed as a Cloudflare handler
  wrapFetchWithSentry(handler)
);
```

### Configure Client-Side Sentry

Initialize Sentry in your `src/router.tsx` file for client-side error tracking.

The snippet also turns on:
- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink> and [`tanstackRouterBrowserTracingIntegration()`](/platforms/javascript/guides/tanstackstart-react/features/tanstack-router/#usage)
- Session Replay: via `replayIntegration()`, sampled with [`replaysSessionSampleRate`](/platforms/javascript/guides/tanstackstart-react/configuration/options/#replaysSessionSampleRate) and [`replaysOnErrorSampleRate`](/platforms/javascript/guides/tanstackstart-react/configuration/options/#replaysOnErrorSampleRate)
- User Feedback: via [`feedbackIntegration()`](/platforms/javascript/guides/tanstackstart-react/user-feedback/#usage)

Don't need a feature? Remove its integration and options from the snippet.

```tsx {diff} {filename:src/router.tsx}
+import * as Sentry from "@sentry/tanstackstart-react";
 import { createRouter } from '@tanstack/react-router'

export const getRouter = () => {
  const router = createRouter();

+ if (!router.isServer) {
+   Sentry.init({
+     dsn: "___PUBLIC_DSN___",
+
+     integrations: [
+       // Registers the TanStack Start router integration for tracing
+       Sentry.tanstackRouterBrowserTracingIntegration(router),
+       // Registers the Replay integration
+       Sentry.replayIntegration(),
+       // Enables User Feedback
+       Sentry.feedbackIntegration({
+         // Additional SDK configuration goes in here, for example:
+         colorScheme: "system",
+       }),
+     ],
+
+     // Enables Tracing.
+     // Set to 1.0 to capture 100% of spans for tracing.
+     // We recommend reducing this value in production.
+     tracesSampleRate: 1.0,
+
+     // Capture replays for 10% of all sessions,
+     // plus for 100% of sessions with an error
+     // Requires Sentry.replayIntegration()
+     replaysSessionSampleRate: 0.1,
+     replaysOnErrorSampleRate: 1.0,
+   });
+ }

  return router;
}
```

### Capture Server-Side Errors

To capture server-side errors from HTTP requests and server function calls, add Sentry's global middlewares to `createStart()` in your `src/start.ts` file.

The Sentry middleware should be the first middleware in the arrays to ensure all errors are captured.

<Alert level="info">
  SSR rendering exceptions are not captured by the middleware. Use
  `captureException` to manually capture those errors.
</Alert>

```tsx {filename:src/start.ts}
import {
  sentryGlobalFunctionMiddleware,
  sentryGlobalRequestMiddleware,
} from "@sentry/tanstackstart-react";
import { createStart } from "@tanstack/react-start";

export const startInstance = createStart(() => {
  return {
    requestMiddleware: [sentryGlobalRequestMiddleware],
    functionMiddleware: [sentryGlobalFunctionMiddleware],
  };
});
```

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

Add a test button to one of your pages, which will trigger an error that Sentry will capture when you click it:

```tsx
<button
  type="button"
  onClick={() => {
    throw new Error("Sentry Test Error");
  }}
>
  Break the world
</button>
```

Run your app with `wrangler dev` (or through your Vite build with Cloudflare plugin), click the button, and check your Sentry project for the error.
