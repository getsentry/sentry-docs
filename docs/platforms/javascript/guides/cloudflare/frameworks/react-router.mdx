<Alert level="info">

This guide is for React Router apps in [framework mode](https://reactrouter.com/start/modes#framework) that you deploy to Cloudflare Workers with the [Cloudflare Vite plugin](https://developers.cloudflare.com/workers/vite-plugin/). For Node.js deployments, see the [React Router guide](/platforms/javascript/guides/react-router/). For Shopify Oxygen, see [Hydrogen with React Router](/platforms/javascript/guides/cloudflare/frameworks/hydrogen-react-router/).

</Alert>

## Prerequisites

You need:

- A Sentry [account](https://sentry.io/signup/) and [project](/product/projects/)
- A React Router app (version `7.15.0` or above) configured for Cloudflare Workers, for example one created with Cloudflare's [React Router guide](https://developers.cloudflare.com/workers/framework-guides/web-apps/react-router/)

```bash {tabTitle:npm}
npm install @sentry/react-router @sentry/cloudflare
```

```bash {tabTitle:yarn}
yarn add @sentry/react-router @sentry/cloudflare
```

```bash {tabTitle:pnpm}
pnpm add @sentry/react-router @sentry/cloudflare
```

### Client-Side Configuration

Initialize Sentry in `app/entry.client.tsx`. If your app doesn't have this file yet, run `npx react-router reveal` to expose the entry files.

</SplitSectionText>
<SplitSectionCode>

```tsx {filename:app/entry.client.tsx}
import * as Sentry from "@sentry/react-router";

Sentry.init({
  dsn: "___PUBLIC_DSN___",

  integrations: [
    // ___PRODUCT_OPTION_START___ performance
    Sentry.reactRouterTracingIntegration(),
    // ___PRODUCT_OPTION_END___ performance
    // ___PRODUCT_OPTION_START___ session-replay
    Sentry.replayIntegration(),
    // ___PRODUCT_OPTION_END___ session-replay
    // ___PRODUCT_OPTION_START___ user-feedback
    Sentry.feedbackIntegration({
      // Additional SDK configuration goes in here, for example:
      colorScheme: "system",
    }),
    // ___PRODUCT_OPTION_END___ user-feedback
  ],
  // ___PRODUCT_OPTION_START___ performance

  // Set tracesSampleRate to 1.0 to capture 100% of spans for tracing.
  tracesSampleRate: 1.0,

  // Set `tracePropagationTargets` to declare which URL(s) should have trace propagation enabled
  tracePropagationTargets: [/^\//, /^https:\/\/yourserver\.io\/api/],
  // ___PRODUCT_OPTION_END___ performance
  // ___PRODUCT_OPTION_START___ session-replay

  // Capture Replay for 10% of all sessions,
  // plus 100% of sessions with an error
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,
  // ___PRODUCT_OPTION_END___ session-replay
});

// ... rest of your client entry
```

</SplitSectionCode>
</SplitSection>

### Server-Side Configuration

Add the Sentry Cloudflare Vite plugin after the Cloudflare and React Router plugins. It wraps your Worker entry with `withSentry` at build time, so you don't need to change `workers/app.ts`.

</SplitSectionText>
<SplitSectionCode>

```typescript {diff} {filename:vite.config.ts}
+import { sentryCloudflareVitePlugin } from "@sentry/cloudflare/vite";

 export default defineConfig({
   plugins: [
     cloudflare({ viteEnvironment: { name: "ssr" } }),
     reactRouter(),
+    sentryCloudflareVitePlugin(),
   ],
 });
```

</SplitSectionCode>
</SplitSection>

<SplitSection>
<SplitSectionText>

Then, create an `instrument.server.ts` file next to the Worker entry that `main` in your Wrangler configuration points to, for example `workers/instrument.server.ts`.

For more on the plugin and its options, see the <PlatformLink to="/install/vite-plugin/">Vite plugin</PlatformLink> page.

</SplitSectionText>
<SplitSectionCode>

```typescript {filename:workers/instrument.server.ts}
import { defineCloudflareOptions } from "@sentry/cloudflare";

export default defineCloudflareOptions({
  dsn: "___PUBLIC_DSN___",
  // ___PRODUCT_OPTION_START___ performance

  // Set tracesSampleRate to 1.0 to capture 100% of spans for tracing.
  tracesSampleRate: 1.0,
  // ___PRODUCT_OPTION_END___ performance
});
```

</SplitSectionCode>
</SplitSection>

<SplitSection>
<SplitSectionText>

Next, update `app/entry.server.tsx`. Import from `@sentry/react-router/cloudflare`, wrap `handleRequest` with `wrapSentryHandleRequest`, pass the rendered stream through `injectTraceMetaTags` to connect server and client traces, and report errors from `handleError`.

Exporting `instrumentations` uses React Router's [instrumentation API](https://reactrouter.com/how-to/instrumentation) to automatically create spans for all loaders, actions, middleware, and request handlers, named after their route.

</SplitSectionText>
<SplitSectionCode>

```tsx {diff} {filename:app/entry.server.tsx}
+import { captureException } from "@sentry/cloudflare";
+import * as Sentry from "@sentry/react-router/cloudflare";
+import type { HandleErrorFunction } from "react-router";
 // ... your existing imports

-export default async function handleRequest(
+async function handleRequest(
   // ... your existing parameters
 ) {
   // ... your existing rendering logic

-  return new Response(body, {
+  return new Response(Sentry.injectTraceMetaTags(body), {
     headers: responseHeaders,
     status: responseStatusCode,
   });
 }

+export default Sentry.wrapSentryHandleRequest(handleRequest);
+
+export const handleError: HandleErrorFunction = (error, { request }) => {
+  // React Router also calls handleError for aborted requests, skip those
+  if (!request.signal.aborted) {
+    captureException(error, {
+      mechanism: { type: "react-router", handled: false },
+    });
+  }
+};
+
+// Automatically instruments all server loaders, actions, middleware,
+// and request handlers.
+export const instrumentations = [Sentry.createSentryServerInstrumentation()];
```

</SplitSectionCode>
</SplitSection>

## Verify Your Setup

Build and deploy your app to Cloudflare Workers, or run it locally with `wrangler dev`. Then throw a test error, for example from a loader or a button's click handler, and check your Sentry project. With tracing enabled, request spans are named after your React Router routes.

### View Captured Data in Sentry

Now, head over to your project on [Sentry.io](https://sentry.io/) to view the collected data (it takes a couple of moments for the data to appear).
