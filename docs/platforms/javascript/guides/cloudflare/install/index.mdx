## How To Decide Which Installation Method To Use

How you set the SDK up depends on how your Worker is built, not on which features you want. All methods give you the same errors, traces, and options.

### I build my Worker with Vite

Follow the <PlatformLink to="/">quick start</PlatformLink>, which sets Sentry up this way. This is what we recommend: the <PlatformLink to="/install/vite-plugin/">Vite plugin</PlatformLink> wraps your Worker entry at build time, so you don't write the wrapper yourself, and it instruments bundled dependencies such as database clients, which is the only way to trace them in the Workers runtime. See the <PlatformLink to="/install/vite-plugin/">Vite Plugin</PlatformLink> page for its options and what it instruments.

### I deploy with `wrangler` directly

Follow the <PlatformLink to="/install/wrangler/">Wrangler setup</PlatformLink> and wrap your entry with `Sentry.withSentry()` yourself. You keep errors and request traces, but you lose the build-time instrumentation of bundled dependencies, so spans from those packages won't appear.

### I'm deploying a Cloudflare Pages application

Follow <PlatformLink to="/features/pages/">Cloudflare Pages</PlatformLink>, which uses the `sentryPagesPlugin` middleware instead of a wrapper. Cloudflare recommends [moving to Workers with static assets](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/) for new projects.
