<Alert title="Using @sentry/hono?">

Starting with version `11.2.0`, the Sentry SDK for your runtime instruments Hono, so you don't need `@sentry/hono` anymore. **Update to `11.2.0` or above** and [migrate to the SDK for your runtime](#migrate-from-sentryhono).

</Alert>

[Hono](https://hono.dev/) doesn't need its own Sentry SDK. Set up Sentry for the runtime your app runs on, and `honoIntegration` instruments Hono automatically:

- Names each request after its route, for example `GET /users/:id`
- Captures errors from your routes and middleware
- Creates spans for incoming requests and each middleware when tracing is enabled

This needs Sentry JavaScript SDK version `11.2.0` or above, and Hono `4.4.9` or above.

## Customize Error Capturing

By default, the SDK skips errors with a 3xx or 4xx status code, since they're usually expected redirects or client errors. To change this, pass a `shouldHandleError` callback to `honoIntegration()`. It receives the thrown error. Return `true` to capture it or `false` to skip it:

```javascript {tabTitle:Node.js} {filename:instrument.mjs}
import * as Sentry from "@sentry/node";

Sentry.init({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    Sentry.honoIntegration({
      shouldHandleError(error) {
        const status = error?.status;
        // Capture 401/403 in addition to the default 5xx errors
        return (
          status === 401 ||
          status === 403 ||
          typeof status !== "number" ||
          status >= 500
        );
      },
    }),
  ],
});
```

```javascript {tabTitle:Bun} {filename:instrument.js}
import * as Sentry from "@sentry/bun";

Sentry.init({

```

```typescript {tabTitle:Deno} {filename:main.ts}
import * as Sentry from "@sentry/deno";

Sentry.init({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    Sentry.honoIntegration({
      shouldHandleError(error) {
        const status = (error as { status?: number })?.status;
        // Capture 401/403 in addition to the default 5xx errors
        return (
          status === 401 ||
          status === 403 ||
          typeof status !== "number" ||
          status >= 500
        );
      },
    }),
  ],
});
```

```typescript {tabTitle:Cloudflare Workers} {filename:src/instrument.server.ts}
import * as Sentry from "@sentry/cloudflare";

export default Sentry.defineCloudflareOptions((env) => ({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    Sentry.honoIntegration({
      shouldHandleError(error) {
        const status = (error as { status?: number })?.status;
        // Capture 401/403 in addition to the default 5xx errors
        return (
          status === 401 ||
          status === 403 ||
          typeof status !== "number" ||
          status >= 500
        );
      },
    }),
  ],
}));
```

## Instrument Hono Manually

The SDK instruments Hono's code when Hono loads, so Sentry must load before your app. The runtime guides set this up for you. If your setup can't do this, for example a Cloudflare Worker that you deploy with Wrangler and without the Vite plugin, add `honoMiddleware()` as the first middleware of your app:

```typescript {filename:src/index.ts}
import { Hono } from "hono";
import * as Sentry from "@sentry/cloudflare";

const app = new Hono();

app.use(Sentry.honoMiddleware(app));

// Your routes here

export default Sentry.withSentry(
  (env) => ({
    dsn: "___PUBLIC_DSN___",
    tracesSampleRate: 1.0,
  }),
  app
);
```

`honoMiddleware()` accepts the same `shouldHandleError` option as `honoIntegration()`. You can keep it when you add the Vite plugin later, because the SDK handles each request only once.

## Migrate From `@sentry/hono`

If your app uses the `@sentry/hono` package or the `@hono/sentry` community middleware, move to the SDK for your runtime:

1. Remove `@sentry/hono` (or `@hono/sentry` and `toucan-js`) from your dependencies.
2. Remove the `sentry()` middleware from your app.
3. Set up Sentry with the guide for your runtime.
4. Move your `sentry()` options to `Sentry.init()`, or to `instrument.server.ts` on Cloudflare Workers.
5. Move `shouldHandleError` to `honoIntegration()`.
