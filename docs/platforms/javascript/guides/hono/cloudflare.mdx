The `@sentry/hono` SDK works as Hono middleware, so you can drop it into your existing Cloudflare Workers app. For Node.js, Bun, and Deno, see the [Hono quick start](/platforms/javascript/guides/hono/).

## Install

### Install the Sentry SDK

Install `@sentry/hono` together with `@sentry/cloudflare`. The runtime package is a peer dependency that you never import directly, but it must be present and its version must match `@sentry/hono`.

```bash {tabTitle:npm}
npm install @sentry/hono @sentry/cloudflare
```

```bash {tabTitle:yarn}
yarn add @sentry/hono @sentry/cloudflare
```

```bash {tabTitle:pnpm}
pnpm add @sentry/hono @sentry/cloudflare
```

## Configure

**Error Monitoring** starts working as soon as you add the `sentry()` middleware. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**.

### Configure Wrangler

The SDK needs `AsyncLocalStorage`, so set the `nodejs_compat` compatibility flag and a `compatibility_date` of `2024-09-23` or later in your Wrangler configuration:

```jsonc {tabTitle:JSON} {filename:wrangler.jsonc}
{
  // Set this to today's date
  "compatibility_date": "{{@inject new Date().toISOString().slice(0, 10) }}",
  "compatibility_flags": ["nodejs_compat"],
}
```

```toml {tabTitle:Toml} {filename:wrangler.toml}
# Set this to today's date
compatibility_date = "{{@inject new Date().toISOString().slice(0, 10) }}"
compatibility_flags = ["nodejs_compat"]
```

### Add the Sentry Middleware

Add the `sentry()` middleware as early as possible in your Hono app, before any route that you want covered.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

```typescript {filename:index.ts}
import { Hono } from "hono";
import { sentry } from "@sentry/hono/cloudflare";

const app = new Hono();

app.use(
  sentry(app, {
    dsn: "___PUBLIC_DSN___",

    // Enables Tracing.
    // Set to 1.0 to capture 100% of spans for tracing.
    // We recommend reducing this value in production.
    tracesSampleRate: 1.0,
  })
);

// Your routes here

export default app;
```

<Expandable title="Accessing env from Worker Bindings">

To read the DSN from a Worker binding, for example a secret, pass a callback instead of a plain options object. The callback receives the Worker `env`:

```typescript {filename:index.ts}
import { Hono } from "hono";
import { sentry } from "@sentry/hono/cloudflare";

type Bindings = { SENTRY_DSN: string };

const app = new Hono<{ Bindings: Bindings }>();

app.use(sentry(app, (env) => ({ dsn: env.SENTRY_DSN })));

export default app;
```

</Expandable>

### Report Unhandled Exceptions

By default, Sentry captures exceptions from Hono's `onError` handler, excluding errors with 3xx or 4xx status codes. No additional configuration is needed for this.

To control which errors are captured, use the <PlatformLink to="/features/error-handler/">`shouldHandleError`</PlatformLink> option.

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

Add a test route to your Hono app that throws an error, then request `/debug-sentry` to trigger it:

```typescript
app.get("/debug-sentry", () => {
  throw new Error("Sentry Test Error");
});
```

### View Captured Data in Sentry

Now, head over to your project on [Sentry.io](https://sentry.io/) to view the collected data (it takes a couple of moments for the data to appear).
