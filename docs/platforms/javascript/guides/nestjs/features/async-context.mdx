---
title: Isolate Background Job Scopes
description: "Learn how to isolate Sentry scopes in NestJS background jobs to prevent breadcrumb leakage into HTTP request events."
---

Background jobs need their own isolation scopes to prevent breadcrumbs and tags from leaking into unrelated HTTP request events.

## Automatic Isolation

Sentry automatically forks an isolation scope for each invocation of:

- `@Cron()`, `@Interval()`, and `@Timeout()` handlers from `@nestjs/schedule`
- `@OnEvent()` handlers from `@nestjs/event-emitter`
- The `process()` method of `@Processor()` classes from `@nestjs/bullmq`

These handlers do not need a manual `Sentry.withIsolationScope()` wrapper.

## Manual Isolation

For other background tasks, wrap each handler with `Sentry.withIsolationScope()` to give it its own isolated scope.

For example, BullMQ lifecycle event listeners such as `@OnWorkerEvent('completed')` can run outside the isolation scope created for `process()` and need their own wrapper:

```typescript {filename: my.processor.ts}
import * as Sentry from "@sentry/nestjs";
import { OnWorkerEvent, Processor, WorkerHost } from "@nestjs/bullmq";
import { Job } from "bullmq";

@Processor("my-queue")
export class MyProcessor extends WorkerHost {
  async process(job: Job) {
    // Your job processing logic runs in an automatically isolated scope.
  }

  @OnWorkerEvent("completed")
  onCompleted(job: Job) {
    return Sentry.withIsolationScope(() => {
      Sentry.addBreadcrumb({
        message: "Job completed",
        data: { jobId: job.id },
      });
      // Your completion handler logic.
    });
  }
}
```
