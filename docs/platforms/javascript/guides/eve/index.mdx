[Eve](https://eve.dev/) is Vercel's filesystem-first framework for building durable backend AI agents on top of the Vercel AI SDK. This guide sets up the `@sentry/node` SDK inside an Eve app so agent turns, model calls, tool executions, and errors flow into [Sentry Agent Tracing](/product/agents/).

<Alert>

This guide covers the Sentry SDK-based setup, which replaces the earlier OTLP instrumentation. It requires JavaScript SDK version `11.0.0-beta.3` or later.

</Alert>

## Prerequisites

Before you begin, you need:

- A Sentry [account](https://sentry.io/signup/) and [project](/product/projects/). The project's DSN tells the SDK where to send data.
- An Eve application.
- `@sentry/node` version `11.0.0-beta.3` or later. The SDK runs in Node.js only; it doesn't support browser or edge runtimes.

## Configure

Create `agent/instrumentation.ts` and initialize Sentry. Eve auto-discovers `agent/instrumentation.ts` and runs it at server startup, before it loads your agent and the AI SDK:

```typescript {filename:agent/instrumentation.ts}
import * as Sentry from "@sentry/node";
// ___PRODUCT_OPTION_START___ profiling
import { nodeProfilingIntegration } from "@sentry/profiling-node";
// ___PRODUCT_OPTION_END___ profiling

Sentry.init({
  dsn: "___PUBLIC_DSN___",
  // ___PRODUCT_OPTION_START___ profiling

  integrations: [
    // Add our Profiling integration
    nodeProfilingIntegration(),
  ],
  // ___PRODUCT_OPTION_END___ profiling
  // ___PRODUCT_OPTION_START___ performance

  // Set tracesSampleRate to 1.0 to capture 100%
  // of spans for tracing.
  // We recommend adjusting this value in production.
  // Learn more at
  // https://docs.sentry.io/platforms/javascript/guides/node/configuration/options/#tracesSampleRate
  tracesSampleRate: 1.0,
  // ___PRODUCT_OPTION_END___ performance
  // ___PRODUCT_OPTION_START___ profiling

  // Set profileSessionSampleRate to 1.0 to profile every session.
  // Learn more at
  // https://docs.sentry.io/platforms/javascript/configuration/options/#profileSessionSampleRate
  profileSessionSampleRate: 1.0,
  // ___PRODUCT_OPTION_END___ profiling
});
```

Because Eve runs this file before your agent and the AI SDK load, the SDK can instrument everything from the first turn — you don't need the `--import` flag or any extra bootstrapping, and you don't need to initialize `@sentry/node` anywhere else.

<OnboardingOption optionId="performance">

To also capture prompts, model outputs, and tool details on your agent spans — so the Agent Tracing transcript shows the full exchange — add `dataCollection`:

```typescript {filename:agent/instrumentation.ts}
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  tracesSampleRate: 1.0,
  // Record generative AI inputs and outputs on your agent spans
  dataCollection: {},
});
```

Passing `dataCollection: {}` opts generative AI inputs and outputs **on**, along with other permissive defaults (bodies, cookies, user info, and more). Review the data your agent handles and tighten these before production. See the <PlatformLink to="/agent-tracing/#privacy-controls">Agent Tracing privacy controls</PlatformLink> for how to turn inputs and outputs off.

</OnboardingOption>

## Verify

Start Eve and send a prompt that calls a tool. Then open [Agent Tracing](/product/agents/) in Sentry and select the run. The timeline shows the model calls, tool calls, token usage, and latency for that turn, plus any errors your agent threw.

If no data appears, confirm that:

- The `dsn` belongs to the Sentry project you're viewing.
- `tracesSampleRate` is greater than `0`.
- Your app completed at least one agent turn after you added `agent/instrumentation.ts`.

</StepConnector>

## Link Conversations

Each Eve turn is its own durable workflow, so a session's turns land in separate traces. To group them into a single [Conversation](/product/agents/conversations/) in the Agents dashboards, add the `eveConversationHook` in an `agent/hooks/sentry.ts` file:

```typescript {filename:agent/hooks/sentry.ts}
import * as Sentry from "@sentry/node";
import { defineHook } from "eve/hooks";

export default defineHook(Sentry.eveConversationHook());
```

This tags every turn of a session with the durable session id (`ctx.session.id`) as the Sentry conversation id, so all of the session's AI spans share the same `gen_ai.conversation.id` and group into one conversation.

To derive the conversation id yourself — for example, to group a subagent's turns under a root or parent session — pass `getConversationId`:

```typescript {filename:agent/hooks/sentry.ts}
import * as Sentry from "@sentry/node";
import { defineHook } from "eve/hooks";

export default defineHook(
  Sentry.eveConversationHook({
    getConversationId: (context) => context.session.id,
  })
);
```

## Instrument Other Dependencies

The basic setup instruments the AI SDK and HTTP/fetch calls. To also instrument other libraries — such as database clients like `pg` or `mysql` — preload the Sentry ESM loader and keep those packages external so the loader can transform them.

Start Eve with the loader preloaded:

```bash
NODE_OPTIONS='--import=@sentry/node/import' eve start
```

Then list the packages you want instrumented under `externalDependencies` in `agent/agent.ts`:

```typescript {filename:agent/agent.ts}
import { defineAgent } from "eve";

export default defineAgent({
  build: {
    externalDependencies: ["pg", "mysql"],
  },
});
```

If Eve inlines a dependency into the server bundle, the loader can't hook it, so keeping it external leaves it a real module the transform can instrument. The AI SDK doesn't need this — it uses a native diagnostics channel.
