## Install

### Import the Sentry SDK

<SplitLayout>
<SplitSection>
<SplitSectionText>

Import the Sentry Deno SDK directly from the npm registry, before importing any other modules. The first line registers the hook that instruments your database drivers, message queues, AI libraries and web frameworks. It only works as the first import of your entry file:

</SplitSectionText>
<SplitSectionCode>

```javascript {filename: main.ts}
import "___SDK_PACKAGE___/import";
import * as Sentry from "___SDK_PACKAGE___";
// your other imports
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

<SplitLayout>
<SplitSection>
<SplitSectionText>

The hook reads your dependencies from a local `node_modules` directory, not from Deno's global npm cache. Set `nodeModulesDir` in your `deno.json`:

</SplitSectionText>
<SplitSectionCode>

```json {filename: deno.json}
{
  "imports": {
    "@sentry/deno": "npm:@sentry/deno"
  },
  "nodeModulesDir": "auto"
}
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**.

<Include name="quick-start-features-expandable" />

### Initialize the Sentry SDK

<SplitLayout>
<SplitSection>
<SplitSectionText>

Initialize Sentry as early as possible in your app:

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

</SplitSectionText>
<SplitSectionCode>

```javascript {filename: main.ts}
import "___SDK_PACKAGE___/import";
import * as Sentry from "___SDK_PACKAGE___";
// your other imports

Sentry.init({
  dsn: "___PUBLIC_DSN___",
  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

### Grant Permissions

<SplitLayout>
<SplitSection>
<SplitSectionText>

Deno blocks access to the network, the file system and system information until you grant it. Start your app with all four permissions so that the SDK can send complete events. Add the other hosts your app talks to, separated by commas:

</SplitSectionText>
<SplitSectionCode>

```bash
deno run \
  --allow-net=___ORG_INGEST_DOMAIN___ \
  --allow-env \
  --allow-read=. \
  --allow-sys=hostname,osRelease \
  main.ts
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

<Expandable permalink={false} title="What each permission gives you">

| Flag                             | What it gives you                                                                            |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| `--allow-net=<host>`             | Delivery of events to Sentry. If a host is missing, Deno names it in the error.              |
| `--allow-env`                    | The import hook. Without it, your app stops at start with `NotCapable: Requires env access`. |
| `--allow-read=.`                 | Source code in stack traces, and `app:///` paths instead of absolute paths.                  |
| `--allow-sys=hostname,osRelease` | The server name and the operating system version on events.                                  |

If you omit `--allow-read` or `--allow-sys`, the SDK sends events without that data and prints no warning.

</Expandable>

## Send Logs

<SplitLayout>
<SplitSection>
<SplitSectionText>

Use `Sentry.logger` to send logs at different levels, such as `info`, `warn`, or `error`. You can pass attributes to search or filter by later.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for logging methods and message formatting.

</SplitSectionText>
<SplitSectionCode>

```javascript
Sentry.logger.info("User example action completed");

Sentry.logger.warn("Slow operation detected", { operation: "data_fetch", duration: 3500 });

Sentry.logger.error("Validation failed", { form_field: "email", reason: "Invalid email" });
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

## Send Application Metrics <FeatureBadge type="new" />

<SplitLayout>
<SplitSection>
<SplitSectionText>

Use `Sentry.metrics` to send counters, gauges, and distributions from your application to Sentry. You can pass attributes to search or filter by later.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for metric types and configuration options.

</SplitSectionText>
<SplitSectionCode>

```javascript
Sentry.metrics.count("checkout.failed", 1);

Sentry.metrics.gauge("time_since_refresh", 4, { unit: "hour" });

Sentry.metrics.distribution("api_latency", 187, {
  unit: "millisecond",
  attributes: { endpoint: "/api/orders" },
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

```javascript
  throw new Error("Sentry Test Error");
}, 0);
```
