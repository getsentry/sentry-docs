## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**, **Session Replay**, and **User Feedback**.

<Include name="quick-start-features-expandable" />

### Initialize the SDK

<SplitLayout>
<SplitSection>
<SplitSectionText>

Call `Sentry.init()` in `app/app.ts` before defining your `Application` class.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink> plus the instance initializer in the next step
- Session Replay: via `replayIntegration()`, sampled with <PlatformLink to="/configuration/options/#replaysSessionSampleRate">`replaysSessionSampleRate`</PlatformLink> and <PlatformLink to="/configuration/options/#replaysOnErrorSampleRate">`replaysOnErrorSampleRate`</PlatformLink>
- User Feedback: via <PlatformLink to="/user-feedback/configuration/">`feedbackIntegration()`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

</SplitSectionText>
<SplitSectionCode>

```typescript {filename:app/app.ts}
import Application from "@ember/application";
import Resolver from "ember-resolver";
import loadInitializers from "ember-load-initializers";
import config from "./config/environment";

import * as Sentry from "@sentry/ember";

Sentry.init({
  dsn: "___PUBLIC_DSN___",
  integrations: [
    // enables Session Replay
    Sentry.replayIntegration(),
    // enables User Feedback
    Sentry.feedbackIntegration({
      // Additional integration configuration goes in here
      colorScheme: "system",
    }),
  ],

  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,

  // Capture replays for 10% of all sessions,
  // plus for 100% of sessions with an error
  // Requires Sentry.replayIntegration()
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,
});

export default class App extends Application {
  modulePrefix = config.modulePrefix;
  podModulePrefix = config.podModulePrefix;
  Resolver = Resolver;
}

loadInitializers(App, config.modulePrefix);
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

### Enable Performance Instrumentation

<SplitLayout>
<SplitSection>
<SplitSectionText>

To capture page loads, navigation, classic component renders, and runloop timings, create an instance initializer that calls `instrumentAppInstancePerformance()`. The `tracesSampleRate` option in `Sentry.init()` controls how much tracing data Sentry captures.

The SDK skips this instrumentation during FastBoot server rendering. To customize it, see <PlatformLink to="/configuration/ember-options/">Ember Options</PlatformLink>.

</SplitSectionText>
<SplitSectionCode>

```typescript {filename:app/instance-initializers/sentry-performance.ts}
import type ApplicationInstance from "@ember/application/instance";
import { instrumentAppInstancePerformance } from "@sentry/ember";

export function initialize(appInstance: ApplicationInstance): void {
  instrumentAppInstancePerformance(appInstance);
}

export default { initialize };
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

## Send Logs

<SplitLayout>
<SplitSection>
<SplitSectionText>

Use `Sentry.logger` to send logs at different levels, such as `info`, `warn`, or `error`.
You can pass any attributes you want and search or filter by them later.

If you're already logging with `console` or Consola, you can capture those logs with <PlatformLink to="/logs/#console-integration">our console integrations</PlatformLink>.

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and the syntax for formatting messages.

</SplitSectionText>
<SplitSectionCode>

```javascript
Sentry.logger.info("User example action completed");

Sentry.logger.warn("Slow operation detected", {
  operation: "data_fetch",
  duration: 3500,
});

Sentry.logger.error("Validation failed", {
  form_field: "email",
  reason: "Invalid email",
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

## Send Application Metrics <FeatureBadge type="new" />

<SplitLayout>
<SplitSection>
<SplitSectionText>

Use `Sentry.metrics` to send counters, gauges, and distributions from your app to Sentry.
You can pass any attributes you want and search or filter by them later.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

</SplitSectionText>
<SplitSectionCode>

```javascript
Sentry.metrics.count("checkout.failed", 1);

Sentry.metrics.gauge("time_since_refresh", 4, { unit: "hour" });

Sentry.metrics.distribution("api_latency", 187, {
  unit: "millisecond",
  attributes: { endpoint: "/api/orders" },
});
```

</SplitSectionCode>
</SplitSection>
</SplitLayout>

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

<SplitLayout>
<SplitSection>
<SplitSectionText>

Add the following test button to one of your templates, which will trigger an error when you click it:
</SplitSectionText>
<SplitSectionCode>

```handlebars {filename: application.hbs}
{{! rest of your page }}
<button type="button" {{on "click" this.throwTestError}}>
  Test Sentry Error
</button>
```

</SplitSectionCode>
</SplitSection>
<SplitSection>
<SplitSectionText>

Next, add the corresponding action to your controller or component.

</SplitSectionText>
<SplitSectionCode>

```javascript {filename: application.js}
import Controller from "@ember/controller";
import { action } from "@ember/object";

export default class ApplicationController extends Controller {
  @action
  throwTestError() {
    throw new Error("Sentry Test Error");
  }
}
```

</SplitSectionCode>
