This guide sets up Sentry in a Next.js app that you build and run with Bun. At the end, your app sends errors, traces, logs, and session replays to Sentry.

## Prerequisites

You need:

- A Sentry [account](https://sentry.io/signup/) and [project](/product/projects/)
- A Next.js app, version `16.0.0` or above
- [Bun](https://bun.sh/) version `1.4.2` or above

## Install

### Run the Installation Wizard

Run the Sentry wizard to automatically install the SDK and configure Sentry in your Next.js application:

```bash
npx @sentry/wizard@latest -i nextjs
```

The wizard asks whether you want to enable **Tracing** and **Session Replay**, route browser requests through your server to avoid ad blockers, and create an example page. To match the configuration in this guide, answer **Yes** to each.

Prefer to set things up yourself? Check out the [Manual Setup](/platforms/javascript/guides/nextjs/manual-setup/) guide.

### Add the Sentry Bun SDK

<AvailableSince version="11.13.0" />

On Bun, the Next.js SDK uses the integrations of the Sentry Bun SDK, for example to create spans for outgoing `fetch` requests. Add it to your app:

```bash
bun add @sentry/bun
```

Without `@sentry/bun`, your app fails to start on Bun.

## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**, **Session Replay**, and **User Feedback**.

<Include name="quick-start-features-expandable" />

The wizard creates the files below. On Bun, `sentry.server.config.ts` runs in the Bun runtime, and `Sentry.init()` from `@sentry/nextjs` sets up Sentry for Bun. You don't need `Sentry.init()` from `@sentry/bun`.

### Build and Start Your App With Bun

Run `next build` and `next start` with `bun --bun`. Update the scripts in your `package.json`:

```json {filename:package.json}
"scripts": {
  "build": "bun --bun next build",
  "start": "bun --bun next start"
}
```

Use `--bun` for both commands. Without it, Bun runs Next.js with Node.js. If you build your app with Node.js and start it with Bun, Sentry uses its setup for Node.js.

On Bun, you get no spans for packages that Next.js loads from `node_modules` at run time instead of bundling them, for example `pg`. Next.js doesn't bundle the packages in [`serverExternalPackages`](https://nextjs.org/docs/app/api-reference/config/next-config-js/serverExternalPackages) and in its default list of these packages. Errors, request spans, Next.js spans, and spans for outgoing `fetch` requests work.

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

The wizard created an example page that sends a test error from both your frontend and your backend:

1. Build and start your app with Bun:

   ```bash
   bun run build && bun run start
   ```

2. Open [localhost:3000/sentry-example-page](http://localhost:3000/sentry-example-page) in your browser.
3. Click **Throw Sample Error**.

If you skipped the example page, add a test button to one of your pages instead. Clicking it will trigger an error for Sentry to capture.

```tsx {filename:app/page.tsx}
"use client";

export default function Page() {
  return (
    <button
      type="button"
      onClick={() => {
        throw new Error("Sentry Test Error");
      }}
    >
      Test Sentry Error
    </button>
  );
}
```
