This guide sets up Sentry in a Next.js app that you build and run with Deno. At the end, your app sends errors, traces, logs, and session replays to Sentry.

## Prerequisites

You need:

- A Sentry [account](https://sentry.io/signup/) and [project](/product/projects/)
- A Next.js app, version `16.0.0` or above, with its dependencies in a `node_modules` folder
- [Deno](https://deno.com/) version `2.9.0` or above

## Install

### Run the Installation Wizard

Run the Sentry wizard to automatically install the SDK and configure Sentry in your Next.js application:

```bash
npx @sentry/wizard@latest -i nextjs
```

The wizard asks whether you want to enable **Tracing** and **Session Replay**, route browser requests through your server to avoid ad blockers, and create an example page. To match the configuration in this guide, answer **Yes** to each.

Prefer to set things up yourself? Check out the [Manual Setup](/platforms/javascript/guides/nextjs/manual-setup/) guide.

### Add the Sentry Deno SDK

<AvailableSince version="11.13.0" />

On Deno, the Next.js SDK uses the integrations of the Sentry Deno SDK, for example to create spans for outgoing `fetch` requests. Add it to your app:

```bash {tabTitle:npm}
npm install @sentry/deno --save
```

```bash {tabTitle:yarn}
yarn add @sentry/deno
```

```bash {tabTitle:pnpm}
pnpm add @sentry/deno
```

Without `@sentry/deno`, your app fails to start on Deno.

## Configure

**Error Monitoring** starts working as soon as you call `Sentry.init()`. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**, **Session Replay**, and **User Feedback**.

### Build and Start Your App With Deno

Run `next build` and `next start` with Deno, and start your app with the `--conditions=deno` flag. Update the scripts in your `package.json`:

```json {filename:package.json}
"scripts": {
  "build": "deno run -A npm:next build",
  "start": "deno run -A --conditions=deno npm:next start"
}
```

Next.js loads the Sentry SDK with `require`, and Deno uses the Deno version of a package for `require` only with `--conditions=deno`. Without this flag, Sentry uses its setup for Node.js, and outgoing `fetch` requests get no spans. If you build your app with Node.js and start it with Deno, Sentry also uses its setup for Node.js.

`-A` gives Next.js all permissions. It needs to read and write files, open the server port, read environment variables, and start worker threads, and Sentry needs the network to send events.

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

The wizard created an example page that sends a test error from both your frontend and your backend:

1. Build and start your app with Deno:

   ```bash
   deno task build && deno task start
   ```

2. Open [localhost:3000/sentry-example-page](http://localhost:3000/sentry-example-page) in your browser.
3. Click **Throw Sample Error**.

If you skipped the example page, add a test button to one of your pages instead. Clicking it will trigger an error for Sentry to capture.

```tsx {filename:app/page.tsx}
"use client";

export default function Page() {
  return (
    <button
      type="button"
      onClick={() => {
        throw new Error("Sentry Test Error");
      }}
    >
      Test Sentry Error
    </button>
  );
}
```
