_Import name: `Sentry.clickhouseIntegration`_

This integration is enabled by default when <PlatformLink to="/tracing/">tracing</PlatformLink> is enabled. To customize it, see [Modifying Default Integrations](./../#modifying-default-integrations).

The `clickhouseIntegration` adds instrumentation for [`@clickhouse/client`](https://www.npmjs.com/package/@clickhouse/client), the official ClickHouse client for Node.js. It creates a `db` span for each statement the client sends, so slow or failing ClickHouse queries show up in your traces.

```javascript
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  tracesSampleRate: 1.0,
  integrations: [Sentry.clickhouseIntegration()],
});
```

## Supported Operations

The integration traces these `ClickHouseClient` methods:

- `query()`
- `command()`
- `exec()`
- `insert()`

`ping()` and `close()` don't send a statement, so they don't create spans. An `insert()` with an empty `values` array doesn't send a request and doesn't create a span either.

Spans are only created inside an active span, such as a request handler or a span you start with <PlatformLink to="/tracing/instrumentation/">`Sentry.startSpan()`</PlatformLink>.

## Spans

Each span is named after the operation and the table it targets, for example `SELECT events` or `INSERT events`. Span attributes follow Sentry's `db.*` conventions, with `db.system.name` set to `clickhouse`. The spans also record the database, the user, and the server address and port of the client.

Query text is sanitized before it's sent to Sentry:

- String and number literals are replaced with `?`. For example, `SELECT name FROM events WHERE name = 'signup'` is recorded as `SELECT name FROM events WHERE name = ?`.
- Comments are removed.
- Inline data sent with a statement, such as the rows after `INSERT INTO events FORMAT CSV`, is removed.
- ClickHouse query parameters, such as `{id:UInt32}`, are kept as written. Their values, passed in `query_params`, aren't recorded.
- `insert()` spans record the target table, but not the inserted values or a query text.

## Errors

When a call fails, the span gets an error status. The integration doesn't capture the error, because the client still rejects to your code, which can handle it. Errors you don't handle are captured like any other unhandled error.

## Supported Versions

- `@clickhouse/client`: `>=1.1.0 <2`
