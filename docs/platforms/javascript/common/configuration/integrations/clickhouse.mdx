_Import name: `Sentry.clickhouseIntegration`_

This integration is enabled by default when <PlatformLink to="/tracing/">tracing</PlatformLink> is enabled. To customize it, see [Modifying Default Integrations](./../#modifying-default-integrations).

The `clickhouseIntegration` adds instrumentation for the official ClickHouse clients: [`@clickhouse/client`](https://www.npmjs.com/package/@clickhouse/client) for Node.js and [`@clickhouse/client-web`](https://www.npmjs.com/package/@clickhouse/client-web) for web runtimes such as Cloudflare Workers. It creates a `db` span for each statement the client sends, so slow or failing ClickHouse queries show up in your traces.

```javascript
Sentry.init({
  dsn: "___PUBLIC_DSN___",
  tracesSampleRate: 1.0,
  integrations: [Sentry.clickhouseIntegration()],
});
```

<PlatformSection supported={["javascript.nextjs"]}>

Run ClickHouse calls in the Node.js runtime. This automatic instrumentation isn't available in the Edge runtime.

</PlatformSection>

<PlatformSection supported={["javascript.cloudflare"]}>

On Cloudflare Workers, use `@clickhouse/client-web` and build your Worker with the <PlatformLink to="/install/vite-plugin/">Sentry Cloudflare Vite plugin</PlatformLink>. The plugin traces the client automatically, as long as `@clickhouse/client-web` is bundled and not marked as external. If you deploy with `wrangler` directly, Sentry doesn't trace ClickHouse calls.

</PlatformSection>

<PlatformSection supported={["javascript.deno"]}>

On Deno, preload Sentry's import hook so it can instrument the ClickHouse client:

```bash
deno run --allow-net --allow-env --allow-read --allow-sys --allow-write --preload=npm:@sentry/deno/import app.ts
```

</PlatformSection>

<PlatformSection supported={["javascript.bun", "javascript.elysia"]}>

On Bun, automatic instrumentation requires a build with `sentryBunPlugin()` and `@clickhouse/client` included in the bundle:

```typescript {filename:build.ts}
import { sentryBunPlugin } from "@sentry/bun/plugin";

await Bun.build({
  entrypoints: ["./src/index.ts"],
  outdir: "./dist",
  target: "bun",
  plugins: [sentryBunPlugin()],
});
```

</PlatformSection>

## Supported Operations

The integration traces these `ClickHouseClient` methods:

- `query()`
- `command()`
- `exec()`
- `insert()`

`ping()` and `close()` don't send a statement, so they don't create spans. An `insert()` with an empty `values` array doesn't send a request and doesn't create a span either.

The integration only creates spans inside an active span, such as a request handler or a span you start with <PlatformLink to="/tracing/instrumentation/">`Sentry.startSpan()`</PlatformLink>.

## Spans

The integration names each span after the operation and its table, for example `SELECT events`. In the query text, it replaces string and number literals with `?` and removes comments and inline data. It doesn't record `query_params` values or inserted rows.

## Supported Versions

- `@clickhouse/client`: `>=1.1.0 <2`
- `@clickhouse/client-web`: `>=1.1.0 <2`
