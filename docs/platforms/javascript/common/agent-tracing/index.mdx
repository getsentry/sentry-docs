With <Link to="/product/agents/dashboards/">Sentry Agent Tracing</Link>, you can monitor and debug your AI systems with full-stack context. You'll be able to track key insights like token usage, latency, tool usage, and error rates — and group multi-turn chats in <Link to="/product/agents/conversations/">Conversations</Link>. Agent Tracing data is fully connected to your other Sentry data like logs, errors, and traces.

## Getting Started

Use Sentry JavaScript SDK version `11.0.0` or later. Complete the <PlatformLink to="/">SDK setup for your framework</PlatformLink> before making AI calls.

<PlatformSection supported={["javascript.node"]}>

Create an initialization file and load it before your application dependencies:

```javascript {filename:instrument.mjs}
import * as Sentry from "@sentry/node";

Sentry.init({
  dsn: "___PUBLIC_DSN___",
  tracesSampleRate: 1.0,
});
```

Start your application with the initialization file preloaded:

```shell
node --import ./instrument.mjs app.mjs
```

</PlatformSection>

<PlatformSection notSupported={["javascript.node", "javascript.cloudflare", "javascript.eve", "javascript.mastra", "javascript.flue"]}>

Set these options in your existing server-side Sentry configuration:

```javascript
dsn: "___PUBLIC_DSN___",
tracesSampleRate: 1.0,
```

</PlatformSection>

<PlatformSection supported={["javascript.cloudflare"]}>

Use the <PlatformLink to="/install/vite-plugin/">Vite plugin</PlatformLink>, <PlatformLink to="/agent-tracing/workers-ai/">`withSentry`</PlatformLink>, or <PlatformLink to="/agent-tracing/agents-sdk/">Agents SDK wrapper</PlatformLink>. Set `tracesSampleRate: 1.0` in that configuration. See [Compose Cloudflare Instrumentation](#compose-cloudflare-instrumentation) for model-client setup.

</PlatformSection>

<PlatformSection supported={["javascript.eve", "javascript.mastra", "javascript.flue"]}>

Follow the <PlatformLink to="/">framework setup</PlatformLink> to register its instrumentation and enable tracing. A separate `Sentry.init()` call is not a substitute for that setup.

</PlatformSection>

<PlatformSection supported={["javascript.nextjs"]}>

Run Vercel AI calls in the Node.js runtime. Its integration does not instrument Next.js Edge.

</PlatformSection>

The SDK records AI inputs and outputs by default. Use [Privacy Controls](#privacy-controls) to omit content, or review all <PlatformLink to="/configuration/options/#dataCollection">data collection options</PlatformLink>.

## Compose Cloudflare Instrumentation

A Cloudflare AI application can need three independent layers. Inspect the host, every model client it calls, and its conversation IDs instead of stopping after the first integration:

1. **Instrument the host.** Use the <PlatformLink to="/install/vite-plugin/">Vite plugin</PlatformLink>, `withSentry`, or <PlatformLink to="/agent-tracing/agents-sdk/">`instrumentAgentWithSentry`</PlatformLink>. Do not wrap the same Worker or Agent class twice.
2. **Instrument each model client.** Workers AI (`env.AI`) is automatic when the Sentry host wrapper supplies the instrumented `env`. For bundled provider SDKs, use Vite build-time instrumentation or the provider's manual wrapper. Follow the matching integration page for Vercel AI, LangChain, LangGraph, or another library.
3. **Group the conversation.** The Agents SDK can infer a conversation ID. For other chat applications, including Workers AI without the Agents SDK, set one before the model or tool calls. See [Tracking Conversations](#tracking-conversations).

For example, an Agents SDK class that calls `env.AI.run()` needs the Agents SDK host setup and Workers AI model instrumentation. The host wrapper supplies the instrumented binding, so do not add another provider wrapper around the same `env.AI` call.

<Alert>

Flue is the exception to this composition. Its blueprint owns the host and model instrumentation. Do not add another Sentry provider integration to Flue-generated model calls, or token and cost totals will be counted twice.

</Alert>

</PlatformSection>

## Verify

Run your agent and open [Explore > Agents](https://sentry.io/orgredirect/organizations/:orgslug/explore/agents/) in Sentry. Check that its model calls, token usage, and any tool executions appear. For streaming calls, consume the stream so the integration can finish the spans and record the response.

## Tracking Conversations

[Conversations](/product/agents/conversations/) groups multi-turn AI activity into a single replay of messages and tool calls. Use `setConversationId()` so every AI span in a chat session shares the same `gen_ai.conversation.id`.

Some integrations infer a conversation ID automatically. For everything else (including Workers AI), set it yourself at the start of **every request or operation that makes AI calls**, before those calls run. Reuse the same session ID across messages in the chat. The ID is applied to AI-related spans on the current isolation scope (which is typically request-scoped). Pass `null` to unset it.

```javascript
Sentry.setConversationId("conv_abc123");
```

### Identifying Users in Conversations

The [Conversations](/product/agents/conversations/) view includes a **User** column. To populate it, call `setUser` once per request or session, before any AI calls:

```javascript
Sentry.setUser({ id: "user_123" });
```

Any of `id`, `email`, or `username` is sufficient — the Conversations tab displays whichever fields are present. See the <PlatformLink to="/configuration/apis/#setUser">setUser API reference</PlatformLink> for the full list of supported fields.

## Options

### Privacy Controls

To omit automatically collected AI inputs and outputs while keeping model, token, and timing metadata, add this option to your existing Sentry configuration:

```javascript
dataCollection: {
  genAI: { inputs: false, outputs: false },
},
```

Set either value independently to collect only inputs or outputs. Explicit integration `recordInputs` and `recordOutputs` options take precedence over these defaults. Vercel AI also supports per-call recording options; see the integration page for your runtime.

These controls apply to integration-collected content, not values you attach manually to spans. See the <PlatformLink to="/configuration/options/#dataCollection">configuration reference</PlatformLink> for other categories and [Agent Data Privacy](/product/agents/privacy/) for scrubbing AI content.

### Streaming Gen AI Spans

From SDK `10.61.0`, `gen_ai` spans are sent as standalone envelope items (avoids large-payload drops; required for <Link to="/product/agents/conversations/">Conversations</Link>).
