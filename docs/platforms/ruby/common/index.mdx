### Control the Data You Send to Sentry

By default, the SDK does **not** send user identity data (IP address, ID, and similar) or other data like HTTP bodies and URL query parameters.

To opt in and get richer debugging context, turn on individual categories using the `data_collection` option. For the full list of categories and their defaults, <PlatformLink to="/configuration/options/#data_collection">see the `data_collection` options</PlatformLink>.

```ruby
require 'sentry-ruby'

Sentry.init do |config|
  config.dsn = '___PUBLIC_DSN___'

  config.data_collection.user_info = true
  config.data_collection.http_bodies = [:incoming_request, :outgoing_request]
  # other categories
end
```

## Send Logs

Use `Sentry.logger` to send logs at different levels, such as `info`, `warn`, or `error`.
You can pass any attributes you want and search or filter by them later.

<PlatformSection supported={["ruby"]}>

If you're already logging with Ruby's standard library `Logger`, you can capture those logs by enabling the `:logger` patch. See <PlatformLink to="/integrations/logging/">Standard Library Logging</PlatformLink>.

</PlatformSection>

<PlatformSection supported={["ruby.rails"]}>

To also capture Rails framework events, such as ActiveRecord queries and controller actions, set `config.rails.structured_logging.enabled = true`.

</PlatformSection>

See <PlatformLink to="/logs/">Set Up Logs</PlatformLink> for all available logging methods and the syntax for formatting messages.

```ruby
Sentry.logger.info("User example action completed")

Sentry.logger.warn("Slow operation detected", operation: "data_fetch", duration: 3500)

Sentry.logger.error("Validation failed", form_field: "email", reason: "Invalid email")
```

</PlatformSection>

## Send Application Metrics <FeatureBadge type="new" />

Use `Sentry.metrics` to send counters, gauges, and distributions from your app. Add attributes to search and filter metrics later.

See <PlatformLink to="/metrics/">Set Up Metrics</PlatformLink> for all available metric types and configuration options.

```ruby
Sentry.metrics.count("checkout.failed", value: 1)

Sentry.metrics.gauge(
  "queue.depth",
  42,
  attributes: { queue: "payments" }
)

Sentry.metrics.distribution(
  "api_latency",
  187,
  unit: "millisecond",
  attributes: { endpoint: "/api/orders" }
)
```

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

Trigger and capture a test error in your application:

```ruby
begin
  1 / 0
rescue ZeroDivisionError => exception
  Sentry.capture_exception(exception)
end
```
