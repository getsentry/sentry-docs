WebAssembly allows you to compile native code into a platform-independent bytecode format, which, for example, permits you to run native C, C++, or Rust code in a web browser.

**This feature is still developing, so may be rough around the edges.**

Debugging support for WebAssembly is an ongoing effort by the WebAssembly community.
Support for it in Sentry is limited by what's possible in that ecosystem.

## Install

To get crash reports with readable stack traces, your compiler must output [WASM DWARF debug information](https://yurydelendik.github.io/webassembly-dwarf/) alongside the binary code.

Sentry also requires debug information files to contain a `build_id` custom section. Our [wasm-split](https://github.com/getsentry/symbolicator/tree/master/crates/wasm-split) tool adds this section if it's missing and splits off the debug information, so it isn't sent to your users. Download a prebuilt `wasm-split` binary from the [Symbolicator releases](https://github.com/getsentry/symbolicator/releases/), or build it from source with a recent Rust compiler.

## Configure

Sentry supports **Error Monitoring** for WebAssembly: it symbolicates WebAssembly frames in crash reports using the debug information files you upload. There's no Native SDK for WebAssembly, so Tracing, Logs, and Application Metrics aren't available through this guide. In the browser, the JavaScript SDK provides them.

### Add a Build ID and Split Debug Information

Once your compiler has produced a `.wasm` file, use `wasm-split` to add a `build_id` (if missing) and split the file into a debug information file and a final stripped `.wasm` file without debug information:

```shell
wasm-split /path/to/file.wasm -d /path/to/file.debug.wasm --strip
```

This command modifies the `file.wasm` in place to add the `build_id`, then removes all debug information. The debug information is put in a `file.debug.wasm` file.

### Upload Debug Information Files

Upload `file.debug.wasm` to Sentry or make it available on a symbol server, as you would for other platforms. For more information, see [Debug Information Files](/platforms/native/guides/wasm/data-management/debug-files/).

### Report Crashes From the Browser

If you want crash reporting in the browser, use the `@sentry/wasm` package and add its `wasmIntegration` to your `@sentry/browser` configuration. This is [documented in detail](/platforms/javascript/guides/wasm/) in the JavaScript platform docs.

### Send Custom Crash Reports

If you don't run WebAssembly in a browser, but in your own runtime, you'll likely want to send custom crash reports. In that case, follow the general protocol documentation, which also covers how to describe WebAssembly frames: [stack trace interface](https://develop.sentry.dev/sdk/foundations/transport/event-payloads/stacktrace/).

Here is an example event for WebAssembly:

```javascript
{
  "platform": "native",
  "debug_meta": {
    "images": [
      {
        // the URL where the wasm file lives
        "code_file": "http://localhost:8002/demo.wasm",
        // indicates a web assembly module
        "type": "wasm",
        // the contents of the build_id section in hex,
        // truncated to 32 characters with a 0 appended
        "debug_id": "9e5cbc5553b44e8b9c69d18cdd7bfd2e0"
      }
    ]
  },
  "exception": {
    "values": [
      {
        "stacktrace": {
          "frames": [
            // wasm frame
            {
              "function": "wasm_func",
              "abs_path": "http://localhost:8002/demo.wasm",
              // the absolute offset in the wasm file for the instruction
              "instruction_addr": "0x8c",
              // indicates that the instruction_addr is relative to the 1st
              // module in the debug_info images list.
              "addr_mode": "rel:0"
            },
            // javascript frame
            {
              "function": "crash",
              "abs_path": "http://localhost:8002/index.html",
              "lineno": 24,
              "platform": "javascript"
            }
          ]
        },
        "type": "Error"
      }
    ]
  }
}
```

## Verify Your Setup

Trigger an error in a WebAssembly function, either in the browser with `wasmIntegration` enabled or by sending a custom crash report like the example above from your runtime.

### View Captured Data in Sentry

To view the recorded error, log into [sentry.io](https://sentry.io) and select your project. Select **Issues** in the sidebar to find the new issue, then click its title and check that the stack trace shows symbolicated WebAssembly frames.
