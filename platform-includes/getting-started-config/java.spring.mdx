Configuration should happen as early as possible in your application's lifecycle.

The `sentry-spring`, `sentry-spring-jakarta`, and `sentry-spring-7` libraries provide an `@EnableSentry` annotation that registers all required Spring beans. Place it on any class annotated with [@Configuration](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/context/annotation/Configuration.html), including your main [@SpringBootApplication](https://docs.spring.io/spring-boot/docs/current/api/org/springframework/boot/autoconfigure/SpringBootApplication.html) class.


```java {tabTitle:Java (Spring 5)} {mdExpandTabs}
import io.sentry.spring.EnableSentry;
// project/dashboard
@EnableSentry(
  dsn = "___PUBLIC_DSN___"
)
@Configuration
class SentryConfiguration {
}
```

Then configure the remaining options in `sentry.properties`.

The snippet also configures:

- Data Collection: via <PlatformLink to="/data-management/data-collected/">`data-collection`</PlatformLink>
- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`traces-sample-rate`</PlatformLink>
- Profiling: via <PlatformLink to="/configuration/options/#profileSessionSampleRate">`profile-session-sample-rate`</PlatformLink> and <PlatformLink to="/configuration/options/#profileLifecycle">`profile-lifecycle`</PlatformLink>
- Logs: via <PlatformLink to="/logs/">`logs.enabled`</PlatformLink>

Don't need a feature? Remove its configuration. Remove the `sentry-async-profiler` dependency to disable Profiling.

```properties {filename:sentry.properties}
# Use Data Collection defaults but don't collect automatic user information.
data-collection.user-info=false
# Configure other data categories here.

# Enable tracing
traces-sample-rate=1.0

# Enable profiling
profile-session-sample-rate=1.0
profile-lifecycle=TRACE

# Enable logs
logs.enabled=true
```

The DSN can also come from the `sentry.dsn` system property, the `SENTRY_DSN` environment variable, or `sentry.properties`. See the [configuration page](/platforms/java/configuration/) for details on external configuration.

### Capture Handled Exceptions

By default, only unhandled exceptions are sent to Sentry. You can tune this behavior through configuring the `exceptionResolverOrder` property. For example, setting it to `Ordered#HIGHEST_PRECEDENCE` ensures exceptions that have been handled by exception resolvers with higher order are sent to Sentry – including ones handled by `@ExceptionHandler` annotated methods.


```java {tabTitle:Java (Spring 5)} {mdExpandTabs}
import io.sentry.spring.EnableSentry;
import org.springframework.core.Ordered;
// NOTE: Replace the test DSN below with YOUR OWN DSN to see the events from this app in your Sentry
// project/dashboard
@EnableSentry(
  dsn = "___PUBLIC_DSN___",
  exceptionResolverOrder = Ordered.LOWEST_PRECEDENCE
)
class SentryConfiguration {
}
```
