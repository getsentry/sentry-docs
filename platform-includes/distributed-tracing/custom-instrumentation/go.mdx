To connect traces across services, continue incoming tracing headers and attach the selected trace to outgoing requests. Sentry's HTTP middleware and HTTP client integration do this automatically; use these steps for custom instrumentation.

## Extract Incoming Tracing Information

Create a scope for the operation and pass `ContinueFromRequest` to the transaction. For non-HTTP input, use `ContinueFromHeaders(trace, baggage)` instead:

```go
ctx, _ := sentry.WithScope(r.Context())
transaction := sentry.StartTransaction(ctx, "handle request",
	sentry.ContinueFromRequest(r),
)
defer transaction.Finish()
ctx = transaction.Context()
```

If middleware has already started a transaction, use the request context and add child spans instead.

## Inject Tracing Information Into Outgoing Requests

Use the same operation context for outgoing work. `GetTraceparent` returns the `sentry-trace` value; use `GetTraceparentW3C` if the destination expects W3C `traceparent`. These functions and `GetBaggage` return an empty string when the context carries neither a scope nor a span.

```go
req, err := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
if err != nil {
	return err
}
req.Header.Set(sentry.SentryTraceHeader, sentry.GetTraceparent(ctx))
baggage, err := sentry.MergeBaggage(req.Header.Get(sentry.SentryBaggageHeader), sentry.GetBaggage(ctx))
if err == nil {
	req.Header.Set(sentry.SentryBaggageHeader, baggage)
}
```

`MergeBaggage` replaces stale `sentry-*` members while preserving third-party baggage.

## Verify Propagation

Send a request to an instrumented downstream service and check that it receives `sentry-trace` and `baggage` headers. Its SDK can then continue the same trace.
