## Install

### Install the Sentry SDK

Run the command for your preferred package manager to add the Sentry SDK to your application:

```bash {tabTitle:npm}
npm install @sentry/nuxt --save
```

```bash {tabTitle:yarn}
yarn add @sentry/nuxt
```

```bash {tabTitle:pnpm}
pnpm add @sentry/nuxt
```

## Configure

**Error Monitoring** starts working as soon as you configure Sentry. **Logs** and **Application Metrics** need no extra configuration, and you'll learn how to send them in steps [#3](#send-logs) and [#4](#send-application-metrics-).
This guide also enables **Tracing**, **Session Replay**, and **User Feedback**.

<Include name="quick-start-features-expandable-cloudflare-frameworks" />

### Apply Instrumentation to Your App

Add the Sentry Nuxt module to your `nuxt.config.ts` file:

```javascript {filename:nuxt.config.ts}
export default defineNuxtConfig({
  modules: ["@sentry/nuxt/module"],
});
```

### Configure Client-Side Sentry

Add a `sentry.client.config.ts` file to the root of your project (this is probably the same level as the `package.json`). In this file, import and initialize Sentry, specifying any SDK options for the client.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>
- Session Replay: via `replayIntegration()`, sampled with <PlatformLink to="/configuration/options/#replaysSessionSampleRate">`replaysSessionSampleRate`</PlatformLink> and <PlatformLink to="/configuration/options/#replaysOnErrorSampleRate">`replaysOnErrorSampleRate`</PlatformLink>
- User Feedback: via <PlatformLink to="/user-feedback/configuration/">`feedbackIntegration()`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

```javascript {filename:sentry.client.config.ts}
import * as Sentry from "@sentry/nuxt";

Sentry.init({
  // If set up, you can use the Nuxt runtime config here
  // dsn: useRuntimeConfig().public.sentry.dsn
  // modify depending on your custom runtime config
  dsn: "___PUBLIC_DSN___",
  integrations: [
    // enables Session Replay
    Sentry.replayIntegration(),
    // enables User Feedback
    Sentry.feedbackIntegration({
      // Additional integration configuration goes in here
      colorScheme: "system",
    }),
  ],

  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,

  // Capture replays for 10% of all sessions,
  // plus for 100% of sessions with an error
  // Requires Sentry.replayIntegration()
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,
});
```

We recommend you store your Sentry [Data Source Name](/concepts/key-terms/dsn-explainer/) (DSN) in an environment variable and configure it via the Nuxt runtime config.

This allows you to access the DSN using `useRuntimeConfig().public.sentry.dsn`.

```javascript {filename:nuxt.config.ts}
export default defineNuxtConfig({
  modules: ["@sentry/nuxt/module"],
  runtimeConfig: {
    public: {
      sentry: {
        dsn: process.env.NUXT_PUBLIC_SENTRY_DSN, // Use a public environment variable for the DSN
      },
    },
  },
});
```

### Add the Nitro Plugin

<Alert level="warning" title="Important">
  If you have an existing `sentry.server.config.ts` file, delete it, as it will
  conflict with the Cloudflare setup.
</Alert>

To enable Sentry for your Nuxt app on Cloudflare, create a new file in `server/plugins` and add the following code to it.

The snippet also turns on:

- Tracing: via <PlatformLink to="/configuration/options/#tracesSampleRate">`tracesSampleRate`</PlatformLink>

Don't need a feature? Remove its integration and options from the snippet.

```TypeScript {filename:server/plugins/sentry-cloudflare-plugin.ts}
import { sentryCloudflareNitroPlugin } from '@sentry/nuxt/module/plugins'

export default defineNitroPlugin(sentryCloudflareNitroPlugin({
  dsn: '___PUBLIC_DSN___',

  // Enables Tracing.
  // Set to 1.0 to capture 100% of spans for tracing.
  // We recommend reducing this value in production.
  tracesSampleRate: 1.0,
}))
```

Or, if you need access to `nitroApp`:

```TypeScript {filename:server/plugins/sentry-cloudflare-plugin.ts}
import { sentryCloudflareNitroPlugin } from '@sentry/nuxt/module/plugins'

export default defineNitroPlugin(sentryCloudflareNitroPlugin((nitroApp: NitroApp) => {
  // You can access `nitroApp` here if needed
  return {
    dsn: '___PUBLIC_DSN___',

    // Enables Tracing.
    // Set to 1.0 to capture 100% of spans for tracing.
    // We recommend reducing this value in production.
    tracesSampleRate: 1.0,
  }
}))
```

### Add Readable Stack Traces With Source Maps

To upload source maps for clear error stack traces, add your Sentry auth token, organization, and project slugs in the `sentry` options inside your configuration file:

<Alert>These `sentry` options only affect the **build time** of the SDK.</Alert>

```javascript {filename:nuxt.config.ts} {3-10}
export default defineNuxtConfig({
  modules: ["@sentry/nuxt/module"],
  sentry: {
    org: "___ORG_SLUG___",
    project: "___PROJECT_SLUG___",
    // store your auth token in an environment variable
    authToken: process.env.SENTRY_AUTH_TOKEN,
  },
});
```

To keep your auth token secure, always store it in an environment variable instead of directly in your files:

<OrgAuthTokenNote />

```bash {filename:.env}
SENTRY_AUTH_TOKEN=___ORG_AUTH_TOKEN___
```

#### Enable Client-Side Source Maps

While Nuxt generates source maps on the server side by default, you need to explicitly enable client-side source maps in your Nuxt configuration.

The `hidden` option enables source map generation while preventing source map reference comments that would normally appear at the end of each generated file in the build output.

```javascript {filename:nuxt.config.ts} {2}
export default defineNuxtConfig({
  sourcemap: { client: "hidden" },
});
```

## Verify Your Setup

Let's test your setup and confirm that Sentry is working correctly and sending data to your Sentry project.

Add a test page with a button that throws an error when you click it:

```html {filename:pages/example-error.vue}
<script setup>
  function triggerClientError() {
    throw new Error("Sentry Test Error");
  }
</script>

<template>
  <button type="button" @click="triggerClientError">Test Sentry Error</button>
</template>
```

Build and deploy your app, open the page in a browser, and click the button to trigger an error.
