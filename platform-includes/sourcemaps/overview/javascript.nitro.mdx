## How Source Maps Work in Nitro

When you wrap your config with `withSentryConfig`, the SDK:

1. Turns on hidden source maps if you haven't set the `sourcemap` option yourself
2. Injects debug IDs into your build output
3. Uploads source maps to Sentry after each production build
4. Deletes the `.map` files it turned on from the build output, so that they aren't public

Source maps are only uploaded during **production builds**. Development builds (`nitro dev`) skip the upload.

If you already set `sourcemap` in your Nitro config, the SDK respects your setting:

- `true` or `"hidden"`: the SDK uploads the generated maps and keeps them in the build output
- `false`: the SDK warns that errors won't be unminified and skips the upload

### Source Map Options

You can customize source map behavior in the Sentry options:

```typescript {filename:nitro.config.ts}
import { defineNitroConfig } from "nitro/config";
import { withSentryConfig } from "@sentry/nitro";

const config = defineNitroConfig({
  // your Nitro options...
});

export default withSentryConfig(config, {
  org: "___ORG_SLUG___",
  project: "___PROJECT_SLUG___",
  authToken: process.env.SENTRY_AUTH_TOKEN,

  sourcemaps: {
    // Glob pattern for source map files to upload
    assets: [".output/server/**"],
    // Glob pattern for files to exclude from upload
    ignore: ["node_modules/**"],
  },
});
```

To delete all source maps from the build output, also the ones you turned on, set [`sourcemaps.delete`](/platforms/javascript/sourcemaps/uploading/bundler-plugin-options/#sourcemaps.delete) to `true`. With `false`, the SDK deletes no source maps.

### Disabling Source Map Uploads

To turn off the upload, set [`sourcemaps.upload`](/platforms/javascript/sourcemaps/uploading/bundler-plugin-options/#sourcemaps.upload) to `false`. The SDK still injects debug IDs, so you can upload the source maps yourself later, for example with `sentry-cli sourcemaps upload`. To keep the source maps in the build output for this upload, also set `sourcemaps.delete` to `false`:

```typescript {filename:nitro.config.ts}
export default withSentryConfig(config, {
  sourcemaps: {
    upload: false,
    delete: false,
  },
});
```

To also turn off debug ID injection, set [`sourcemaps.injectDebugIds`](/platforms/javascript/sourcemaps/uploading/bundler-plugin-options/#sourcemaps.injectDebugIds) to `false`. The SDK then injects no debug IDs and uploads no source maps. Use this when another tool injects the debug IDs and uploads the source maps, for example the Sentry CLI:

```typescript {filename:nitro.config.ts}
export default withSentryConfig(config, {
  sourcemaps: {
    injectDebugIds: false,
  },
});
```

With SDK versions before 11.18.0, use `sourcemaps.disable: "disable-upload"` instead of `upload: false`, and `sourcemaps.disable: true` instead of `injectDebugIds: false`.
