## Job Monitoring

Use the Python SDK to monitor and notify you if your periodic task is missed (or doesn't start when expected), if it fails due to a problem in the runtime (such as an error), or if it fails by exceeding its maximum runtime.

Use the `monitor` decorator to wrap your tasks. Pass a `monitor_config` so Sentry creates or updates the monitor from your code (requires SDK version `1.45.0` or higher):

```python
import sentry_sdk
from sentry_sdk.crons import monitor

monitor_config = {
    "schedule": {"type": "crontab", "value": "0 * * * *"},
    "checkin_margin": 5,  # In minutes. Optional.
    "max_runtime": 10,  # In minutes. Optional.
    "timezone": "Europe/Vienna",  # Optional.
}

# Add the @monitor decorator to your task
@monitor(monitor_slug='<monitor-slug>', monitor_config=monitor_config)
def tell_the_world():
    print('My scheduled task...')
```

Alternatively, `monitor` can be used as a context manager:

```python
import sentry_sdk
from sentry_sdk.crons import monitor

def tell_the_world():
    with monitor(monitor_slug='<monitor-slug>', monitor_config=monitor_config):
        print('My scheduled task...')
```

If no monitor with this slug exists in Sentry and no `monitor_config` is sent, Sentry drops the check-ins. If you already created the monitor in Sentry, you can leave out `monitor_config`:

```python
@monitor(monitor_slug='<monitor-slug>')
def tell_the_world():
    print('My scheduled task...')
```

See [Configuring Cron Monitors](#configuring-cron-monitors) for all configuration options.

<Alert>

Since version `1.44.1` of the SDK you can use `monitor` to annotate asynchronous
functions as well.

</Alert>
