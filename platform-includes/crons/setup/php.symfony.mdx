## Symfony Scheduler

<Alert>

Symfony Scheduler monitoring ships in the next release of `sentry/sentry-symfony`.

</Alert>

The Symfony SDK can monitor the recurring messages of the [Symfony Scheduler](https://symfony.com/doc/current/scheduler.html) 6.4 or later. It sends a check-in when a worker starts a recurring message, and another when the message finishes or fails. (Please note, this creates a Cron Monitor for every recurring message, which counts against your quota.)

Enable it in your bundle configuration:

```yaml {filename:config/packages/sentry.yaml}
sentry:
    scheduler:
        enabled: true
```

The monitor slug is the schedule name and a name for the message, for example `default-app-send-report`. The name is the command for scheduled console commands, the service and method for scheduled services, and the class name for other messages. When recurring messages in the same schedule have the same name, the ID that Symfony gives each recurring message is added to their slugs. That ID changes when the message or its schedule changes, which creates a new monitor.

Sentry creates each monitor from the message's schedule on its first check-in:

- `RecurringMessage::cron()` and `#[AsCronTask]` send the cron expression and its timezone.
- `RecurringMessage::every()` and `#[AsPeriodicTask]` send the interval when it's a whole number of minutes.
- A jitter widens the check-in margin to cover it.

For schedules that can't be expressed in the Crons schedule format (for example, a message that runs every 10 seconds), triggers that skip runs, such as excluded time ranges, and custom triggers, the SDK doesn't send check-ins.

`RedispatchMessage` isn't monitored; the message it redispatches is monitored when a worker consumes it. Retried messages, cancelled runs, and messages of anonymous classes don't send check-ins.

To skip some recurring messages, list them under `excluded_messages`. An entry matches the message class, the command name or full command of a scheduled console command, the `@service::method` of a scheduled service, or the monitor slug. Entries wrapped in slashes are regular expressions.

```yaml {filename:config/packages/sentry.yaml}
sentry:
    scheduler:
        enabled: true
        excluded_messages:
            - App\Message\CleanupMessage
            - 'app:sync-search-index'
            - '/^reports-/'
```
