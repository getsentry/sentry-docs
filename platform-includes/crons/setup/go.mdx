## Check-Ins (Recommended)

Check-in monitoring allows you to track a job's progress by completing two check-ins: one at the start of your job and another at the end of your job. This two-step process allows Sentry to notify you if your job didn't start when expected (missed) or if it exceeded its maximum runtime (failed).

Wrap your job with `sentry.WithMonitor`. It sends an in-progress check-in with the monitor config, which creates or updates the monitor, then runs the job and sends an `ok` or `error` check-in with its duration:

```go
err := sentry.WithMonitor("<monitor-slug>", &sentry.MonitorConfig{
	Schedule: sentry.CrontabSchedule("0 * * * *"),
}, func() error {
	// Execute your scheduled task here...
	return nil
})
```

The job's error is returned unchanged. If the job panics, Sentry gets an `error` check-in and the panic continues. `sentry.WithMonitor` and `sentrycron` require sentry-go version `0.50.0` or higher. If the monitor already exists in Sentry, you can pass `nil` instead of a config.

### robfig/cron

If you schedule jobs with [robfig/cron](https://github.com/robfig/cron), add them with `sentrycron.AddFunc`. Install the package:

```bash
go get github.com/getsentry/sentry-go/cron
```

It wraps the job in `sentry.WithMonitor` and uses the job's spec as the monitor schedule and the cron's location as its timezone:

```go
import (
	"time"

	"github.com/getsentry/sentry-go"
	sentrycron "github.com/getsentry/sentry-go/cron"
	"github.com/robfig/cron/v3"
)

c := cron.New(cron.WithLocation(time.UTC))
sentrycron.AddFunc(c, "0 * * * *", "<monitor-slug>", func() error {
	// Execute your scheduled task here...
	return nil
}, &sentry.MonitorConfig{MaxRuntime: 30})
c.Start()
```

Pass `nil` as the last argument to use the default monitor settings. Specs Sentry can't represent, such as seconds other than a fixed value or `@every` under a minute, still send check-ins but don't create the monitor.

With the default `time.Local` location, the timezone comes from `$TZ` or `/etc/localtime`. If that isn't an IANA name, such as `America/New_York`, only check-ins are sent, so set the schedule in Sentry or use `cron.WithLocation`.

### asynq

If you schedule periodic tasks with [asynq](https://github.com/hibiken/asynq), install the package:

```bash
go get github.com/getsentry/sentry-go/asynq
```

On the scheduler, wrap your `PeriodicTaskConfigProvider` with `sentryasynq.NewConfigProvider` to monitor every periodic task. Each task type becomes a monitor slug, and the task's cronspec and the scheduler's location become the monitor schedule and timezone. On the workers, add `sentryasynq.Middleware`, which sends the check-ins around each periodic task:

```go
import (
	"time"

	"github.com/hibiken/asynq"
	sentryasynq "github.com/getsentry/sentry-go/asynq"
)

// Scheduler
mgr, err := asynq.NewPeriodicTaskManager(asynq.PeriodicTaskManagerOpts{
	RedisConnOpt: redis,
	PeriodicTaskConfigProvider: sentryasynq.NewConfigProvider(provider, sentryasynq.Options{
		// Same as asynq.SchedulerOpts.Location. Defaults to UTC.
		Location: time.UTC,
		Exclude:  []string{"<task-type>"},
	}),
})

// Workers
mux := asynq.NewServeMux()
mux.Use(sentryasynq.Middleware)
```

With a plain `asynq.Scheduler`, mark each task with `sentryasynq.WithMonitor` before registering it:

```go
scheduler.Register("0 * * * *", sentryasynq.WithMonitor(task, "<monitor-slug>", "0 * * * *", sentryasynq.Options{}))
```

`Exclude` skips task types by exact name, and `ExcludePatterns` by regular expression. Periodic tasks that share a task type aren't monitored by `NewConfigProvider`, so give them their own slugs with `sentryasynq.WithMonitor`. Pass task options to `Register` instead of `asynq.NewTask`, since a task created with options can't be marked. Schedules that can't be expressed in the Crons schedule format (for example, a task that runs every 10 seconds) send check-ins without creating the monitor. The asynq integration ships in the next release of `sentry-go`.

### gocron

If you schedule jobs with [gocron v2](https://github.com/go-co-op/gocron) (v2.22.0 or higher), install the package:

```bash
go get github.com/getsentry/sentry-go/gocron
```

Pass `sentrygocron.NewSchedulerMonitor` to `gocron.WithSchedulerMonitor` to monitor every job. Each job name becomes a monitor slug, and cron and duration jobs use their schedule and the scheduler's location as the monitor schedule and timezone. Check-ins go to the client carried by the context, or the global client:

```go
import (
	"context"
	"time"

	"github.com/go-co-op/gocron/v2"
	sentrygocron "github.com/getsentry/sentry-go/gocron"
)

s, err := gocron.NewScheduler(
	gocron.WithLocation(time.UTC),
	gocron.WithSchedulerMonitor(sentrygocron.NewSchedulerMonitor(context.Background(), sentrygocron.Options{
		// Same as gocron.WithLocation. Defaults to time.Local.
		Location: time.UTC,
		Exclude:  []string{"<job-name>"},
	})),
)
s.NewJob(gocron.CronJob("0 * * * *", false), gocron.NewTask(task), gocron.WithName("<monitor-slug>"))
```

Name your jobs with `gocron.WithName`. Jobs running an anonymous function without a name, and jobs sharing a name, aren't monitored. `Exclude` skips jobs by exact name, and `ExcludePatterns` by regular expression. Daily, weekly, monthly, random and one-time jobs, and schedules that can't be expressed in the Crons schedule format (for example, a job that runs every 10 seconds), aren't monitored. The gocron integration ships in the next release of `sentry-go`.

### Manual Check-Ins

To send check-ins yourself, call `sentry.CaptureCheckIn` at the start and end of your job. Pass a monitor config with the in-progress check-in so Sentry creates or updates the monitor from your code:

```go
monitorConfig := &sentry.MonitorConfig{
	Schedule: sentry.CrontabSchedule("0 * * * *"),
}

// 🟡 Notify Sentry your job is running:
checkinId := sentry.CaptureCheckIn(
	&sentry.CheckIn{
		MonitorSlug: "<monitor-slug>",
		Status:      sentry.CheckInStatusInProgress,
	},
	monitorConfig,
)

// Execute your scheduled task here...

// 🟢 Notify Sentry your job has completed successfully:
sentry.CaptureCheckIn(
	&sentry.CheckIn{
		ID:          *checkinId,
		MonitorSlug: "<monitor-slug>",
		Status:      sentry.CheckInStatusOK,
	},
	monitorConfig,
)
```

If the monitor already exists in Sentry, the configuration is optional, so you can pass `nil` instead. See [Upserting Cron Monitors](#upserting-cron-monitors) for all configuration options.

If your job execution fails, you can notify Sentry about the failure:

```go
// 🔴 Notify Sentry your job has failed:
sentry.CaptureCheckIn(
	&sentry.CheckIn{
		ID:          *checkinId,
		MonitorSlug: "<monitor-slug>",
		Status:      sentry.CheckInStatusError,
	},
	nil,
)
```

## Heartbeat

Heartbeat monitoring notifies Sentry of a job's status through one check-in. This setup will only notify you if your job didn't start when expected (missed). If you need to track a job to see if it exceeded its maximum runtime (failed), use check-ins instead.

```go
// Execute your scheduled task...

// 🟢 Notify Sentry your job completed successfully:
sentry.CaptureCheckIn(
	&sentry.CheckIn{
		MonitorSlug: "<monitor-slug>",
		Status:      sentry.CheckInStatusOK,
		// Specify the duration of the job.
		Duration:    time.Second * 10,
	},
	nil,
)
```

If your job execution fails, you can:

```go
// 🔴 Notify Sentry your job has failed:
sentry.CaptureCheckIn(
	&sentry.CheckIn{
		MonitorSlug: "<monitor-slug>",
		Status:      sentry.CheckInStatusError,
		Duration:    time.Second * 10,
	},
	nil,
)
```

## Upserting Cron Monitors

You can create and update your Monitors programmatically with code
rather than [creating and configuring them in Sentry.io](https://sentry.io/issues/alerts/new/crons/).

```go
// Create a crontab schedule object (every 10 minutes)
monitorSchedule := sentry.CrontabSchedule("*/10 * * * *")

// Or create an interval schedule object (every 10 minutes)
monitorSchedule := sentry.IntervalSchedule(10, sentry.MonitorScheduleUnitMinute)
```

Supported units are:

- `sentry.MonitorScheduleUnitMinute`
- `sentry.MonitorScheduleUnitHour`
- `sentry.MonitorScheduleUnitDay`
- `sentry.MonitorScheduleUnitWeek`
- `sentry.MonitorScheduleUnitMonth`
- `sentry.MonitorScheduleUnitYear`

```go
// Create a monitor config object
monitorConfig := &sentry.MonitorConfig{
	Schedule:      monitorSchedule,
	MaxRuntime:    2,
	CheckInMargin: 1,
	FailureIssueThreshold: 2,
}

// 🟡 Notify Sentry your job is running:
checkinId := sentry.CaptureCheckIn(
	&sentry.CheckIn{
		MonitorSlug: "<monitor-slug>",
		Status:      sentry.CheckInStatusInProgress,
	},
	monitorConfig,
)

// Execute your scheduled task here...

// 🟢 Notify Sentry your job has completed successfully:
sentry.CaptureCheckIn(
	&sentry.CheckIn{
		ID:          *checkinId,
		MonitorSlug: "<monitor-slug>",
		Status:      sentry.CheckInStatusOK,
	},
	monitorConfig,
)
```

A full end-to-end example can be found [in the `sentry-go` repository](https://github.com/getsentry/sentry-go/blob/dde4d360660838f3c2e0ced8205bc8f7a8d312d9/_examples/crons/main.go).
