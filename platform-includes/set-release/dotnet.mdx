The SDK attempts to locate the release to attach to events sent to Sentry.

The SDK will first check if there's a version set on the environment via `SENTRY_RELEASE` and use it as-is.

On Android, iOS and Mac Catalyst, if no version is found, the SDK uses the app package's ID, version and build number, in the format `<package-id>@<version>+<build>`.

On Android, these values are the package name, `versionName` and `versionCode`. On iOS and Mac Catalyst, they're `CFBundleIdentifier`, `CFBundleShortVersionString` and `CFBundleVersion`. The `ApplicationId`, `ApplicationDisplayVersion` and `ApplicationVersion` properties in your project file set them.

<Alert title="Changed in Version 7.0.0">

In earlier versions, the release from the app package took precedence over `SENTRY_RELEASE`.

</Alert>

On other platforms, if no version is found, the SDK will look at the [entry assembly's](<https://msdn.microsoft.com/en-us/library/system.reflection.assembly.getentryassembly(v=vs.110).aspx>) `AssemblyInformationalVersionAttribute`, which accepts a string value and is often used to set a GIT commit hash. If that returns null, then the SDK will look at the default `AssemblyVersionAttribute`, which accepts the numeric version number. The resulting release will be in the format `<assembly-name>@<version-number>`.

<Alert>
An `AssemblyInformationalVersionAttribute` is included automatically in SDK-style projects with a default value of `"1.0.0.0"`. You can set the `Version` property in your project file to override this value or [disable it entirely](https://learn.microsoft.com/en-us/dotnet/standard/assembly/set-attributes-project-file#use-package-properties-as-assembly-attributes) by setting the `GenerateAssemblyInformationalVersionAttribute` property to `false`.
</Alert>
